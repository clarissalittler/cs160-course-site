Lesson 1: Computers as Layered Systems

Big question

How can the same kind of machine be a camera, a map, a jukebox, a word processor, and a game console?

By the end of this lesson, you should be able to describe the four jobs every computer performs, distinguish major kinds of hardware and software, trace an everyday action through several layers of a computing system, and identify how a design choice can distribute access, privacy, and control.

A computer is not just a laptop

When people hear computer, they often picture a laptop or a desktop tower. Computer scientists use the word more broadly. A phone, a game console, a car's navigation system, a smart thermostat, and the control board in a microwave are all computers. Their shapes and purposes differ, but each is a system that follows instructions to transform information.

Every computer performs some combination of four basic jobs:

  • Input: receiving information from outside the system. A touchscreen receives the location of your finger; a microphone receives changing air pressure; a network connection receives messages from other computers.
  • Processing: following instructions that transform information. A photo app may brighten pixels, a calculator may add numbers, and a game may decide whether two objects collided.
  • Storage: holding information for later use. Some storage lasts only while a program is running, while other storage keeps files even after power is turned off.
  • Output: sending information out of the system. A screen displays an image, a speaker moves air to make sound, and a network connection sends a message.

These categories describe roles, not permanent labels. A touchscreen is both an input device and an output device. A network connection is an input when it receives a webpage and an output when it sends a form. Even storage can become input when a program reads a saved file.

Information is the common material

A computer's four jobs are all jobs performed on information. Here, information means something that lets us distinguish one possibility from another. Did a button receive a press or not? Is a light red, green, or blue? Which letter did a person type? A single choice between two possibilities is the smallest unit of digital information: one bit.

Information can move between physical forms without losing its identity. The same sentence can be spoken as sound waves, printed in ink, tapped in Morse code, stored as electrical states, or transmitted as pulses of light. The material carrying it changes, but the pattern—the information—can remain the same.

This is why one general-purpose machine can replace many specialized objects. Once maps, songs, photographs, messages, and calculations are represented as digital information, the same hardware can store and process all of them. Different software gives those bits different meanings and gives the machine different behavior.

The physical layer: hardware

Hardware means the physical parts of a computing system: the parts you could, at least in principle, touch. The following categories describe the work those parts usually perform.

  • The central processing unit (CPU) carries out program instructions. It performs arithmetic, compares values, and coordinates other components. It works very quickly, but it needs somewhere else to keep the instructions and data it is using.
  • Random-access memory (RAM) is the computer's temporary working area. It holds active programs and data close to the CPU. RAM is fast, but its contents normally disappear when power is removed.
  • Long-term storage, such as a solid-state drive, retains programs and files when power is off. It is generally slower than RAM but can hold information persistently.
  • Input and output devices connect the computer to people and the physical world. Keyboards, sensors, screens, speakers, and network adapters translate between physical events and digital information.

RAM is not the same as storage. If a computer has many applications open, it may run short of RAM even when its drive has plenty of free space. Saving a document copies information from a program's temporary working state into persistent storage.

The instruction layer: software

Software is organized information that tells hardware what to do. A program is a set of instructions, while data is the information those instructions operate on. The boundary can be slippery: a word-processing document is data to the word processor, but a program file can itself be treated as data by an editor or downloaded like any other file.

Software also comes in layers:

  1. Applications help a person accomplish a task: write a paper, edit a photo, visit a site, or play a game.
  2. The operating system manages shared resources such as files, memory, devices, and running applications. It provides common services so every application does not need to control the hardware from scratch.
  3. Device software and firmware translate general requests into the particular operations understood by a keyboard, display, storage device, or other component.
  4. Hardware finally carries out those low-level operations using physical circuits.

Follow one tap through the layers

Imagine tapping the camera button on a phone:

  1. The touchscreen detects a physical touch and converts its location into digital input.
  2. The operating system sends a description of that event to the camera application.
  3. The application decides that the event means “take a picture” and requests data from the camera.
  4. A sensor measures light. Hardware and device software convert those measurements into numbers.
  5. The CPU follows image-processing instructions to adjust color and compress the data.
  6. The operating system stores the resulting file and asks the display hardware to show a preview.

No one person needs to think about every transistor in order to take a photograph or write a camera app. Each layer offers a simpler set of concepts to the layer above it while hiding many lower-level details. Computer scientists call this abstraction. Abstraction is not pretending details do not exist; it is choosing which details matter for the task at hand.

Layers also help us diagnose problems. If a video call has no sound, we can ask separate questions: Is the microphone receiving input? Does the operating system allow the app to use it? Did the app select the correct device? Is the network carrying the data? Breaking a complicated system into layers turns one vague problem into several testable ones.

Computers reflect human decisions

None of these layers is inevitable or neutral. People decide what a device senses, what an interface makes easy, which files an operating system allows a program to open, and whose needs are considered during design. A screen-only interface may exclude a blind user; tiny controls may exclude someone with limited dexterity; software that assumes fast home internet may fail students who rely on a phone connection.

Accessibility features make the layers especially visible. A screen reader takes application information, uses operating-system accessibility services to interpret it, and produces speech or braille as output. When an image has useful alternative text, meaning can cross those layers. When it does not, the chain breaks. Technical choices are also choices about who can participate.

Everyday life and social impact: app permissions

Install a navigation app and it may request access to your location. A video-calling app may request the camera, microphone, contacts, and notifications. Those requests expose the layers from this lesson: physical sensors collect input, the operating system controls access to them, and an application decides what to request and how to use the result.

The same permission can support a useful feature or enable unwanted surveillance. Location can give turn-by-turn directions, help a family member find a lost phone, reveal visits to a medical clinic, or feed an advertising profile. A user can tap “Allow” or “Don't Allow,” but that choice is meaningful only if the explanation is understandable and the app offers a usable alternative.

  • Who benefits? The user may gain a convenient service; the app developer may gain data, revenue, or a better product.
  • Who might be harmed? The user or people nearby may lose privacy, experience exclusion when they refuse, or have their data used in an unexpected way.
  • Who decides? Hardware designers choose sensors, operating-system designers choose permission controls, app developers choose what to request, and users make choices within those boundaries. Employers, schools, stores, and governments may also require or regulate a system.

Abstraction makes a phone easy to use, but it can also hide the path information takes. Understanding the layers gives you better questions to ask.

Try it: trace a familiar action

Choose one action such as sending a text, searching the web, paying with a card, or playing a song. Write one example of input, processing, storage, and output involved in that action. Then name at least three layers—application, operating system, device software, or hardware—that cooperate to make it happen.

Show a sample answer

When sending a text, taps on a keyboard are input. The messaging app processes them into a message, the phone stores a local copy, and the screen displays the conversation as output. The application creates the message, the operating system provides keyboard, file, and network services, and hardware detects touches and transmits radio signals. A network reply later becomes another input.

Lesson takeaway

A computer is a layered system for inputting, processing, storing, and outputting information. Hardware provides the physical mechanisms; software organizes instructions and meaning; abstraction lets us work at one useful level at a time. In the next lesson, we will look beneath all of these media and ask how a computer can represent so many kinds of information using only bits.

Lesson 4: Images, Sound, and Compression

Big question

Pictures and sounds seem very different from text. How can a computer turn both into numbers, and what must it trade away to keep their files manageable?

By the end of this lesson, you should be able to explain pixels, RGB color, and sampled sound; identify the role of metadata; estimate how representation choices affect file size; choose between lossless and lossy compression for a purpose; and analyze who gains or loses when a platform chooses quality settings for its users.

From continuous experience to discrete measurements

Light and sound in the physical world vary continuously. A digital computer cannot store every possible point in a scene or every instant of a sound. Instead, a device samples the world: it takes a finite set of measurements and represents each measurement with a finite number of bits.

This process makes two decisions unavoidable:

  • Where or when will measurements be taken? An image sensor divides a scene into locations; an audio system measures a signal at successive moments.
  • How precisely will each measurement be recorded? More bits allow more possible values, such as more shades or finer sound-pressure levels.

More samples and more bits per sample can preserve finer distinctions, but they also create more data. Digital media design is therefore a continuing negotiation among detail, file size, processing time, transmission speed, and the needs of an audience.

Black-and-white images: one bit per pixel

A raster image is a rectangular grid of small picture elements called pixels. For the simplest black-and-white image, one bit can represent each pixel. We might agree that 0 means white and 1 means black.

Consider this 5-by-5 image, written one row at a time:

10001
01010
00100
01010
10001

Under our agreement, the four corner pixels are black, the center is black, and diagonal black pixels connect them to form an X. The same 25 bits could form a different picture if we changed the width or read columns before rows. A file therefore needs more than pixel values.

Metadata tells us how to interpret data

Metadata is information about other data. An image file may include its width, height, color system, creation time, camera settings, and geographic location. The first two values tell software how to break a long stream of pixels into rows. The color-system information tells it how to interpret each pixel's numbers.

Metadata is useful, but it can also reveal more than a person expects. A shared photograph may contain the time and location where it was taken. Social platforms often remove some metadata, but a careful user should not assume that every service does. Representation choices affect privacy as well as appearance.

Resolution describes how many samples make up an image, commonly given as width by height in pixels. Increasing resolution can preserve smaller spatial details. It does not automatically improve an image, however: enlarging a low-resolution file only makes larger versions of measurements that already exist. Display size and viewing distance also affect whether added pixels are noticeable.

The optional Pixelation Widget lets you enter width, height, and binary pixel values. If a visual grid is not useful to you, make a textual image like the 5-by-5 example above: state the dimensions, read each row aloud or in text, and describe the resulting pattern.

Color images: several measurements per pixel

Many screens create colors by combining red, green, and blue light. In the common RGB representation, each pixel stores three numbers: an amount of red, an amount of green, and an amount of blue. If each channel uses eight bits, its value ranges from 0 to 255.

Three eight-bit channels use 24 bits per pixel and provide 224, or 16,777,216, possible patterns. Not every display reproduces every distinction perfectly, and human perception does not treat all numeric changes equally, but the scheme gives software a consistent vocabulary.

Web colors are often written in hexadecimal, a compact base-16 notation. The six digits in #RRGGBB are three two-digit values. Each pair ranges from 00, meaning decimal 0, to FF, meaning decimal 255. Thus black is #000000, white is #FFFFFF, and bright red is #FF0000. You do not need to perform hexadecimal arithmetic in this unit, but you should recognize that this is another way to write the same channel numbers.

Sound: samples across time

Sound reaches us as changing air pressure. A microphone converts those changes into an electrical signal, and an analog-to-digital converter measures the signal repeatedly. Each measurement is a sample. Played in sequence through a speaker, the values approximate the original pressure pattern.

  • The sample rate is the number of measurements taken per second. A higher rate can represent more rapid changes in the signal and therefore higher frequencies, but produces more samples.
  • The bit depth is the number of bits available for each measurement. More bits provide more possible levels and can represent smaller differences, but make each sample larger.
  • The number of channels describes separate simultaneous signals. Stereo audio normally stores a left and a right channel, doubling the sample data compared with one-channel audio at the same settings.

Sampling never captures an infinite physical signal in its entirety. The practical question is whether the representation preserves the distinctions needed for a purpose. Speech for a phone call, a studio music master, a hearing-assistance device, and a scientific recording may require different settings.

A concrete sound-file calculation

Suppose we record one minute of uncompressed stereo audio at 44,100 samples per second, with 16 bits per sample in each channel. Its raw sample data requires:

44,100 samples/second × 16 bits/sample × 2 channels × 60 seconds = 84,672,000 bits

Dividing by eight gives 10,584,000 bytes, or about 10.6 megabytes for one minute before adding file metadata. A ten-minute recording would contain about 106 megabytes of raw sample data. The calculation makes each design choice visible: doubling the duration, sample rate, bit depth, or channel count doubles the data.

By comparison, an audio file delivered at 128,000 bits per second contains roughly 960,000 bytes per minute, plus a small amount of metadata. Reaching that much smaller size normally requires lossy audio compression: the decoder can produce convincing sound, but it cannot reconstruct every original sample value. A lossless audio format may also reduce the raw size, but the amount saved depends on the patterns in the recording.

Why uncompressed media becomes large

Representation choices let us estimate a file's raw data. A 1920-by-1080 RGB image with 24 bits per pixel contains:

1920 × 1080 × 24 = 49,766,400 bits

Dividing by eight gives 6,220,800 bytes, or about 6.2 megabytes before headers and other metadata. Thirty such images every second would make uncompressed video enormous. Audio size similarly grows with sample rate, bit depth, number of channels, and duration.

Files need to travel across networks, fit on devices, and open quickly. Compression represents information using fewer bits. A compression method can be lossless or lossy, depending on whether decompression can reconstruct the original data exactly.

Lossless compression: find a shorter description

Lossless compression preserves every bit of the original after decompression. It works by finding patterns or repetition and describing them more efficiently.

For a simple example, the sequence AAAAAAAAAABBBBBCC contains ten A's, five B's, and two C's. A run-length description such as 10A5B2C is shorter. Real formats use more sophisticated techniques: they may build dictionaries of repeated sequences, assign shorter codes to common patterns, or predict values and store only differences.

What “lossless” means in practice

Imagine a file named draft.txt containing the sentence Meet at 10:30. You add it to a ZIP archive and email the smaller archive. The recipient cannot use the compressed codes as ordinary prose; their software must decompress the archive. After extraction, the contents of draft.txt are byte-for-byte identical to the contents before compression: the capital M, spaces, digits, colon, period, and every other byte are in exactly the same positions.

Lossless compression therefore does not summarize the paper, remove “unimportant” vowels, replace words with synonyms, or lower the quality and hope nobody notices. It creates a reversible description. If decompression changes even one character in the file, the process was not lossless—or the archive was damaged.

A practical exactness test: Software can compare the original and decompressed files one byte at a time or compare their checksums, which are short values calculated from all the file's bytes. Matching files produce the same checksum. Backup systems, software downloads, and scientific workflows use such tests to detect accidental changes.

What must be identical depends on the format:

  • A ZIP archive can preserve the complete bytes of the files placed inside it. After extraction, the contents of a program file or paper are exactly as they were before.
  • A PNG image losslessly preserves its decoded pixel values. A PNG encoder may organize or compress those values differently, and resaving may change optional metadata, but compression need not blur a line, alter a color value, or invent an artifact.
  • A FLAC audio file losslessly preserves the decoded audio samples. It can reconstruct the same sample numbers as an uncompressed PCM recording while using a shorter description of their patterns.

Lossless does not guarantee that a file will become dramatically smaller. A one-character text file can grow when placed in an archive because the archive needs headers and a decoding key. JPEG photographs, MP3 audio, ZIP archives, and DOCX documents are already compressed, so compressing them again often saves little and can even add overhead. The guarantee is exact reconstruction, not a particular compression percentage.

The optional Text Compression Widget demonstrates a dictionary method. You replace repeated phrases with shorter symbols and store a key that allows the original to be rebuilt. The key counts toward the file size, so replacing a phrase only once may make the result larger rather than smaller.

Lossless compression is appropriate when every detail must survive: program code, financial records, a term paper, database contents, or an image that will undergo further exact editing. Common lossless formats include ZIP archives and PNG images.

Lossy compression: preserve what matters for a purpose

Lossy compression creates a smaller representation by discarding some information. Decompression produces an approximation rather than the original bit-for-bit data. Good lossy methods use knowledge about perception and a medium's purpose to discard distinctions that are less likely to matter.

Photographic compression may represent broad color patterns more precisely than tiny changes people are unlikely to notice. Audio compression may devote fewer bits to sounds masked by louder nearby sounds. Video compression can store how one frame differs from the previous frame instead of repeating an almost identical image.

Consider three everyday comparisons:

  • A screenshot containing small text: PNG is often a good choice because its lossless image compression keeps the captured pixel values exact and sharp. Saving the same screenshot as a heavily compressed JPEG may add fuzzy halos around letters, making them harder to read.
  • A phone photograph: A moderate-quality JPEG can be far smaller than raw pixel data while remaining convincing at the size used on a webpage. The decoded pixels are not the camera's original pixels, but the lost distinctions may not matter for that purpose.
  • A music recording: FLAC can reconstruct every stored source sample; a lossy format such as MP3 or AAC stores an approximation designed for listening. A listener may not notice a good lossy copy in ordinary conditions, but audio analysis or later editing cannot recover the discarded sample information.

Lossy does not mean “bad,” and lossless does not always mean “best.” A smaller file can load over a slower connection, consume less mobile data, use less energy, and reach more people. But excessive compression can smear text in an image, introduce ringing sounds, destroy evidence needed for analysis, or make speech harder to understand. Quality must be evaluated by people and in context.

Saving an already compressed file repeatedly can compound loss because each generation discards more information. Keep a high-quality or lossless original when you expect to edit and export a work more than once. Make smaller delivery copies from that original.

A practical media workflow often has three stages:

  1. Capture or create a source with enough detail for the work you intend to do.
  2. Keep a master in an uncompressed or lossless format so future edits begin from the best available information.
  3. Export delivery copies for particular audiences: perhaps a smaller JPEG for a webpage, compressed audio for a phone connection, and a higher-quality copy for an archive.

Delivery copies are not automatically inferior work. They are versions optimized for a use. The mistake is discarding the master and later expecting a delivery copy to contain information that its compression deliberately removed.

Everyday life and social impact: platforms choose quality for us

When you upload a photograph, send a video message, or stream a song, a platform often compresses it automatically. It may create several versions and select one based on the device and network. Most users never see the sample rates, bit depths, resolutions, or quality settings involved.

That automatic choice can be valuable. Smaller files cost less to deliver, begin playing sooner, use less storage and energy, and may make participation possible for someone using a data-limited phone plan or an unreliable connection. But discarded detail can matter differently to different people. Compression that sounds acceptable to one listener can make unfamiliar accents or quiet speech harder to understand. A photograph compressed for casual viewing may be unsuitable for documenting fine artwork, reading distant text, or preserving evidence.

There is also a power difference between choosing to make your own delivery copy and having a platform alter every upload. A responsible service can disclose what it changes, retain an original when appropriate, offer a high-quality option, and test results with the people most likely to be affected.

  • Who benefits? People on slow or expensive connections, the platform paying for storage and delivery, and audiences who receive media quickly.
  • Who might be harmed? Creators may lose important detail or control; audiences may receive less intelligible or less trustworthy information; people with particular sensory or access needs may experience quality differently.
  • Who decides? Engineers and product managers set defaults, platform owners set business priorities, creators sometimes choose export settings, and users may—or may not—receive a quality control.

Try it: make the tradeoff explicit

  1. A black-and-white icon is 20 pixels wide and 10 pixels high and uses one bit per pixel. How many bits are needed for its raw pixels?
  2. What additional information would software need to display those bits correctly?
  3. You are publishing an audio interview for students who may use limited mobile data. Would you choose lossless or lossy compression? Name one quality you would test before publishing.
  4. You compress a program file into a ZIP archive and then extract it. What must be true for the compression to count as lossless?
Check your reasoning
  1. 20 × 10 × 1 = 200 bits.
  2. At minimum, the width and height, the order in which pixels are stored, and the mapping between bit values and colors. A real format needs further metadata.
  3. A carefully chosen lossy speech format is reasonable because smaller downloads improve access. Test intelligibility—including with quiet voices, different accents, and assistive listening setups—rather than judging file size alone.
  4. The extracted program's complete byte sequence must be identical to the original. It is not enough for the program to look approximately right or usually run.

Lesson takeaway

Digital images sample space into pixels; digital audio samples a signal across time. More samples and more bits per sample can preserve more distinctions but create more data. Metadata supplies the context needed to interpret that data. Lossless compression reconstructs the original exactly, while lossy compression discards selected information to achieve smaller files. Neither choice is automatically correct: the purpose, audience, and consequences determine what must survive.

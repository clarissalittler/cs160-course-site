Part 1: Follow a Web Page

A student connected through home Wi-Fi opens https://class.example/readings/week2.html. The events below are out of order.

  1. The web server sends an HTTP response containing the page or an error message.
  2. The browser asks DNS for an IP address associated with class.example.
  3. The browser reads the URL and identifies the HTTPS scheme, host name, and page path.
  4. The device uses the IP address to contact the destination. Routers begin forwarding packets through the home network, ISP, and other networks to reach it.
  5. After contacting the destination, the browser and server exchange the information needed to establish a protected HTTPS connection using TLS.
  6. The browser sends an HTTP request for /readings/week2.html.
  7. The browser interprets the response and displays the page.

1A. Put the events in a reasonable conceptual order

Order the events by when each process first begins. First the browser identifies and locates the destination; then the device contacts it; then the browser and server secure their exchange and request the page. Packet routing continues during the later events, but it begins when the device first contacts the destination.

Optional vocabulary bank
  • Browser: the client program requesting and displaying the page
  • DNS: the name-lookup system that connects a domain name to records such as an IP address
  • IP address and routing: information and decisions used to move packets toward a destination network

Part 2: Design a Wordle Protocol

Imagine that you are designing a protocol for a Wordle-like game. Each round, a player sends a five-letter guess to the server. The server replies with the number of turns left and information about each letter.

Bit reminder: With n bits, you can make 2n patterns. Find the smallest number of bits that provides enough patterns for the possibilities you need.

2A. Send the guess

The English alphabet has 26 letters. If every letter uses the same number of bits, how many bits are needed to send one five-letter guess? Explain how you know your field for each letter is large enough.

2B. Send the result

The server must send:

  • the number of turns left, from 0 through 5; and
  • one of three results for each of the five letters: not in the word, in the word but in another position, or in the correct position.

Design a binary reply and calculate its total number of bits. Identify the fields in your message and explain what their patterns mean. There is more than one defensible design, so your reasoning matters as much as your total.

Part 3: Analyze One Internet Problem

Choose one scenario. Some describe a discrete failure; others describe an ongoing access problem or a governance decision. You are not expected to prove a single cause from limited information. Your job is to explain the most important technical and organizational factors, use the available evidence, and identify what you would investigate next.

  1. Name trouble: A course site opens by its known IP address but not by its domain name on one campus network. The domain name works over a student's cellular connection.
  2. Access gap: A neighborhood has one advertised broadband provider, but the monthly charge, installation fee, and required equipment are unaffordable to many residents. The public library connection works but is available only during library hours.
  3. Shared outage: Several unrelated news and shopping sites return errors at the same time. Email, text messaging, and small independent sites continue to work.
  4. Platform decision: A creator's page disappears from a large platform after a moderation decision. The creator's personal website remains reachable, but most followers do not know its address.

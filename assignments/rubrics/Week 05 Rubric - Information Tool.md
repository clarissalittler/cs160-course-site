# Week 5 Rubric — In-Memory Information Tool

Score each row independently. Half-points are welcome. Add the five scores (20 points possible), then divide by 5 for the 0–4 assignment score.

| Criterion | 4 — Complete and effective | 3 — Mostly demonstrated | 2 — Partly demonstrated | 1 — Beginning evidence | 0 — No evidence |
|---|---|---|---|---|---|
| Schema, records, and data responsibility | Uses a consistent list of dictionaries with 4+ documented fields including a numerical field, and identifies an unnecessary/sensitive field not collected. | Model is sound with one documentation, consistency, or privacy gap. | Records and schema are partly usable but keys/types vary or documentation is incomplete. | Begins a relevant record structure or data dictionary. | No relevant data model. |
| Menu, adding, and display | While-loop menu, add, labeled display, record count, and quit path work. | Core flow works with one minor path or labeling issue. | Several actions work but the loop or an important path is incomplete. | One menu/data-entry/display component shows relevant work. | No relevant interface work. |
| Filter, summary, and empty states | Working filter plus numerical summary and explicit empty/no-match messages are correct. | All are present with one minor calculation or edge-case issue. | Filter or summary works and the other is attempted; some edge behavior is handled. | Attempts one relevant filter, calculation, or empty-state response. | No evidence for these operations. |
| Functions and program reliability | Runs top to bottom and separates at least three coherent jobs into understandable functions. | Mostly runs and is sensibly organized with one minor issue. | Substantial code works, but errors or weak separation block an important path. | Some relevant function/program structure is visible. | No relevant working structure. |
| Evidence, usability, and submission | Complete sample run, data dictionary, required test cases, usability observation, evidence-based revision, and accessible keyboard/text output are provided. | Most evidence is complete with one thin or missing item. | Several useful artifacts are present, including some testing or usability evidence. | One useful supporting artifact is provided. | No supporting evidence. |

Partial-credit notes: a broken menu does not erase credit for a correct schema, working functions, tests, or usability study. Award credit per working action and per documented test rather than treating either set as all-or-nothing.

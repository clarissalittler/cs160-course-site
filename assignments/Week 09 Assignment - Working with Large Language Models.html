This assignment is about getting hands-on with large language models, the technology behind ChatGPT, Claude, Gemini, &c. Back in Lesson 5 we saw that a chatbot answering a question on its own is a bit like you answering off the top of your head, and that the biggest improvements have come from letting models use tools and take a few rounds to check and fix their own work. Question 1: Build a Program Together

Ask the model to write a Python program that does something simple but interesting. Pick something that sounds fun to you! A tip: be specific. Instead of "write a Python program," try something like "write a Python program that asks the user for their name and their favorite animal, then prints a short story about them and that animal." Also ask it to stick to the Python from Units 3–6, with no extra packages and nothing that changes files or accounts. The more specific your prompt, the easier it is to tell whether the program does what you asked.

Then keep going! Don't stop at the first answer. Run the program (in OnlineGDB, Colab, or any Python you have), and then ask the model for one new feature in the same conversation, and run it again. Finally, ask the model to write three test cases for its own program: for each one, what you'd type in and what the program should print. Then actually try those three cases yourself.

  1. What was your first prompt? Paste exactly what you typed.
  2. What code did it give you, and did it work when you ran it? If not, what went wrong (error messages, unexpected behavior, &c.)?
  3. What feature did you ask for, and did the new version work? If anything broke along the way, how did you and the model fix it?
  4. What three test cases did the model write, and did your program really pass them? Did the model's tests check anything that mattered, or miss something you would have checked?

Question 2: Debug a Program

Take the following Python program, which has a problem (well, more than one), and ask the model to explain what's wrong with it and fix it. This is a program that implements the Sieve of Eratosthenes, a classic algorithm for finding prime numbers. You don't need to already know how the algorithm works; what we want to see is how the model handles debugging.

After the model gives you a fixed version, test whether it runs and whether its answers are correct. Then ask the model to reorganize the code so it has a main function that asks the user for the limit on the console.

def sieve_of_eratosthenes(limit):
    if limit < 2:
        return []

    # Initialize a list of boolean values. All numbers are initially assumed to be prime.
    is_prime = [True] * (limit + 1)
    is_prime[0:2] = [False, False]  # 0 and 1 are not prime numbers

    # Iterate through the numbers and mark their multiples as non-prime
    for number in range(2, limit**0.5 - 1):
        if is_prime[number]:
            for multiple in range(number*number, number, limit + 1):
                is_prime[multiple] = False

    # Collect all prime numbers
    primes = [number for number, prime in enumerate(is_prime) if prime]

    return primes

# Example usage
limit = 200
primes = sieve_of_eratosthenes(limit)
print(primes)

Check the result: The function should return every prime number up to and including an integer limit. Use the cases below on the repaired function and the console version. Write down both the list you expected and the list you got, because a program can run without errors and still give the wrong answer. You don't need to handle non-integer input for this assignment.

Question 3: Off the Top of Its Head, or Looking It Up?

In Lesson 5 we talked about hallucination, when a model writes something that sounds completely plausible but is wrong. That happens because a language model writes by following patterns it learned, not by looking facts up. Searching the web helps a lot, but it doesn't fix everything: a model can still misread a page, or say a source claims something it doesn't. So let's see the difference for ourselves.

Pick a factual question where the details matter, and where you can check the answer. A few kinds that work well: something recent ("What happened in the most recent Mars mission?"), something local and specific ("What are the hours of the PCC library on my campus?"), or a specific fact from this course ("When did ARPANET switch to TCP/IP?"). Then:

  1. Ask the model to answer from memory, without searching the web. (You can just say that in your prompt, or turn the search feature off if your tool has a switch for it.)
  2. Ask the same question again, this time telling it to search the web and cite its sources.
  3. Open at least two of the sources it cited, and check whether they really say what the model said they say.
  1. What question did you ask, and what were the two answers? (Paste both.)
  2. How were the two answers different? Was the from-memory answer wrong, out of date, or vaguer than the searched one?
  3. What did the sources actually say? Did they back up the model's answer, or did it get something wrong even with search turned on?

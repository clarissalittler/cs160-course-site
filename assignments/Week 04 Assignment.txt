== What every route needs ==

Whichever notebook you pick, your program should:

  1. Run without errors from top to bottom
  2. Define at least one function of your own, not a tutorial function reused as-is
  3. Call that function more than once, so it's doing real repeated work
  4. Use at least one if, elif, or else decision that changes what the program draws, says, calculates, or does
  5. Be a new, recognizably intentional artifact
  6. Include readable words, headings, labels, comments, or a short description, so the meaning doesn't depend only on color or where things sit on the screen

The medium-specific details and starter patterns are in each notebook. Parameters, extra branches, input validation, and additional loops are all optional style challenges. They're nice to have, but they're not requirements for one medium and not another.

== Grading ==

  4 (Exceeds): The notebook runs top to bottom, defines and repeatedly calls an original function, makes a meaningful conditional choice, and produces something clearly intentional that a reader can understand. Code uses sensible names and is easy to follow.

  3 (Meets): The program runs and meets most of the requirements, but one thing is missing or has a minor issue. Maybe the function is only called once, the condition doesn't actually change anything, or leftover test code interrupts the result.

  2 (Progressing): The code shows real work, but errors stop it from running all the way through, there's no original reusable function or meaningful decision, or the result is too minimal to tell what it was meant to be.

  1 (Beginning): An attempt was made, but the code doesn't yet run or produce a complete artifact.

  0: Nothing was submitted, or the final assignment cell is untouched.

If you don't get a 4, read the feedback, revise, and resubmit for full credit. You have unlimited resubmissions.

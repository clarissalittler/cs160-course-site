WEEK 6 ASSIGNMENT — THE TINY DUNGEON

Build a small text adventure that uses Python data structures to represent a connected world. It doesn't have to be a dungeon: a haunted library, a museum after closing, a spaceship, an apartment building, a dream, or any other place you can describe in text all work.

Companion Colab notebook:
https://colab.research.google.com/github/clarissalittler/cs160-course-site/blob/summerwork/assignments/Week%2006%20Assignment%20-%20The%20Tiny%20Dungeon.ipynb

Or use OnlineGDB, another browser-based interpreter, or a local editor. The program is ordinary Python and needs no files, no outside libraries, no graphics, and no install privileges.

== Core requirements ==

Your adventure needs:

  1. At least three connected locations
  2. A dictionary that stores the layout and the information about each location
  3. A while loop that keeps the adventure going until an ending or a quit
  4. Commands for looking, moving, checking inventory, and quitting
  5. At least one object the player can pick up
  6. At least one obstacle or ending that checks the player's location or inventory
  7. At least three functions with clear, different jobs
  8. A triple-quoted string used for a title screen, room display, ending, or other multi-line text
  9. Clear labels and a visible command list, so the game works without color or graphics
 10. A completed test table and one change made after watching someone play

The notebook gives you a complete three-room world, a movement function, an interface scaffold, and the command loop. Your job is to make the world your own, finish the item action, connect the pieces, and explain how they work. Combat, random events, big maps, full-sentence parsing, files, and object-oriented programming are all optional, and I'd hold off on them until the small required path works. A finished three-room game beats an unfinished thirty-room epic every time.

== What to submit ==

Submit:

  1. A Colab link, pasted code, or .py file
  2. Your world-planning table and the shortest successful path
  3. One copied playthrough from the entrance to an ending
  4. The completed test table and your playtest notes
  5. Short explanations of the data structures and of one function
  6. A note identifying any substantial copied or AI-generated code and how you tested it

Submit working partial progress even if not every feature is done. Label what works, what doesn't yet, and the next change you'd make.

== Grading ==

  4 (Exceeds): The small adventure is complete, understandable, and clearly your own; the world model, actions, interface, tests, playtest revision, and explanations all show it.

  3 (Meets): The required path works and most requirements are there, with only a minor gap in polish, evidence, or explanation.

  2 (Progressing): Several meaningful pieces work (the world model, display, movement, item, or loop), but the complete path is unreliable or important evidence is missing.

  1 (Beginning): An identifiable attempt using course concepts, even if only a small part runs or the starter is mostly unchanged.

  0: Not submitted, or no meaningful attempt.

If you don't get a 4, read the feedback, revise, and resubmit for full credit. You have unlimited resubmissions.

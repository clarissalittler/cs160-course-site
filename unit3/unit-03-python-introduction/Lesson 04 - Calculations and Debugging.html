Expressions produce values

An expression is code Python can evaluate to produce a value. A literal such as 5 is an expression. So are price * quantity and input("Name: "). Expressions can be stored, displayed, or used inside larger expressions.

-subtraction7 - 25

Two kinds of division solve different problems

Ordinary division asks, “what is the quotient, including any fractional part?” Floor division and remainder ask, “how many complete groups fit, and what is left?”

minutes = 135
hours = minutes // 60
minutes_left = minutes % 60
print(f"{minutes} minutes is {hours} hours and {minutes_left} minutes.")

Because 60 fits into 135 two complete times with 15 left, the program prints 135 minutes is 2 hours and 15 minutes. The same pair of operators can turn inches into feet and inches, distribute objects into full boxes, or determine whether a number is even:

number = 18
remainder_after_pairs = number % 2
print(remainder_after_pairs)  # 0 means no item was left without a partner

In Unit 4, number % 2 == 0 will become a complete yes-or-no question.

Order of operations and units

Python follows the familiar order of operations: parentheses first, then exponents, then multiplication and division, then addition and subtraction. Operators at the same level normally go left to right. Parentheses are useful even when they are not strictly required because they make the intended grouping visible:

average = (score_1 + score_2 + score_3) / 3

Without the parentheses, only score_3 would be divided by 3 before the other scores were added. A program can run perfectly and still compute the wrong result.

Units are part of the calculation. You cannot meaningfully add 3 hours to 12 miles, even though Python will happily add the bare numbers. Put units in variable names, prompts, or comments, and convert values to compatible units before combining them.

Replace unexplained numbers with named constants

A named constant is a variable whose value is intended not to change while the program runs. Python does not enforce constants, so programmers use names in ALL_CAPS to communicate that intent:

TIP_RATE = 0.18

meal_cost = float(input("Meal cost before tip: $"))
tip = meal_cost * TIP_RATE
total = meal_cost + tip
print(f"Tip: ${tip:.2f}")
print(f"Total: ${total:.2f}")

TIP_RATE explains what 0.18 means and puts the policy in one place. The number is not a law of nature, however. A tax rate, wage, eligibility threshold, or estimated speed may depend on place, time, or circumstance. Good code makes changeable assumptions visible and documents where they came from.

When Python gives you a traceback

You will write code, choose Run, and receive red text. This is ordinary programming. An error message is evidence, not a grade on your ability. When Python stops, it usually prints a traceback. Read it in this order:

  1. Read the last line first. It names the error type and gives a short explanation.
  2. Find the line number that points into your code.
  3. Compare what that line needs with the values and names it actually has.
  4. Change one thing, then run again.
price = input("Price: $")
tax = price * 0.08
print(tax)
Traceback (most recent call last):
  File "program.py", line 2, in <module>
    tax = price * 0.08
TypeError: can't multiply sequence by non-int of type 'float'

The last line says TypeError: the operation does not fit the types involved. input() returned a string, so the repair is to convert the input: price = float(input("Price: $")).

Four common messages

  • SyntaxError or IndentationError: Python cannot understand the program's grammar. Look for a missing quote, parenthesis, colon, or mismatched indentation.
  • NameError: Python does not know a name. Check for a typo, capitalization difference, or variable used before assignment.
  • TypeError: an operation does not make sense for the kinds of values involved, such as adding a string and an integer.
  • ValueError: the requested conversion is reasonable in general, but not for this value, such as int("twelve").

When no error message appears

A logic error allows the program to run but produces an incorrect result. Suppose a discount program says:

DISCOUNT_RATE = 0.20
original_price = 50.00
sale_price = original_price + original_price * DISCOUNT_RATE
print(f"Sale price: ${sale_price:.2f}")

Python reports no problem, but a 20% discount on $50 should be $40, not $60. The operator should be subtraction. Only a test with a known expected answer exposes that mistake.

Useful test cases include a normal case, a boundary or unusual case, and—when the program is ready to handle it—an invalid case. Write the expected result down before running so you do not let the computer's confidence persuade you.

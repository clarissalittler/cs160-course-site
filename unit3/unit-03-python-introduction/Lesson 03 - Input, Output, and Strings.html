Lesson 3 - Input, Output, and Strings

At the end of this lesson, you will be able to:

  • Collect text with input() and store the returned value.
  • Convert number-shaped text with int() or float().
  • Create readable output with print() and f-strings.
  • Design prompts and output that tell a user what the program needs and what it produced.

From a speech to a conversation

A program made entirely of fixed print() calls gives the same speech on every run. Input makes it a conversation. The built-in input() function displays a prompt, waits for the user to type, and hands the typed text back to the program:

name = input("What name would you like me to use? ")
print("Hello", name)

The assignment matters. If you write input("Name: ") without storing the result, Python still waits for an answer—but the program has no name for that answer afterward. Functions can produce values, and assignment lets us keep those values.

Input always begins as text

Even when a user types 25, input() returns the string "25". That is sensible: a keyboard sends characters, and Python cannot guess whether 25 is an age, a bus route, or part of a password. If we intend to do arithmetic, we must convert explicitly:

age_text = input("How old are you? ")
age = int(age_text)
age_next_year = age + 1
print(age_next_year)

The shorter form nests the function calls:

age = int(input("How old are you? "))

Use int() when only whole numbers make sense and float() when a fractional value is reasonable:

people = int(input("How many people? "))
distance_miles = float(input("Distance in miles: "))

If the user types three where int() expects number-shaped text, Python raises a ValueError. That does not mean the user is “bad input.” It means our current program has no plan for that perfectly possible response. We will build input-validation loops in Unit 4.

Build clear messages with f-strings

An f-string is a string with the letter f before its opening quotation mark. Expressions inside curly braces are evaluated and placed into the text:

title = input("Title of your tiny publication: ")
pages = int(input("How many pages? "))
print(f"Your publication '{title}' will have {pages} pages.")

Unlike concatenation, an f-string can include numbers without manually converting them to strings. The braces can also contain a small expression:

print(f"Printing two copies will require {pages * 2} page-sides.")

For money and measurements, formatting can make output easier to read. :.2f requests two digits after the decimal point:

cost = 7.5
print(f"Estimated cost: ${cost:.2f}")

Formatting changes how the value is displayed, not the stored value itself. cost is still the number 7.5.

A complete small program

Here is the meal-sharing idea from Lesson 1 as running Python. Notice how the pseudocode maps to code in the same order:

# Input
meal_total = float(input("Total cost of the meal in dollars: $"))
number_of_people = int(input("How many people are sharing the cost? "))

# Process
cost_per_person = meal_total / number_of_people

# Output
print(f"Each person pays ${cost_per_person:.2f}.")

A line beginning with # is a comment. Python ignores comments; they are notes for people reading the code. Good comments explain the purpose or a non-obvious choice. They do not need to translate every line into English.

Predict, run, investigate, modify.

  1. Predict the output for a $48 meal shared by 4 people.
  2. Run that case and compare the result with your prediction.
  3. Run a case where the result does not divide evenly, such as $20 shared by 3.
  4. Add an input for a tip percentage and include the tip before dividing.
  5. Change at least one prompt so the expected unit is unmistakable.

The user interface is part of the program

Prompts and output are a tiny user interface. They should not make a user guess. Compare input("Number? ") with input("Trip distance in miles: "). The second prompt identifies both the meaning and the unit. Output should also label its result; printing a bare 12.5 asks the user to remember what 12.5 represents.

Clear text is an accessibility feature. Do not communicate an important result only through color, spacing, emoji, or a picture. A screen reader can announce "Estimated travel time: 35 minutes" directly. A message such as "Result: red" may be meaningless without the surrounding visual context.

Programs should also ask only for information they actually need. A zine generator may need a preferred display name; it probably does not need a legal name, birth date, or email address. Collecting data creates responsibility for it.

Make it yours. Create a short program that asks for at least two pieces of information and produces an intentional text artifact: a tiny event announcement, a two-line poem, a museum label, a recipe scaler, or a trip estimate. Include:

  • descriptive variable names,
  • at least one useful prompt,
  • at least one f-string, and
  • output that makes sense without seeing your source code.

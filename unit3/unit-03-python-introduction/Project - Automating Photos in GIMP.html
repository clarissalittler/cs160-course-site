Small Weird Project — Automating Photos in GIMP

What you'll do: Use Python — inside a real image editor — to manipulate photos with code instead of clicking through menus. You'll see that the Python you've been learning can actually control other software.

This project is NOT graded. It's just for fun and exploration. There's nothing to turn in. If you try it and it's cool, great. If you skip it, that's fine too.

What Can You Actually Do With This Stuff?

You've been learning Python syntax — print() statements, variables, data types, math expressions. If you're anything like most students, you're wondering: "Okay, but when do I get to do something real with this?" Fair question. Let's answer it.

In this project, you're going to use Python to control an image editor. Instead of clicking through menus fifty times to process a batch of photos, you'll type a few lines of code and let the computer do the tedious work. This is what programming is actually for — automating the boring stuff so you don't have to.

What You'll Need

  • GIMP — a free, open-source image editor. Works on Windows, Mac, and Linux. Download it at gimp.org.
  • Any photo — something from your phone, a picture of your dog, a landscape, whatever. It doesn't matter what it is.

GIMP has a built-in Python console. That means there's a Python interpreter living inside the image editor, and it can talk directly to the program's guts. You can do anything with code that you could do by clicking menus — and then some.

Step-by-Step

1. Open GIMP and load a photo

Open GIMP and then open any photo (File → Open). Something colorful works best — you'll be able to see the effects more clearly.

2. Open the Python-Fu console

Go to Filters → Python-Fu → Console. A new window will pop up with a Python prompt (>>>). This is a real Python interpreter, but it has access to all of GIMP's internal functions. You can type Python code here and it will directly affect your image.

3. Get a reference to your image

Type this into the console:

image = gimp.image_list[0]
print(image.width, image.height)

You just used a variable (image) and a print statement — things you already know! The gimp.image_list[0] part grabs whichever image is currently open. The .width and .height are properties of that image — like variables that belong to it.

4. Convert your photo to grayscale

Type these lines one at a time:

drawable = pdb.gimp_image_get_active_drawable(image)
pdb.gimp_desaturate_full(drawable, 0)
pdb.gimp_displays_flush()

Look at your image. It's black and white now. You just did with three lines of code what would normally require clicking through Colors → Desaturate. That might not seem like a big deal for one photo — but imagine doing it to 200 photos.

Let's break down what happened:

  • pdb.gimp_image_get_active_drawable(image) — this is a function call. It gets the currently active layer of your image (the thing you can actually draw on or apply effects to).
  • pdb.gimp_desaturate_full(drawable, 0) — another function call. It removes all color from the layer. The 0 is an argument that tells it which desaturation method to use.
  • pdb.gimp_displays_flush() — tells GIMP to refresh the display so you can see the change.

5. Try some more effects

Undo the desaturation first (Edit → Undo in the main GIMP window, or press Ctrl+Z) so you're back to the color photo. Then try these:

# Crank up the brightness and contrast
drawable = pdb.gimp_image_get_active_drawable(image)
pdb.gimp_brightness_contrast(drawable, 50, 30)
pdb.gimp_displays_flush()

The two numbers are brightness (50) and contrast (30). Try different values — negative numbers make things darker and flatter.

# Flip the image horizontally
pdb.gimp_item_transform_flip_simple(drawable, 0, True, 0)
pdb.gimp_displays_flush()
# Invert all the colors (photo negative effect)
pdb.gimp_drawable_invert(drawable, False)
pdb.gimp_displays_flush()

Each of these is one line of Python doing something that would normally require clicking through menus. That's the power of scripting — you can express complex operations as simple, repeatable commands.

6. The batch processing idea

Here's where it gets really practical. Imagine you had 200 photos from a trip and you wanted to resize them all to 800 pixels wide for a website. By hand, you'd go Image → Scale Image, type 800, click OK — 200 times. Or you could write something like this:

# Resize the current image to 800px wide (maintaining aspect ratio)
new_width = 800
new_height = int(image.height * (800.0 / image.width))
pdb.gimp_image_scale_full(image, new_width, new_height, 0)
pdb.gimp_displays_flush()

That's variables, math expressions, a function call, and a type conversion (int()) — all things you've learned in Unit 3. With a bit more Python (loops, which you'll learn in Unit 5), you could point this at a whole folder of images and let it run while you get coffee.

Experiment!

Try this:

  • In the Python-Fu console, type pdb.gimp_ and look at the autocomplete suggestions. There are hundreds of functions. Try ones with names that sound interesting.
  • Try pdb.plug_in_pixelize(image, drawable, 10) followed by pdb.gimp_displays_flush() — it turns your photo into pixel art. Change the 10 to make the pixels bigger or smaller.
  • Try pdb.plug_in_oilify(image, drawable, 8, 1) for a painting effect.
  • Chain effects together: pixelize, then adjust brightness, then invert colors. See what kind of weird art you can make.
  • Try changing the numbers in each function call. What does each number control? Experiment and find out.

What You Just Demonstrated

You just used variables, function calls, arguments, and math expressions — the same stuff from the past few lessons — to control a real application. The dot notation (pdb.gimp_desaturate_full) is something you'll learn more about later, but the underlying idea is straightforward: you're calling functions and passing in arguments, exactly like you've been doing with print().

Programming isn't just about printing numbers to a terminal. It's a tool for controlling other software, automating repetitive tasks, and doing in seconds what would take hours by hand. The syntax you're learning right now is the foundation for all of that.

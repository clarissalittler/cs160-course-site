Repetition

Say a poem needs the same refrain four times. Copy-and-paste works, technically:

print("Again, the river answers.")
print("Again, the river answers.")
print("Again, the river answers.")
print("Again, the river answers.")

But there's something unsatisfying about this. The fact that it's one idea, repeated, is hidden across four separate lines, and if you wanted the refrain forty times you'd be scrolling. A loop says what you mean directly:

for repetition in range(4):
    print("Again, the river answers.")

print("The poem is finished.")

Read the first line as "for each value called repetition in the sequence produced by range(4), run the indented block." The indented print runs four times. The last line isn't indented, so it isn't part of the loop, so it runs once after the loop is finished.

The anatomy of a for loop

  • for begins a counted repetition.
  • repetition is the loop variable. It receives one value from the sequence during each iteration.
  • range(4) produces the values 0, 1, 2, and 3.
  • The colon ends the loop header.
  • Every statement in the loop body is indented the same amount, normally four spaces.
  • One trip through the body is called an iteration.

Why does the counting start at 0 rather than 1? This is a convention that runs all through computing, and it comes from how computers find things in memory: the first item is zero steps from the start, the second is one step away, and so on. You don't have to like it (plenty of programmers don't!) but you do have to be able to think in it, because most programming languages count this way!

Use the loop variable

Loops like these don't have to literally do the exact same thing every time. For example, you can use the loop variable, which counts how many times the loop has gone around so far:

for beat in range(4):
    print(f"Beat {beat}: clap")

That prints Beat 0 through Beat 3. If the count is meant for humans and should start at 1, you can adjust the number you display:

for beat in range(4):
    print(f"Beat {beat + 1}: clap")

Or just tell range() where to start:

for beat in range(1, 5):
    print(f"Beat {beat}: clap")

Start, stop, and step

ExpressionValues producedInterpretation
range(4)0, 1, 2, 3start at 0; stop before 4
range(2, 6)2, 3, 4, 5start at 2; stop before 6
range(2, 11, 2)2, 4, 6, 8, 10start at 2; add 2; stop before 11
range(5, 0, -1)5, 4, 3, 2, 1start at 5; subtract 1; stop before 0

The stop value is never included. Never! This is one of the most common ways to end up with an off-by-one error, where a loop runs one time too many or one too few, and experienced programmers make them too. So when you're first learning, write out the values you expect a range() to produce, and if you're not sure, check with list(range(...)) in a scratch program or a REPL.

Trace repeated state changes

A variable created before a loop can be updated on every trip through it:

total = 0

for number in range(1, 5):
    total = total + number
    print(f"Added {number}; total is now {total}")

print(f"Final total: {total}")
Iterationnumbertotal after addition
111
223

4410

This is called the accumulator pattern, and you'll use it constantly: total builds up a result across the repetitions. First, you set the total up once, before the loop, and you update it inside the loop. If total = 0 got indented into the loop body, the total would be reset to zero on every iteration and you'd end up with 4 instead of 10. (Try it!)

The same loop, different media

Loops don't care what kind of output they're producing. Here's a text pattern:

word = input("Choose a word for the refrain: ")
for line_number in range(1, 5):
    print(f"{line_number}. {word} " * line_number)

And in the Week 3 drawing route, the loop body can be turtle commands instead:

for side in range(4):
    forward(100)
    right(90)

The first loop repeats and varies text; the second repeats a movement to draw the four sides of a square. Notice that you don't need to see the drawing to understand what the second one does: each time through, the turtle moves 100 units forward and turns 90 degrees, and after four of those it's back where it started, facing the same way.

Common loop bugs

  • Missing colon: for side in range(4) produces a SyntaxError.
  • Body not indented: Python raises an IndentationError or repeats nothing useful.
  • Too much indentation: a line that was supposed to run once, after the loop, runs every single time instead.
  • Wrong stop value: range(1, 4) produces three values, not four.
  • Resetting state inside: an accumulator that never grows because it gets set back to 0 on every iteration.

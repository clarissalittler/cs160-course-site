Lesson 5 - Repetition with for and range

At the end of this lesson, you will be able to:

  • Use a for loop to repeat an indented block a known number of times.
  • Explain the values generated by one-, two-, and three-argument forms of range().
  • Use the loop variable to make each repetition meaningfully different.
  • Trace a loop and diagnose common indentation and off-by-one mistakes.

One instruction can stand for many actions

Suppose a poem needs the same refrain four times. Copying and pasting works:

print("Again, the river answers.")
print("Again, the river answers.")
print("Again, the river answers.")
print("Again, the river answers.")

But the repetition is hidden inside four separate lines. A loop makes the idea explicit:

for repetition in range(4):
    print("Again, the river answers.")

print("The poem is finished.")

Read the first line as “for each value called repetition in the sequence produced by range(4), run the indented block.” The indented print runs four times. The final unindented line runs once, after the loop.

The anatomy of a for loop

  • for begins a counted repetition.
  • repetition is the loop variable. It receives one value from the sequence during each iteration.
  • range(4) produces the values 0, 1, 2, and 3.
  • The colon ends the loop header.
  • Every statement in the loop body is indented the same amount, normally four spaces.
  • One trip through the body is an iteration.

Why does counting begin at 0? Python follows a common convention in computing: the first item is zero steps from the beginning. You do not have to love the convention, but you do need to predict it.

Use the loop variable

A loop is more interesting when each repetition changes:

for beat in range(4):
    print(f"Beat {beat}: clap")

This prints Beat 0 through Beat 3. If the audience-facing count should begin at 1, adjust the displayed value:

for beat in range(4):
    print(f"Beat {beat + 1}: clap")

Or ask range() to begin at 1:

for beat in range(1, 5):
    print(f"Beat {beat}: clap")

Start, stop, and step

range(5, 0, -1)5, 4, 3, 2, 1start at 5; subtract 1; stop before 0

The stop value is always excluded. This is the source of many off-by-one errors. Do not guess: list the expected values, then compare them with list(range(...)) in a scratch program if you need to.

Trace repeated state changes

A variable created before a loop can be updated during each iteration:

total = 0

for number in range(1, 5):
    total = total + number
    print(f"Added {number}; total is now {total}")

print(f"Final total: {total}")

This is an accumulator pattern: total gathers a result across repetitions. The important parts are initializing the total once before the loop and updating it inside. If total = 0 were indented into the loop, it would be erased and restarted during every iteration.

Repetition can create patterns in different media

The loop is not tied to any one kind of output. Here is a text pattern:

word = input("Choose a word for the refrain: ")
for line_number in range(1, 5):
    print(f"{line_number}. {word} " * line_number)

In the Week 3 drawing route, the repeated body can contain turtle commands:

for side in range(4):
    forward(100)
    right(90)

The first loop repeats and changes text; the second repeats movement to make four sides. A screen reader user does not need the drawing to understand the algorithm: on every iteration the turtle moves 100 units and rotates 90 degrees, returning to its starting position after four sides.

Common loop bugs

  • Missing colon: for side in range(4) produces a SyntaxError.
  • Body not indented: Python raises an IndentationError or repeats nothing useful.
  • Too much indentation: a line intended to run once after the loop instead runs every time.
  • Wrong stop value: range(1, 4) produces three values, not four.
  • Resetting state inside: an accumulator never grows because it is assigned 0 on every iteration.

  5. Turn the program into an intentional tiny poem, chant, sound score, or narrated visual pattern.

Automation changes scale—and responsibility

A loop lets one instruction affect four items, four thousand items, or four million items. That scale can remove drudgery and make tools available to more people. It can also repeat a bad assumption at enormous speed. Before automating a repeated action, ask: what exactly is being repeated, who benefits, who must correct mistakes, and how will someone stop or appeal the process?

Lesson 5 - Repetition with for and range

By the end of this last lesson of the unit, you'll be able to:

  • Use a for loop to repeat an indented block a known number of times.
  • Explain the values generated by one-, two-, and three-argument forms of range().
  • Use the loop variable to make each repetition meaningfully different.
  • Trace a loop and diagnose common indentation and off-by-one mistakes.

One instruction can stand for many actions

Say a poem needs the same refrain four times. Copy-and-paste technically works:

print("Again, the river answers.")
print("Again, the river answers.")
print("Again, the river answers.")
print("Again, the river answers.")

But the fact that this is one idea repeated is hidden across four separate lines. A loop says it outright:

for repetition in range(4):
    print("Again, the river answers.")

print("The poem is finished.")

Read the first line as “for each value called repetition in the sequence produced by range(4), run the indented block.” The indented print runs four times; the final unindented line runs once, after the loop is done.

The anatomy of a for loop

  • for begins a counted repetition.
  • repetition is the loop variable. It receives one value from the sequence during each iteration.
  • range(4) produces the values 0, 1, 2, and 3.
  • The colon ends the loop header.
  • Every statement in the loop body is indented the same amount, normally four spaces.
  • One trip through the body is called an iteration.

Why does the counting start at 0? Python follows a convention that runs deep in computing: the first item is zero steps from the beginning. You don't have to love this convention — plenty of programmers don't — but you do have to be able to predict it.

Use the loop variable

A loop gets more interesting when each trip through it is a little different:

for beat in range(4):
    print(f"Beat {beat}: clap")

That prints Beat 0 through Beat 3. If the audience-facing count should start at 1, you can adjust the displayed value:

for beat in range(4):
    print(f"Beat {beat + 1}: clap")

Or just ask range() to start at 1:

for beat in range(1, 5):
    print(f"Beat {beat}: clap")

Start, stop, and step

ExpressionValues producedInterpretation
range(4)0, 1, 2, 3start at 0; stop before 4

range(5, 0, -1)5, 4, 3, 2, 1start at 5; subtract 1; stop before 0

The stop value is always excluded — always — and this is where an enormous number of off-by-one errors come from. Don't guess. Write out the values you expect, and if you're not sure, check yourself with list(range(...)) in a scratch program.

Trace repeated state changes

A variable created before a loop can be updated during each iteration:

total = 0

for number in range(1, 5):
    total = total + number
    print(f"Added {number}; total is now {total}")

print(f"Final total: {total}")

This is the accumulator pattern: total gathers up a result across repetitions. The two parts doing the real work are setting the total up once before the loop and updating it inside. If total = 0 were indented into the loop, the total would get wiped back to zero on every iteration.

Repetition can create patterns in different media

Loops aren't tied to any one kind of output. Here's a text pattern:

word = input("Choose a word for the refrain: ")
for line_number in range(1, 5):
    print(f"{line_number}. {word} " * line_number)

In the Week 3 drawing route, the repeated body can contain turtle commands:

for side in range(4):
    forward(100)
    right(90)

The first loop repeats and varies text; the second repeats movement to make four sides. And a screen reader user doesn't need to see the drawing to understand the algorithm: on every iteration the turtle moves 100 units and rotates 90 degrees, ending up back at its starting position after four sides.

Common loop bugs

  • Missing colon: for side in range(4) produces a SyntaxError.
  • Body not indented: Python raises an IndentationError or repeats nothing useful.
  • Too much indentation: a line that was supposed to run once, after the loop, runs every single time instead.
  • Wrong stop value: range(1, 4) produces three values, not four.
  • Resetting state inside: an accumulator that never grows because it gets set back to 0 on every iteration.

Automation changes scale—and responsibility

A loop lets one instruction touch four items, four thousand items, or four million items. That kind of scale can erase drudgery and put tools in more people's hands. It can also repeat a bad assumption at enormous speed. So before automating a repeated action, it's worth asking: what exactly is being repeated, who benefits, who has to clean up the mistakes, and how does someone stop or appeal the process?

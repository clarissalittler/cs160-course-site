Unit 3 Summary

We started this unit by making Python do something and then worked backwards to understand what we'd done. Here's the shape of it: a program is an algorithm written down as source code, and the interpreter runs that code from top to bottom. Variables give values names so we can hold on to them. Input lets one run differ from the next. Expressions turn old values into new ones, output tells a person what happened, and a for loop lets us say "do this four times" instead of pasting the same line four times.

What to carry forward

  • An algorithm is a precise sequence of steps, like a recipe that leaves nothing to guesswork. Writing it out as pseudocode first lets you check the plan before you have to worry about where the colons go.
  • print(), input(), int(), float(), and range() are functions Python already knows. You use one by calling it, which means writing its name with parentheses after it and putting whatever it needs inside.
  • The assignment operator = is a command, not an equation. It says "store the value on the right under the name on the left," which is why count = count + 1 makes sense in Python even though it would be nonsense in a math class.
  • Every value has a type, and the basic ones are str, int, float, and bool. Quotation marks are what make something a string, and that matters right away, because input() always gives you back a string. If you want to do arithmetic with what someone typed, convert it with int() or float() first.
  • F-strings let you drop values and expressions straight into a message, like f"Total: ${total:.2f}", so the code reads much like the sentence that will show up on screen.
  • Arithmetic includes + - * / // % **, and Python will happily calculate whatever you write. Parentheses, named constants, descriptive names, and units are how you show the next reader (including you, next week) what you meant.
  • When you get a traceback, read its last line first, find the line in your code it points at, change one thing, and run again. Changing one thing at a time is how you find out which change fixed it.
  • A logic error is sneakier, because the program runs and just gives the wrong answer. The only way to catch one is to write down the result you expect before you run a test, and to include boundary cases, like a bill split between exactly one person.
  • for item in range(...): repeats the indented body, and the loop variable takes a new value each time around. The stop value is never included, so range(1, 4) gives you 1, 2, and 3.
  • Every program is built out of human choices about what to collect, calculate, label, automate, and say. Should the meal-splitting program include the tip? What should it do when 0 people are splitting the bill? Python doesn't answer questions like those for you, so whoever writes the program is the one deciding.

Can you explain these programs?

distance_miles = float(input("Trip distance in miles: "))
travel_time_hours = distance_miles / 12
print(f"Estimated cycling time: {travel_time_hours:.1f} hours")

Identify the input, conversion, stored values, calculation, unit assumption, and output. What test would reveal whether 12 miles per hour is a reasonable estimate for the intended users?

for line_number in range(1, 4):
    print(f"Line {line_number}: we make the web together.")

List the three values of line_number, predict the complete output, and explain which punctuation marks define the loop.

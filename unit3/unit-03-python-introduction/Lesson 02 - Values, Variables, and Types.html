Lesson 2 - Values, Variables, and Types

When you're done with this lesson, you'll be able to:

  • Store a value in a variable and trace how reassignment changes it.
  • Distinguish strings, integers, floating-point numbers, and Boolean values.
  • Choose descriptive variable names and include units where they matter.
  • Predict the final state and output of a short sequential program.

Values are the material programs work with

Last lesson, print() displayed pieces of text. Each of those pieces of text was a value: a chunk of data a program can store or use. Programs work with plenty of other data too — numbers, yes-or-no answers, images, sounds, lists, &c. We'll start with four basic Python types:

  • str (string): text such as "Vancouver" or "42"
  • int (integer): a whole number such as 42 or -7
  • float: a number that can have a decimal part, such as 42.0 or 3.75
  • bool (Boolean): one of the special values True or False

Quotation marks matter here. 42 is a number; "42" is two text characters that happen to look like one. You can do arithmetic with the first. The second might be a room label, part of an address, or text that's waiting to be converted into a number.

Try it. Run this program, then change one value at a time:

print("CS 160")
print(160)
print(3.5)
print(True)

print(type("CS 160"))
print(type(160))

The type() function reports what type a value is, and its answer gets handed straight to print() — a function call nested inside another function call. Python works out the inner one first.

Variables give values useful names

A variable is a name that refers to a value. The statement below assigns the value 12 to the name cupcakes:

cupcakes = 12
print(cupcakes)

That equals sign is the assignment operator, and it reads right to left: “take the value 12 and store it under the name cupcakes.” It is not asking whether two things are equal — Python uses == for that question, and we'll get to it in Unit 4.

Programs change state

All the values a program currently has stored make up its state, and assignment is how that state changes. Trace this program one line at a time:

score = 10
print(score)
score = score + 5
print(score)
score = 2
print(score)

score = 1010nothing

score = 2210, then 15
third print210, then 15, then 2

In score = score + 5, Python looks up the old value on the right side first, adds 5, and then stores the result back under the same name. The shorter form score += 5 does exactly the same thing. One caution: reassignment keeps no secret history. Unless we stashed the old value somewhere else, it's gone — replaced, not archived.

Names are part of the explanation

Python variable names can contain letters, digits, and underscores, but can't begin with a digit. They're also case-sensitive, so total and Total are two different names. The convention among Python programmers is lowercase words separated by underscores:

distance_miles = 12.5
travel_time_minutes = 35
route_name = "Green line"
wheelchair_accessible = True

Names like these do more than keep Python happy — they tell another person what the values mean. Compare d = 12.5 with distance_miles = 12.5. The second one records the unit, which is exactly the kind of thing that prevents a miles-versus-kilometers mistake. (And that other person reading your code? A few weeks from now, it's probably you.)

Naming is a social choice, too. Names like person, member, or account keep code general; a name built around an unnecessary assumption can turn some users into exceptions without anyone choosing that on purpose. Clear code makes its categories visible enough to question.

Strings can be combined

The + operator adds numbers, but hand it two strings and it joins them instead — an operation with the delightfully fancy name concatenation:

first = "Ada"
last = "Lovelace"
full_name = first + " " + last
print(full_name)

Python refuses to join a string and a number with +, and honestly that refusal is doing us a favor: it makes us say out loud whether 3 should be treated as a number or as the character "3". Next lesson, f-strings will give us a much more pleasant way to mix different types into one message.

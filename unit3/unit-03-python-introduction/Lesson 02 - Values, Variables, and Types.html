Lesson 2 - Values, Variables, and Types

When you're done with this lesson, you'll be able to:

  • Store a value in a variable and trace how reassignment changes it.
  • Distinguish strings, integers, floating-point numbers, and Boolean values.
  • Choose descriptive variable names and include units where they matter.
  • Predict the final state and output of a short sequential program.

Values are the stuff programs work with

Last lesson, print() displayed some text. Each piece of text was a value: a chunk of data that a program can store, pass around, or do something with. Text is only the beginning, though. Programs deal in numbers, yes-or-no answers, images, sounds, lists of things, &c. We'll start with four basic Python types:

  • str (string): text such as "Vancouver" or "42"
  • int (integer): a whole number such as 42 or -7
  • float: a number that can have a decimal part, such as 42.0 or 3.75
  • bool (Boolean): one of the special values True or False

Quotation marks matter here, and this trips people up at first. 42 is a number. "42" is text that happens to be made of two digits. You can do arithmetic with the first one. The second one might be a room number, part of a street address, or text that's about to be turned into a number, but as far as Python is concerned right now it's no more a number than "hi" is.

Try it. Run this program, then change one value at a time:

print("CS 160")
print(160)
print(3.5)
print(True)

print(type("CS 160"))
print(type(160))

Look at the last two lines. type() is a function that tells you what type a value has, and we're handing its answer straight to print(), so that's a function call sitting inside another function call. Python works out the inner one first, then the outer one. We'll be nesting calls like this a lot.

Variables give values names

A variable is a name that refers to a value. This statement stores the value 12 under the name cupcakes:

cupcakes = 12
print(cupcakes)

The equals sign here is the assignment operator, and it doesn't mean what it means in math class. It's not a claim that two things are equal; it's a command, and it reads right to left: "take the value 12 and store it under the name cupcakes." (Python has a separate operator, ==, for actually asking whether two things are equal. We'll get to it in Unit 4.) Why use = for something that isn't equality? Mostly history: the languages Python borrowed from did it that way, and by now it's a convention nobody can change.

Programs change state

All the values a program has stored at a given moment make up its state, and assignment is how the state changes. Let's trace this program one line at a time:

score = 10
print(score)
score = score + 5
print(score)
score = 2
print(score)

score = 2210, then 15
third print210, then 15, then 2

Look carefully at score = score + 5. Python evaluates the right-hand side first, using the old value of score, gets 15, and then stores 15 under the name score. So the same name means two different things on the two sides of the equals sign, which is exactly why it helps to read assignment as a command rather than an equation. The shorthand score += 5 does the same job. One more thing to notice: once we assign score = 2, the 15 is gone. Python doesn't keep a history of old values. If you wanted that 15 later, you needed to have stashed it under some other name first.

Names are part of the explanation

Python variable names can have letters, digits, and underscores, but can't start with a digit. They're case-sensitive too, so total and Total are two different variables (and a reliable source of confusing bugs). The convention among Python programmers is lowercase words joined with underscores:

distance_miles = 12.5
travel_time_minutes = 35
route_name = "Green line"
wheelchair_accessible = True

Python would be just as happy with d = 12.5. So why bother typing out distance_miles? Because code gets read by people far more often than it gets written, and the name is where you tell the reader what the number means. This name also records the unit, which is precisely the thing that prevents a miles-versus-kilometers mixup six weeks from now. And the person reading your code six weeks from now, having forgotten everything about it? Most likely that's you.

Names carry assumptions, too. A variable called person or member or account stays general. A name built on an assumption about who the user is can turn some people into edge cases without anyone ever deciding that it should. At the scale of one small program this hardly matters, but it's a habit that matters more and more as programs grow.

Strings can be glued together

The + operator adds numbers, but hand it two strings and it joins them end to end instead. This has the impressive-sounding name concatenation:

first = "Ada"
last = "Lovelace"
full_name = first + " " + last
print(full_name)

Try "Ada" + 3, though, and Python stops and complains. It won't guess whether you wanted the number 3 or the character "3", and that's a reasonable thing to refuse to guess about, even if it's a little annoying in the moment. Next lesson we'll meet f-strings, which are a much nicer way to mix text and numbers in one message.

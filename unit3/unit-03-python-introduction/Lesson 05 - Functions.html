Lesson 5 - Functions: Your Own Verbs

At the end of this lesson, you will be able to:

  • Call a function to run a chunk of code.
  • Define your own function using the def keyword.
  • Explain why functions help you avoid repeating yourself.

You've been using functions all along

Here's a secret: you already know what a function is. Every time you've written print(...) or input(...), you've been using a function. Someone, somewhere, wrote a chunk of code that knows how to display text on the screen, gave it the name print, and now you get to use it just by writing its name and a pair of parentheses. You say the name, the code runs. That's called calling a function.

Think of a function as a verb you've taught the computer - a named action. print means "show this on the screen." input means "go ask the human something." Python comes with a whole pile of these verbs built in. But the really powerful move - the one this lesson is about - is that you can invent your own verbs.

Defining your own function

To teach Python a new verb, you define a function. The recipe looks like this:

def greet():
    print("Hello there!")
    print("Welcome to CS 160.")

Let's read that line by line:

  • def is the keyword that means "I'm about to define a function." (Think "def" for "define.")
  • greet is the name we're giving our new verb. We made it up - it could have been anything.
  • The empty parentheses () will eventually let us hand the function some information. For now they're empty - more on that in the next lesson.
  • The colon : and the indented lines below it are the function's body - the actual work it does. Everything indented underneath belongs to the function.

Here's the part that trips everyone up at first: defining a function does not run it. The code above teaches Python what greet means, but nothing prints yet. It's like writing a recipe card - the card existing doesn't cook dinner. To actually run the function, you have to call it by writing its name with parentheses:

def greet():
    print("Hello there!")
    print("Welcome to CS 160.")

greet()
greet()

Why bother? Don't Repeat Yourself

Imagine you're writing a program that has to print a little divider line in a few different places:

print("=" * 30)
print("   CS 160 Gradebook")
print("=" * 30)

# ... some other code ...

print("=" * 30)
print("   Final Report")
print("=" * 30)

That print("=" * 30) banner keeps showing up. If you later decide the line should be 40 characters instead of 30, you have to hunt down every copy and change it. That's tedious and it's how bugs sneak in. Functions fix this. Write the banner once, give it a name, and call it whenever you need it:

def banner():
    print("=" * 30)

banner()
print("   CS 160 Gradebook")
banner()

Now the banner lives in exactly one place. Change it once and every call updates. Programmers have a slogan for this: DRY - "Don't Repeat Yourself." If you find yourself copying and pasting the same lines over and over, that's usually your code begging to become a function.

Try it! Write a function called cheer that prints your favorite short phrase three times (anything you like). Then call it. As a bonus, call it again right after - did it cheer six times total? Predict before you run.

A few rules to remember

  • You have to define a function before you call it - Python reads your file top to bottom, so the def needs to come above the call.
  • The function name follows the same rules as variable names (letters, numbers, underscores; no spaces; don't start with a number).
  • Don't forget the parentheses when you call it. Writing greet by itself just refers to the function; greet() actually runs it.
  • Everything that should be "inside" the function must be indented underneath the def line.

You've been writing a function this whole time

Here's the payoff promised way back in Lesson 2. That def main(): wrapper you've been copying into every program? It's a function definition. You were defining a function called main, putting your program inside its body, and then - on that last line - calling it with main(). That's exactly why nothing ran until the main() at the bottom: defining main only described it; the main() call is what actually set it going. You already knew how to do this - now you know what it's called.

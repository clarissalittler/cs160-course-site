Lesson 7 - When Python Yells at You

At the end of this lesson, you will be able to:

  • Read a Python error message and find the line it's pointing at.
  • Recognize the handful of errors you'll actually run into: SyntaxError, NameError, TypeError, and ValueError.
  • Follow a calm, repeatable process to track down and fix a bug.

Let's talk about the thing nobody warns you about: you are going to write code, hit Run, and get back a wall of red text. A lot. This is not a sign that you're bad at this - it is the single most normal thing in all of programming. Professional developers with twenty years of experience produce errors every single day. The difference between them and a frustrated beginner isn't that they avoid errors; it's that they've learned to read them without panicking. This lesson is about becoming that calmer person.

An error is Python trying to help

When Python hits something it can't do, it stops and prints an error message (often called a traceback). It feels like being yelled at. It's really the opposite - Python is handing you a note that says exactly what went wrong and exactly where. The trick is knowing how to read the note instead of slamming the laptop shut.

Here's the whole secret, and it's almost embarrassingly simple: read the last line first. A traceback is printed top-to-bottom, but the bottom line is the punchline - it names the type of error and gives a plain-English hint. The lines above it are just Python showing its work on the way down.

How to read a traceback

Say we run this three-line program, but fat-finger the variable name:

message = "Hello there"
print("About to greet you...")
print(mesage)   # oops - typo

Python prints:

About to greet you...
Traceback (most recent call last):
  File "greet.py", line 3, in <module>
    print(mesage)
NameError: name 'mesage' is not defined

Don't let the middle scare you. Read it in three moves:

  1. The last line is the headline: NameError: name 'mesage' is not defined. That's the what - the kind of error (NameError) and a description (Python has never heard of anything called mesage).
  2. The line 3 part is the where. Python is pointing at the exact line to go look at. Not line 1, not "somewhere in your program" - line 3.
  3. The quoted code shows you the scene of the crime: print(mesage). Sure enough - we defined message but asked for mesage. Fix the typo and it runs.

When there's a stack of files. Sometimes the traceback is long, listing several files. Still start at the bottom. Then look for the last line that mentions a file you actually wrote - that's almost always where your bug lives. The frames above it are usually Python's own code doing what you asked.

The four errors you'll actually meet

There are many kinds of errors, but as a beginner you'll bump into the same few over and over. Learn these four on sight and you've covered the vast majority of your first months.

SyntaxError / IndentationError - "that's not valid Python"

You broke a grammar rule, so Python can't even start running. Classic causes: a missing colon at the end of a def, if, or loop; a missing closing quote or parenthesis; or indentation that doesn't line up.

def greet(name)      # missing the colon!
    print("Hi", name)
  File "greet.py", line 1
    def greet(name)
                   ^
SyntaxError: expected ':'

The little ^ caret points right at where Python got confused. Add the colon and the indentation, and it's happy.

NameError - "I've never heard of that"

You used a name Python doesn't know. Almost always it's a typo (like mesage above), a variable you forgot to create, or a capitalization slip - Python thinks Score and score are two completely different things.

TypeError - "you can't do that to those things"

You asked for an operation that doesn't make sense for the types involved. The most common beginner version is mixing text and numbers - remember, input from input() is always a string:

age = input("Your age: ")   # this is the TEXT "20", not the number 20
next_year = age + 1         # can't add a number to text
TypeError: can only concatenate str (not "int") to str

The fix is to convert first: age = int(input("Your age: ")). Any time a TypeError mentions str and int together, suspect a forgotten int() or float().

ValueError - "right type, wrong value"

The type is fine, but the specific value can't be used that way. The everyday case: trying to turn text that isn't a number into a number.

count = int("twelve")   # "twelve" is a string, but not a number-shaped one
ValueError: invalid literal for int() with base 10: 'twelve'

int("12") would be fine; int("twelve") is not, because int() can't make sense of it. This one shows up constantly when a user types something unexpected.

Two flavors of wrong. All of the above are errors that stop your program - Python refuses to continue. There's a sneakier kind: a logic error, where the program runs perfectly but gives the wrong answer (you wrote + where you meant -). No red text will save you there - only testing with inputs where you already know the right answer. When your program runs but the output is off, suspect a logic error and start checking your math.

A calm way to squash a bug

When something breaks, resist the urge to change things at random until it works - that way lies madness. Use this loop instead:

  1. Read the last line of the traceback. What type of error, and what's the hint?
  2. Go to the line number it names and read that line slowly, out loud if you have to.
  3. Form one guess about what's wrong. Just one.
  4. Change one thing to test that guess - not five things.
  5. Run it again. Fixed? Move on. Different error? Progress! Same error? Your guess was wrong - undo the change and form a new guess.

Two old tricks that feel silly and work anyway:

  • Rubber-duck debugging. Explain your code, line by line, out loud to a rubber duck (or a patient friend, or the wall). The bug very often reveals itself mid-sentence, because saying it forces you to actually read what you wrote instead of what you meant to write.
  • Print your way through it. Not sure what a variable actually holds? Drop in a print(age) right before the line that breaks and see. Half of debugging is just discovering that a variable didn't contain what you assumed.

Try it! This little program has a bug. Read the error, find the line, fix one thing, and run it again - use the loop above.

def main():
    price = input("Enter the price: ")
    tip = price * 0.20
    print("Suggested tip:", tip)

main()
Show the fix

Running it and typing 10 gives a TypeError (you can't multiply text by a number in a way that makes sense here) - or, sneakier, it "works" but prints the price repeated twenty times! Either way the root cause is that input() hands back a string. Convert it: price = float(input("Enter the price: ")). Now price is a real number and the math works.

That's the end of Unit 3! You can write straight-line programs, store data in variables, build your own functions - and now, crucially, you can read the error messages that come with the territory. Next unit your programs start making decisions and repeating work, and you'll put this debugging calm to good use.

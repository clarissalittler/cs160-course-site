Lesson 3 - Patterns for Processing Collections

By the time you finish this lesson, you should be able to:

  • Recognize traversal, transformation, filtering, counting, accumulation, and min/max patterns.
  • Build a new list rather than accidentally destroying source data.
  • Separate collection processing from keyboard input and formatted display.
  • Test collection code with empty, one-item, typical, and boundary cases.

Most collection programs use a few recurring moves

A playlist, a search page, a gradebook, a shopping cart, and a transit app all look like different programs, but under the hood they keep doing the same handful of jobs:

  • Traverse: visit every item.
  • Transform: produce a changed value for every item.
  • Filter: keep only items that match a condition.
  • Aggregate: combine many items into one result, such as a count or total.
  • Find an extreme: locate the smallest or largest item by some measure.

Once you can recognize which pattern you're in, you get to start from the logic instead of guessing at syntax.

Traversal: perform one job for every item

hours = [1.5, 2.0, 0.5, 3.0]

for value in hours:
    print(f"Recorded study time: {value:.1f} hours")

The loop doesn't change the list at all—it just visits each element and displays it.

Transformation: build a corresponding collection

temperatures_f = [32, 50, 68, 77]
temperatures_c = []

for fahrenheit in temperatures_f:
    celsius = (fahrenheit - 32) * 5 / 9
    temperatures_c.append(celsius)

print(temperatures_c)

The result has one Celsius value for every Fahrenheit value. Building a new list keeps the source around for comparison or later reuse. Replacing elements in the original is sometimes the right call, but it should be a decision—not an accident.

Filtering: build a collection of matches

all_locations = ["online", "library", "online", "student center"]
in_person_locations = []

for location in all_locations:
    if location != "online":
        in_person_locations.append(location)

print(in_person_locations)

A filter doesn't change which items exist in the source; it produces a selected view of them. In a real interface, say what filter is active and how many matches were found. An empty result, meanwhile, should say “No matching locations” rather than just sit there looking broken.

Counting and accumulating

donations = [5.00, 12.50, 3.00, 20.00]
total = 0.0
large_donation_count = 0

for amount in donations:
    total += amount
    if amount >= 10:
        large_donation_count += 1

print(f"Total: ${total:.2f}")
print(f"Donations of at least $10: {large_donation_count}")

An accumulator begins with an identity value—0 for addition—and updates once per relevant element. A counter is just an accumulator that adds 1 whenever a condition is met. Python will happily hand you sum(donations) and len(donations), but writing the loop yourself once makes the state change visible, and it prepares you for the specialized summaries the built-ins don't cover.

Minimum and maximum without a made-up starting value

wait_times = [18, 7, 24, 11]

if len(wait_times) == 0:
    print("No wait times were recorded.")
else:
    shortest = wait_times[0]
    longest = wait_times[0]

    for minutes in wait_times:
        if minutes < shortest:
            shortest = minutes
        if minutes > longest:
            longest = minutes

    print(f"Range: {shortest} to {longest} minutes")

Initialize from a real element, not from 0 or 999999. I don't trust made-up starting values: they work right up until the data changes, and then they fail. The empty-list branch is necessary because an empty list has no first element to start from.

Put processing in a function

def average(numbers):
    if len(numbers) == 0:
        return None

    total = 0
    for number in numbers:
        total += number
    return total / len(numbers)

result = average([4, 7, 10])
if result is None:
    print("No average is available.")
else:
    print(f"Average: {result:.1f}")

The function receives data and returns a result. It doesn't ask for keyboard input, and it doesn't decide how an entire report should look. That separation is exactly what makes it easy to test:

  • average([]) should return None.
  • average([8]) should return 8.
  • average([4, 7, 10]) should return 7.

None represents the absence of a result, which is different from 0—after all, 0 could be a genuine average.

Filters and summaries are choices about attention

A “top results” function decides what becomes visible. An average compresses variation into one number. A maximum highlights an extreme. None of these is inherently dishonest, but each one leaves something out. So when you present a summary, label the measure, the unit, the number of records, and any active filter—and ask whether missing values or excluded records systematically change the story.

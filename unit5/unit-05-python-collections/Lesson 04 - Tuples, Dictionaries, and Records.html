Lesson 4 - Tuples, Dictionaries, and Records

At the end of this lesson, you will be able to:

  • Create, index, and unpack tuples and explain their immutability.
  • Use tuples for fixed groups, multiple-value returns, loop unpacking, and compound dictionary keys.
  • Create, read, add, and update dictionary entries.
  • Use a dictionary as one record and a list of dictionaries as a table of records.
  • Choose between a tuple and dictionary based on the meaning and expected evolution of the data.

Tuples keep a fixed group together

A tuple is an ordered collection, usually written with parentheses. It is a good fit when a small number of values form one fixed unit:

point = (3, 5)
color = (40, 120, 200)
book_pair = ("Parable of the Sower", "Octavia Butler")

print(point[0])
print(point[1])
print(len(point))

Like strings and lists, tuples are indexed from 0 and support slicing, looping, membership, and len(). Unlike a list, a tuple is immutable: after creation, its elements cannot be replaced, appended, or removed.

point = (3, 5)
point[0] = 9  # TypeError: a tuple does not support item assignment

Immutability communicates intent: these values belong together as one fixed description. It does not make the information permanently safe or correct; the variable point can still be assigned a different tuple later.

Parentheses and the one-element tuple

Parentheses often group an expression, so the comma is what truly creates a tuple:

not_a_tuple = (5)
one_item_tuple = (5,)

print(type(not_a_tuple))
print(type(one_item_tuple))

(5) is just the integer 5 inside grouping parentheses. (5,) is a one-element tuple. This punctuation looks strange because tuples are normally useful when they contain several related values.

Packing and unpacking

Creating a tuple packages—or packs—several values together. Unpacking assigns its elements to separate names in one statement:

point = (3, 5)
x, y = point

print(f"x is {x}")
print(f"y is {y}")

The number of names must match the number of elements. x, y, z = point raises a ValueError because a two-element tuple cannot fill three names.

Unpacking also makes swaps concise:

left = "tea"
right = "coffee"
left, right = right, left
print(left, right)

Python first packs the right-side values, then unpacks them into the left-side names.

Functions can return a tuple

A function returns one value. That one value may be a tuple containing several parts:

def quotient_and_remainder(total, group_size):
    quotient = total // group_size
    remainder = total % group_size
    return quotient, remainder

full_boxes, items_left = quotient_and_remainder(53, 12)
print(f"Full boxes: {full_boxes}")
print(f"Items left: {items_left}")

return quotient, remainder constructs a two-element tuple. The caller immediately unpacks it into descriptive names. This pattern is common when two results naturally belong to one calculation.

Loop unpacking makes fixed records readable

events = [
    ("Repair Cafe", "Saturday", 0.0),
    ("Bike Workshop", "Tuesday", 10.0),
    ("Seed Swap", "Sunday", 0.0),
]

for name, day, cost in events:
    print(f"{name} | {day} | ${cost:.2f}")

Each list element is a tuple. During every iteration, the tuple is unpacked into name, day, and cost. This is much clearer than repeatedly writing event[0], event[1], and event[2].

Many Python tools produce values intended for unpacking. enumerate() produces an index and element, zip() pairs elements from collections, dictionary .items() produces key-value pairs, and database query rows are commonly tuple-like.

titles = ["Kindred", "Parable of the Sower", "Dawn"]

for number, title in enumerate(titles, start=1):
    print(f"{number}. {title}")

Tuples can be dictionary keys

Dictionary keys must be immutable and hashable. A tuple whose elements are also hashable can represent a compound key:

temperatures = {
    (2026, 7, 8): 72,
    (2026, 7, 9): 76,
    (2026, 7, 10): 74,
}

print(temperatures[(2026, 7, 9)])

The key is a fixed (year, month, day) triple. A list cannot serve as a dictionary key because it can change after insertion.

Dictionaries look up fields by meaning

A tuple's positions must be remembered. A dictionary attaches a meaningful key to every value:

resource = {
    "name": "Northside Tool Library",
    "neighborhood": "Arbor Lodge",
    "cost": 0.0,
    "wheelchair_entry": True,
}

print(resource["name"])
print(resource["cost"])

The keys are strings; the values have different types. resource["cost"] explains more than resource[2], especially as a record grows.

Add, update, and handle missing fields

resource["phone"] = "555-0142"
resource["cost"] = 5.0

print("email" in resource)
print(resource.get("email", "not provided"))

for key, value in resource.items():
    print(f"{key}: {value}")

Assignment adds a new key or replaces an existing value. Direct lookup of a missing key raises KeyError; .get(key, fallback) returns a fallback. .items() supplies key-value pairs, which the loop unpacks into two variables.

One dictionary record; a list of records

resources = [
    {"name": "Tool Library", "area": "North", "cost": 0.0},
    {"name": "Repair Cafe", "area": "Central", "cost": 0.0},
    {"name": "Bike Workshop", "area": "North", "cost": 10.0},
]

for resource in resources:
    print(f"{resource['name']} — ${resource['cost']:.2f}")

The outer list answers “which record?” The inner dictionary answers “which field?” This nested shape is common in configuration files, APIs, and data loaded from CSV or JSON.

Choose the representation that explains the data

RepresentationGood fitTradeoff
Tuplesmall fixed group whose position is conventional: coordinates, RGB color, database row, paired return valuesreaders must know what each position means
Dictionaryrecord with named fields, optional fields, or a schema likely to evolvemore syntax and mutable state
Listordered collection expected to grow, shrink, or changeposition alone does not name record fields

A tuple is not an inferior dictionary, and a dictionary is not a superior tuple. A point expressed as (x, y) is compact and conventional. A community-resource record benefits from named fields because its meaning and schema matter to many readers.

A schema is still an agreement

Whether a record is positional or named, document its meaning. For a dictionary, a small data dictionary records key, type or unit, definition, required status, and missing-value rule. For a tuple, state its order explicitly: (name: str, day: str, cost_usd: float). The model should expose assumptions rather than asking future readers to reverse-engineer them.

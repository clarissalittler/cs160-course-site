Lesson 2 - Lists and Changing Collections

Here's what you should be able to do by the end of this lesson:

  • Create, index, slice, and measure a list.
  • Add, replace, and remove list elements.
  • Use membership and empty-list tests safely.
  • Trace how mutation and simple aliasing change a program's state.

One name can refer to many related values

Suppose a resource directory needs several neighborhood names. You could make separate variables, neighborhood_1, neighborhood_2, neighborhood_3, and you can already feel how badly that's going to go once there are forty of them. So let's do it properly. A list holds an ordered, changeable collection under one name:

neighborhoods = ["Arbor Lodge", "Cully", "Lents"]
print(neighborhoods)
print(len(neighborhoods))
print(neighborhoods[0])
print(neighborhoods[-1])

Lists use square brackets, and indexing and slicing work exactly as they did for strings: zero-based, stop excluded, negative indexes from the end. Everything from last lesson carries over. One difference: a list's elements can be values of any type, including other lists. The second difference is that the elements of a list can actually change, that is "mutate" in computer science parlance. One would say that "lists are mutable, strings are immutable".

A list can change

resources = ["library", "food pantry"]
resources.append("repair cafe")
resources.insert(1, "tool library")
resources[0] = "community library"
resources.remove("food pantry")
print(resources)

Let's trace the list after each statement:

OperationList afterward
initial value["library", "food pantry"]
append["library", "food pantry", "repair cafe"]
insert(1, ...)["library", "tool library", "food pantry", "repair cafe"]
replace index 0["community library", "tool library", "food pantry", "repair cafe"]
remove["community library", "tool library", "repair cafe"]

.append(value) adds to the end. .insert(index, value) wedges a value in at a position and shifts everything after it over by one. Assigning to an index replaces an element. .remove(value) takes out the first matching value, and raises a ValueError if there's no such value at all.

Membership makes a safe question

requested = input("Resource to remove: ").strip().lower()

if requested in resources:
    resources.remove(requested)
    print("Removed.")
else:
    print("That resource was not in the list.")

in and not in give you Booleans, which means the program can ask before trying something that might fail. One catch: this example assumes the stored names are already lowercase. If they aren't, the program needs a clearer plan for comparing text.

Empty collections need explicit thought

scores = []

if len(scores) == 0:
    print("No scores are available yet.")
else:
    print(f"First score: {scores[0]}")

Indexing, min(), max(), and averaging all fail on an empty list, and we'll run into every one of those next lesson. And "no records yet" is a completely normal state, especially the first time a program runs! So let's give it a real message, rather than letting the program crash on line 4 with an IndexError that somebody has to decode.

Loop directly over elements

We can loop over the elements of a list just the same way that we looped over the elements of a string!

resources = ["community library", "tool library", "repair cafe"]

for resource in resources:
    print(f"Available: {resource}")

Use an index loop when you actually need to change elements by position:

for index in range(len(resources)):
    resources[index] = resources[index].title()

The direct loop is nearly always easier to read. Much like with strings, you can loop with the index and a range() call, but if you just want the individual elements it doesn't buy you much!

Two names can refer to one list

original = ["zine", "poster"]
also_original = original
also_original.append("field guide")
print(original)

The output includes "field guide". We appended through also_original, and yet original changed too. What happened? Well, assignment didn't copy the list. It made a second name for the same list, so both names point at one object. This is called aliasing, and the first time it bites you it feels like Python is lying. It isn't. A list is a thing that lives somewhere, and a variable is a label stuck on it. Put two labels on the same thing and either label will show you the changes. If you want an actual copy of a simple list like this one, take a full slice:

independent_copy = original[:]
independent_copy.append("map")
print(original)
print(independent_copy)

You don't need a theory of computer memory for this yet. The practical rule is enough: change a list through one name, and the change shows up through every other name for that list.

A collection is a claim about belonging

Deciding what goes in a list is data modeling, whether or not you meant to be doing any. A list called accessible_resources needs a definition of "accessible." Wheelchair access? A quiet space? Captions? Transit nearby? Language access? Cost? One Boolean label can flatten a lot of very different needs into a single yes-or-no. A clear program names the specific property it actually records.

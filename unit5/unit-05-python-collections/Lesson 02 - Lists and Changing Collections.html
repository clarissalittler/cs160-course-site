Lesson 2 - Lists and Changing Collections

Here's what you should be able to do by the end of this lesson:

  • Create, index, slice, and measure a list.
  • Add, replace, and remove list elements.
  • Use membership and empty-list tests safely.
  • Trace how mutation and simple aliasing change a program's state.

One name can refer to many related values

Suppose a resource directory needs several neighborhood names. You could make separate variables—neighborhood_1, neighborhood_2, neighborhood_3—but you can already feel how badly that scales. A list stores an ordered, changeable collection under one name:

neighborhoods = ["Arbor Lodge", "Cully", "Lents"]
print(neighborhoods)
print(len(neighborhoods))
print(neighborhoods[0])
print(neighborhoods[-1])

Lists use square brackets, and their indexes and slices follow the same zero-based, stop-exclusive rules as strings—everything from last lesson carries over. Unlike a string, though, a list's elements may be values of any type, including other collections.

A list can change

resources = ["library", "food pantry"]
resources.append("repair cafe")
resources.insert(1, "tool library")
resources[0] = "community library"
resources.remove("food pantry")
print(resources)

Let's trace the state of the list after each statement:

OperationList afterward
initial value["library", "food pantry"]
append["library", "food pantry", "repair cafe"]
insert(1, ...)["library", "tool library", "food pantry", "repair cafe"]
replace index 0["community library", "tool library", "food pantry", "repair cafe"]
remove["community library", "tool library", "repair cafe"]

.append(value) adds one value at the end. .insert(index, value) wedges a value in at a position and shifts the later values over. Assignment to an index replaces an element. .remove(value) removes the first matching value—and raises a ValueError if the value isn't there at all.

Membership makes a safe question

requested = input("Resource to remove: ").strip().lower()

if requested in resources:
    resources.remove(requested)
    print("Removed.")
else:
    print("That resource was not in the list.")

in and not in produce Boolean values, which lets a program ask before attempting an operation that might fail. One caveat: this example assumes the stored names are already lowercase. If they aren't, a real program needs a clearer plan for comparing text.

Empty collections need explicit thought

scores = []

if len(scores) == 0:
    print("No scores are available yet.")
else:
    print(f"First score: {scores[0]}")

Indexing, min(), max(), and averaging can all fail on an empty list. “No records” is often a completely normal state, too—especially the first time a program runs. Design a useful message for it rather than letting the program crash mysteriously.

Loop directly over elements

resources = ["community library", "tool library", "repair cafe"]

for resource in resources:
    print(f"Available: {resource}")

Use an index loop when you genuinely need to replace elements by position:

for index in range(len(resources)):
    resources[index] = resources[index].title()

A direct element loop is usually easier to read. An index loop is a tool, not a badge of seriousness.

Two names can refer to one list

original = ["zine", "poster"]
also_original = original
also_original.append("field guide")
print(original)

The output includes "field guide"—we appended through also_original, and yet original changed too. That's because assignment didn't copy the list; both names refer to the same changeable object. This is called aliasing. If what you want is a shallow copy of a simple list like this one, take a full slice:

independent_copy = original[:]
independent_copy.append("map")
print(original)
print(independent_copy)

You don't need a deep theory of computer memory yet. The practical rule is enough: change a list through one name, and the change may be visible through any other name that refers to the same list.

A collection is a claim about belonging

Choosing what belongs in one list is data modeling, whether you meant to be modeling or not. A list called accessible_resources needs a definition of “accessible”: wheelchair access, quiet space, captions, transit access, language access, cost, or something else? One Boolean label can flatten several very different needs into a single yes-or-no. A clear program names the specific property it actually records.

Build and trace a changing list.

  1. Create an empty list for five resources, songs, recipes, or study strategies.
  2. Add at least three elements with .append().
  3. Replace one element and safely remove one.
  4. Print a numbered display using range(len(...)).
  5. Test the empty-list case and an attempted removal of a missing value.
  6. Explain what qualifies an item to belong in your collection.

Lesson 1 - Strings as Sequences

By the end of this lesson, you'll be able to:

  • Use indexes, negative indexes, slices, and len() with strings.
  • Traverse text with a for loop and build a transformed result.
  • Normalize simple text with string methods while preserving an original value when needed.
  • Explain why “character” and “one visible symbol” are not always identical.

Text is an ordered collection

Until now, a string has probably felt like one indivisible value: "Portland" is just "Portland". But Python also treats a string as a sequence—an ordered collection whose elements you can visit one at a time. Which means a program can inspect text, transform it, count things in it, search it, &c.

city = "Portland"
print(len(city))
print(city[0])
print(city[1])
print(city[-1])

len(city) is 8. An index is a position in the sequence, and Python starts counting positions at 0—so city[0] is "P", city[1] is "o", and city[-1] counts backward to give you the final element, "d".

CharacterPortland
Forward index01234567
Negative index-8-7-6-5-4-3-2-1

Ask for an index that doesn't exist—city[8], say—and Python raises an IndexError. The last valid forward index is always len(city) - 1, an off-by-one detail that catches everybody at least once.

Slices select a section

A slice pulls out a whole section at once. You give it a starting index and a stopping index, and the stop is excluded:

city = "Portland"
print(city[0:4])   # Port
print(city[4:8])   # land
print(city[:4])    # Port
print(city[4:])    # land
print(city[::2])   # P r l n, with no spaces in the actual result

Like range(), a slice includes its start and stops just before its end. Leave out the start and Python assumes “from the beginning”; leave out the stop and it assumes “through the end.” A third value is a step, so city[::2] selects indexes 0, 2, 4, and 6 and produces "Prln".

Oddly enough, a slice that runs past the available range silently stops at the end, while a single invalid index raises an error. Don't memorize that as trivia—open an interpreter and try both, it sticks better that way.

Traverse a string

When you need every element but not its numeric position, loop over the string directly:

word = "signal"
vowel_count = 0

for character in word:
    if character in "aeiou":
        vowel_count += 1

print(f"{word} contains {vowel_count} vowels.")

The membership operator in asks whether one value occurs anywhere inside a collection. Each time through the loop, character receives the next element of word.

Reach for range(len(word)) only when the position itself matters:

for index in range(len(word)):
    print(f"Index {index} contains {word[index]}")

Strings do not change in place

Strings are immutable: you can't reach in and replace one element with word[0] = "S"—Python will refuse. What you do instead is build a new string:

message = "meet at noon"
new_message = ""

for character in message:
    if character == " ":
        new_message += "-"
    else:
        new_message += character.upper()

print(new_message)  # MEET-AT-NOON

This is a transformation pattern you'll use constantly: begin with an empty result, inspect each element, and add a transformed version to the result.

Methods provide common transformations

raw_reply = "  Yes Please  "
normalized_reply = raw_reply.strip().lower()

print(raw_reply)
print(normalized_reply)
print(normalized_reply.startswith("yes"))
print(normalized_reply.replace("please", ""))

Useful methods include .strip(), .lower(), .upper(), .replace(), .startswith(), .endswith(), and .split(). Each one returns a new value and leaves the original alone. Keep that original around when its exact form matters—a person's chosen capitalization, say, or their punctuation.

One Python element is not always one visible symbol

For simple English examples, “character” is a fine shorthand. Human writing systems are more complicated than that, though. A visibly accented letter may be stored as one code point or as a base letter followed by a combining mark. Some emoji are assembled from several code points. So Python's basic indexing can split apart something a reader experiences as one symbol.

None of this is a reason to avoid strings. It's a reason to be honest about the limits of a model. A rule such as “a name must be at most 20 characters” may behave differently across languages, and converting every name to lowercase may not serve a real person's preferred form. Normalizing a temporary value for comparison is useful; casually rewriting the data that records someone's identity is not.

Unit 5 Summary

This unit moved from values to models. Strings, lists, and tuples are all sequences; tuples keep fixed positional groups together; dictionaries attach meaningful keys to values; and a list of dictionaries can represent a small table of records. Loop by loop, the work repeats—traverse, transform, filter, count, aggregate, unpack, find an extreme. And the final question is never just whether the structure works, but whether its fields and interface serve people.

What to carry forward

  • Indexes begin at 0; negative indexes count backward; slices include the start and exclude the stop.
  • Strings are immutable sequences. Methods return new strings; preserve exact human-entered text when its form matters.
  • Lists are ordered and mutable. Treat empty collections and missing elements as expected states, not surprises.
  • Two names can refer to the same list, so mutation through one alias may appear through the other.
  • Collection patterns include traversal, transformation, filtering, aggregation, counting, and min/max.
  • A tuple is an ordered immutable sequence suited to compact fixed groups.
  • Tuple unpacking assigns elements to separate names; it appears in multiple-value returns, enumerate(), zip(), dictionary .items(), and database rows.
  • A hashable tuple can be a compound dictionary key.
  • Functions separate calculations from input and display and make empty/boundary tests repeatable.
  • A dictionary maps keys to values. A list of dictionaries represents multiple records with named fields.
  • A schema or data dictionary explains types, units, meanings, required fields, and missing-value rules.
  • Choose tuples for fixed conventional positions and dictionaries when named or evolving fields better explain the record.
  • Data minimization, recoverable errors, keyboard access, descriptive labels, predictable navigation, and usability testing are part of technical quality—not extra credit.
  • A record is a selective model, not the person or situation itself.

Readiness check

Can you create and unpack a tuple, explain a multiple-value return, and recognize when fixed positions are clearer than named fields? Can you explain why a catalog is a list of dictionary records, state its schema, filter without changing the source, summarize a numeric field, handle zero matches, and spot a field that shouldn't be collected in the first place? The real test of all of it: can another person complete the intended task from the labels alone?

Garbage in, garbage out

If programs read in bad data as input, it will produce bad data as output: garbage in, garbage out. Design programs to accept only good data. Inspect all input before processing. If the input is invalid, reject and prompt to enter correct data. Input validation is defensive programming - anticipating both obvious and not so obvious errors.

Types of errors  

Types of errors you should consider when designing your programs:

  • Invalid string input - prompting for ‘yes’ or ‘no’ and user enters ‘cat’.
  • Unreasonable values - entering negative or > 120 when prompted for their age.
  • Empty input - the user does not enter any values, causing a division by 0 error when calculating the average.

String validation

Run the program below. (Copy or download the string.py and run in your IDE of choice.) What are the user input problems with this program? One of the problems is if the user enters ‘Yes’, it does not work as intended! We can fix this by changing user input to all lower or uppercase so we don't need to compare against all possible case variations, such as YES, yes, YEs, etc. 

def main():
    response = ""

    response = input("Do you like coding? (yes/no): ")

    if response == 'yes':
        print("Yay!")
    else:
        print("Oh no!")

    print("\nGoodbye!")

main()

Using lower() and upper() is useful for changing case, but what happens if the user enters ‘cat’? If the user enters something other than ‘yes’ or ‘no’ we want to give an error message and keep asking again until they finally enter ‘yes’ or ‘no’! Use a validation loop to keep prompting the user until they enter valid input. Run the program below for an example. (Copy from or download the string_case.py and run in your IDE of choice.)

def main():
    response = ""

    response = input("Do you like coding? (yes/no): ") 
    # Loop while their response is not 'yes' AND is not 'no'.
    # When user enters 'yes' or 'no' one of the conditions will
    # be false, so the AND will be false and the loop will exit
    while response.lower() != 'yes' and response.lower() != 'no':
        print("Invalid response!")
        response = input("\nDo you like coding? (yes/no): ") 

    # When we get here - we are guaranteed to have 'yes' or 'no' !!
    if response.lower() == 'yes':
        print("Yay!")
    else: # if it is not 'yes', it has to be 'no', since we validated
          # the user input
        print("Oh no!")

    print("\nGoodbye!")

main()

Unreasonable input

Another potential problem is unreasonable input from the user. Suppose you are writing a program to prompt a user to enter their age. Instead of allowing any age to be entered, validate for ages [0, 120], including 0 and 120. If the user entered any age < 0 or age > 120, give an error and prompt again before continuing.

Empty input

What happens when you run a program to prompt for a list of numbers and then calculate the average, but the user does not enter any values to average? Run the program (Copy from or download the empty_input.py and run in your IDE of choice) below and provide 0 as the first input. What happens? Avoid these types of errors by adding an if/else statement to check if count is greater than 0, meaning they have entered values!

def main():
    num = -1
    sum = 0
    count = 0

    while num != 0:
        num = int(input("Enter integer (0 to quit): "))
        sum = sum + num
        if num != 0:
            count = count + 1

    print("\nSum is:", sum)
    print("Average is:", sum / count)

main()

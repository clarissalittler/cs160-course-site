Lesson 4 - Loop Patterns

At the end of this lesson, you will be able to:

  • Use the accumulator pattern to build a running total or count.
  • Use a sentinel value to end a loop.
  • Use a loop to validate user input.

Loops become really powerful once you know a few standard patterns - shapes of code that come up again and again. Learn these three and you'll recognize them everywhere.

The accumulator pattern

Want to add up a bunch of numbers, or count how many of something you've seen? You use an accumulator: a variable that you set up before the loop and update inside it, so it "accumulates" a result as the loop runs. The most important detail: the accumulator has to start outside the loop, or it would reset every time around.

A counter is the same idea, but you add 1 each time instead of adding a value - that's how you'd count how many numbers were negative, or how many vowels are in a word.

Sentinel values: looping until a signal

Often you don't know in advance how many times to loop - you just keep going until the user says stop. A sentinel is a special "stop" value the user can enter to end the loop (like entering 0 to quit). Here's a program that keeps adding numbers until the user enters 0:

def main():
    num = -1
    total = 0
    count = 0

    while num != 0:
        num = int(input("Enter integer (0 to quit): "))
        total = total + num
        if num != 0:
            count = count + 1

    print("\nSum is:", total)
    print("Average is:", total / count)

main()

Bug Alert: what happens if the user enters 0 right away? Then count is still 0, and total / count tries to divide by zero - which crashes the program. Real programs have to guard against empty or unexpected input. That's exactly what the next pattern is for.

A bonus variation: while True and break

Remember the while True: program that could never stop - the classic infinite loop? Here's the piece it was missing. The break statement immediately exits the loop it's inside - which means "loop forever" plus "break when you see the sentinel" is another perfectly good way to write the same program:

def main():
    total = 0
    count = 0

    while True:
        num = int(input("Enter integer (0 to quit): "))
        if num == 0:
            break
        total = total + num
        count = count + 1

    print("\nSum is:", total)
    print("Average is:", total / count)

main()

Some programmers prefer this version because the "are we done?" check sits right where the answer arrives - just after the input() - so there's no need to give num a fake starting value or repeat the if num != 0: test to protect count. When you find yourself contorting a loop condition to avoid processing the sentinel, break often reads cleaner. One caution, though: a while True: whose break can never be reached (or that has no break at all) is exactly that infinite loop again - so if you use this pattern, make sure the exit really can happen.

Validating input

Programmers have a saying: "garbage in, garbage out." If your program trusts whatever the user types, one bad entry can wreck everything. Input validation means checking input and refusing to move on until it's acceptable - and a while loop is the perfect tool: keep re-asking while the answer is invalid.

Input Validation

This program won't accept anything except "yes" or "no" - it loops until the user cooperates. Notice .lower() from the strings lesson doing the work of treating "Yes", "YES", and "yes" the same:

def main():
    response = input("Do you like coding? (yes/no): ")

    # keep asking while the answer is neither 'yes' nor 'no'
    while response.lower() != 'yes' and response.lower() != 'no':
        print("Invalid response!")
        response = input("\nDo you like coding? (yes/no): ")

    # once we get here, response is guaranteed to be 'yes' or 'no'
    if response.lower() == 'yes':
        print("Yay!")
    else:
        print("Oh no!")

main()

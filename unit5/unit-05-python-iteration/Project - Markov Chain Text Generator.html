Small Weird Project — Markov Chain Text Generator

What you'll do: Build a program that generates fake text that sounds weirdly plausible. It's called a Markov chain, and it's the great-great-grandparent of ChatGPT.

This project is NOT graded. It's just for fun and exploration. There's nothing to turn in. If you try it and it's cool, great. If you skip it, that's fine too.

Loops + Randomness = Creativity?

You've learned about loops and random numbers. Individually, they're useful tools. But when you combine them, something surprising happens: you can build programs that produce output that feels almost creative. Not intelligent — we're a long way from that — but weirdly, entertainingly plausible.

The program you're about to build is called a Markov chain text generator. It reads a piece of text, learns which words tend to follow which other words, and then generates brand-new sentences by randomly choosing "what comes next" over and over. The result is grammatically dubious nonsense that somehow captures the flavor of the original text. Feed it Shakespeare and you get pseudo-Shakespeare. Feed it cooking recipes and you get bizarre instructions for meals that don't exist. It's delightful.

The Idea

Here's the concept in plain English:

  1. Look at a piece of text. For every word, write down what word(s) come after it.
  2. Now, to generate new text: pick a random starting word. Look up what words can follow it. Pick one randomly. Now look up what can follow that word. Pick one randomly. Repeat.

That's it. It's shockingly simple, and the results are shockingly fun.

For example, given the text "the cat sat on the mat the cat ate the food" —

  • After "the" you can get: cat, mat, cat, food
  • After "cat" you can get: sat, ate
  • After "sat" you can get: on
  • After "on" you can get: the

So if you start with "the", you might randomly get "cat", then "ate", then "the", then "mat" — producing "the cat ate the mat." A sentence that never appeared in the original text, but sounds like it could have.

The Code

Here's the complete program. Copy it into your Python environment and run it:

import random

# A small sample text (you can replace this with anything!)
text = """the cat sat on the mat the cat ate the food
the dog sat on the mat the dog ate the bone
the cat sat on the rug the dog sat on the rug"""

# Step 1: Build the chain
# For each word, record what words come after it
words = text.split()
chain = {}

for i in range(len(words) - 1):
    current = words[i]
    next_word = words[i + 1]
    if current not in chain:
        chain[current] = []
    chain[current].append(next_word)

# Step 2: Generate new text
current_word = random.choice(words)
output = [current_word]

for i in range(30):
    if current_word in chain:
        next_word = random.choice(chain[current_word])
        output.append(next_word)
        current_word = next_word
    else:
        break

print(" ".join(output))

Run it a few times. You'll get different output each time — that's the randomness at work.

What's Happening Here?

Let's walk through the important parts.

Building the chain

words = text.split()
chain = {}

for i in range(len(words) - 1):
    current = words[i]
    next_word = words[i + 1]
    if current not in chain:
        chain[current] = []
    chain[current].append(next_word)

First, text.split() breaks the text into a list of individual words. Then we create a dictionary called chain. You haven't formally learned about dictionaries yet — that's coming in Unit 6 — but think of it as a lookup table. Each word is a "key," and the "value" is a list of words that followed it in the original text.

The for loop goes through every word (except the last one) and says: "The word at position i was followed by the word at position i + 1. Add that to the lookup table." The if statement checks whether we've seen this word before — if not, we create a new empty list for it first. That's your Unit 4 selection statement doing real work!

After the loop runs, chain looks something like:

{
    "the": ["cat", "mat", "cat", "food", "dog", "mat", "dog", "bone", ...],
    "cat": ["sat", "ate", "sat"],
    "sat": ["on", "on", "on", "on"],
    "on":  ["the", "the", "the", "the"],
    ...
}

Notice that "the" can be followed by lots of different words, but "sat" is always followed by "on." That's because in our sample text, sitting always happens on something. The chain captures these patterns.

Generating new text

current_word = random.choice(words)
output = [current_word]

for i in range(30):
    if current_word in chain:
        next_word = random.choice(chain[current_word])
        output.append(next_word)
        current_word = next_word
    else:
        break

We pick a random starting word with random.choice() — the same random module from this unit's lessons. Then we loop 30 times (generating 30 more words). Each time through the loop:

  1. Look up the current word in the chain.
  2. If it's there, randomly pick one of the words that can follow it.
  3. Add that word to the output and make it the new current word.
  4. If the current word isn't in the chain (meaning it was the very last word in the original text and nothing ever followed it), stop.

That random.choice() call is doing all the creative work. Because words that appear more often in the "next word" list get picked more often, the generated text tends to follow the same patterns as the original. It's probability, not intelligence — but it feels like something more.

Experiment!

Try this — this is where it gets really fun:

  • Replace the sample text with something longer. The tiny cat-and-dog text is just a demo. Try pasting in a paragraph (or several!) from your favorite book, song lyrics, a Wikipedia article, or even your own writing. The more text you feed it, the more interesting and varied the output gets.
  • Try feeding it a whole chapter of a book from Project Gutenberg (free public domain books). Paste the text between the triple quotes. Moby Dick generates some truly unhinged output.
  • Change the output length. Replace range(30) with range(100) or range(200) for longer passages.
  • Feed it two different authors mixed together. Paste a paragraph of Shakespeare followed by a paragraph of a cooking blog. The generator will mash them together in surprising ways.
  • Run it multiple times. Because of random.choice(), you get different results every time. Some will be nonsense. Some will accidentally produce something that sounds almost profound.

The Connection to ChatGPT

This tiny program is doing, in principle, what ChatGPT does: predicting the next word based on what came before. The difference?

  • Your Markov chain looks at one previous word. ChatGPT looks at hundreds or thousands of tokens (word-pieces) of context.
  • Your chain uses simple frequency counting. ChatGPT uses neural networks with billions of parameters.
  • Your chain was trained on a few sentences. ChatGPT was trained on a significant fraction of all text ever written on the internet.

But the core idea — predict the next word — is the same. You just built the simplest possible version of the same concept. When you get to Unit 9, where we talk about large language models in detail, remember this project. The leap from your 25-line Markov chain to ChatGPT is enormous in scale and sophistication, but the fundamental question both systems are answering is identical: "Given what came before, what word is likely to come next?"

A note on dictionaries: This code uses a Python dictionary (chain = {}), which you haven't learned yet. Don't worry about understanding every detail of how it works — you'll cover dictionaries properly in Unit 6. For now, just think of it as a lookup table: you give it a word, and it gives you back a list of words that can follow it. The point of this project is to see loops and randomness working together, not to master dictionaries.

What You Just Demonstrated

You combined for loops, the range() function, random.choice(), if-statements, and string operations into a program that produces emergent behavior — output that's more interesting and surprising than any individual line of code would suggest. That's one of the genuinely magical things about programming: simple rules, repeated many times, can produce complexity that surprises even the person who wrote the code.

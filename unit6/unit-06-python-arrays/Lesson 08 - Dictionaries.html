  • Loop through dictionaries.
  • Explain when to use a dictionary vs. a list.

The Problem with Lists

Lists are great when you know the position of what you're looking for. Need the third item? Easy — my_list[2]. But what if you want to look something up by name instead of by number?

Think about a phone book. You don't flip to "position 47" and hope it's the person you want. You look up someone's name, and the phone book gives you their number. That's a fundamentally different kind of lookup — and it's exactly what dictionaries are for.

Your First Dictionary

A dictionary stores key-value pairs. The key is what you look up (like a name), and the value is what you get back (like a phone number). Here's how you make one:

phone_book = {
    "Clarissa": "503-555-1234",
    "Marcus": "971-555-5678",
    "Priya": "503-555-9012"
}

print(phone_book["Clarissa"])  # 503-555-1234
print(phone_book["Priya"])     # 503-555-9012

A few things to notice:

  • Dictionaries use curly braces {} — not square brackets (lists) or parentheses (tuples).
  • Each entry is a key: value pair, separated by a colon.
  • You look up values using the key inside square brackets: phone_book["Clarissa"].
  • Keys must be unique — you can't have two entries for "Clarissa." If you try, the second one just overwrites the first.

Adding and Updating

Unlike tuples, dictionaries are mutable — you can add new entries and change existing ones whenever you want. The syntax is the same either way:

phone_book = {
    "Clarissa": "503-555-1234",
    "Marcus": "971-555-5678",
    "Priya": "503-555-9012"
}

# Add a brand-new entry
phone_book["Jordan"] = "541-555-3456"

# Update an existing entry
phone_book["Marcus"] = "503-555-0000"

print(phone_book["Jordan"])   # 541-555-3456
print(phone_book["Marcus"])   # 503-555-0000 (updated!)

If the key doesn't exist yet, Python creates it. If it already exists, Python replaces the old value with the new one. Same syntax, two different behaviors — Python figures out which one you mean.

Checking if a Key Exists

Here's something that trips up a lot of beginners. What happens if you try to look up a key that doesn't exist?

phone_book = {"Clarissa": "503-555-1234"}
print(phone_book["Zoe"])  # CRASH!

Common Error: Accessing a key that doesn't exist gives you a KeyError:

KeyError: 'Zoe'

Python doesn't know what to give you — there's no entry for "Zoe" — so it crashes. Always check first!

The easiest way to avoid this is with the in keyword:

phone_book = {
    "Clarissa": "503-555-1234",
    "Marcus": "971-555-5678"
}

name = input("Who are you looking for? ")

if name in phone_book:
    print(f"{name}'s number is {phone_book[name]}")
else:
    print(f"{name} is not in the phone book.")

There's also a handy method called .get() that lets you provide a default value instead of crashing:

# Returns the value if found, or "Not found" if not
number = phone_book.get("Zoe", "Not found")
print(number)  # Not found

The .get() method is great for quick lookups where you don't need the full if/else block.

Looping Through Dictionaries

Just like with lists and tuples, you can loop through a dictionary. The most common approach uses .items(), which gives you both the key and the value on each pass through the loop:

phone_book = {
    "Clarissa": "503-555-1234",
    "Marcus": "971-555-5678",
    "Priya": "503-555-9012"
}

for name, number in phone_book.items():
    print(f"{name}: {number}")

That for name, number in phone_book.items() line is doing tuple unpacking — the same trick you learned in the Tuples lesson! Each key-value pair comes out as a tuple, and Python unpacks it right into your loop variables.

You can also loop through just the keys or just the values if that's all you need:

# Just the keys
for name in phone_book.keys():
    print(name)

# Just the values
for number in phone_book.values():
    print(number)

Practical Example: Word Counter

Let's put it all together with a real-world example. Say you've got a sentence and you want to count how many times each word appears. This is a classic use case for dictionaries — the word is the key, and the count is the value:

def main():
    sentence = "the cat sat on the mat the cat"
    word_counts = {}

    for word in sentence.split():
        if word in word_counts:
            word_counts[word] = word_counts[word] + 1
        else:
            word_counts[word] = 1

    for word, count in word_counts.items():
        print(f"'{word}' appears {count} time(s)")

main()

Let's walk through what's happening:

  1. We start with an empty dictionary {}.
  2. sentence.split() breaks the sentence into a list of words: ["the", "cat", "sat", "on", "the", "mat", "the", "cat"].
  3. For each word, we check: is it already in our dictionary? If yes, add 1 to the count. If no, set the count to 1.
  4. At the end, we loop through and print the results.

The output looks like this:

'the' appears 3 time(s)
'cat' appears 2 time(s)
'sat' appears 1 time(s)
'on' appears 1 time(s)
'mat' appears 1 time(s)

This pattern — "check if a key exists, then update or create it" — comes up all the time when working with dictionaries. It's worth getting comfortable with.

Dictionaries vs. Lists

Here's a quick comparison to help you choose the right tool:

ListDictionary
Syntax[1, 2, 3]{"a": 1, "b": 2}
Lookup byPosition (index number)Key (a meaningful name)
OrderItems stay in insertion orderItems stay in insertion order
DuplicatesAllowedKeys must be unique
Good forOrdered collections, sequencesLooking things up by name
ExampleA list of test scoresStudent names mapped to grades

Use a list when order matters and you access items by position. Use a dictionary when you want to look things up by a meaningful key — a name, a word, an ID, &c.

Nested Dictionaries

One last thing before we wrap up. The values in a dictionary can be anything — including other dictionaries. This lets you build more complex data structures:

students = {
    "Alice": {"major": "Biology", "gpa": 3.8},
    "Bob": {"major": "Art", "gpa": 3.2}
}

print(students["Alice"]["major"])  # Biology
print(students["Bob"]["gpa"])      # 3.2

The first set of brackets picks the student, and the second set picks the field within that student's record. We won't go deep on nested dictionaries in this class, but it's good to know the possibility is there. You'll see patterns like this in JSON data, web APIs, and all sorts of real-world programming.

Quick Recap

Dictionaries give you a way to store and look up data by name instead of by position. You've now seen three Python data structures — lists, tuples, and dictionaries — and each one has its sweet spot:

  • Lists — ordered, changeable collections. Great when you need to add, remove, or rearrange items.
  • Tuples — ordered, unchangeable records. Great for grouping related values that should stay together.
  • Dictionaries — key-value lookups. Great when you want to find something by a meaningful name.

Knowing which one to reach for is a big part of thinking like a programmer. The more you practice, the more natural the choice becomes.

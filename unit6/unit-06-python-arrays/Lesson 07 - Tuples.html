  • Use tuples to group related data together.

What's a Tuple?

You already know lists — they're one of the handiest tools in Python. Tuples are like lists' more responsible sibling. They look similar, but once you create a tuple, you can't change it. That's the big idea: tuples are immutable, meaning their contents are locked in after creation.

Here's the side-by-side comparison:

# A list (mutable -- you can change it)
my_list = ["Portland", "Eugene", "Salem"]

# A tuple (immutable -- you can't change it)
my_tuple = ("Portland", "Eugene", "Salem")

Notice the difference? Lists use square brackets [], tuples use parentheses (). That's really all it takes to make one. In fact, Python is pretty relaxed about it — you can even create a tuple with just commas and no parentheses at all:

my_tuple = "Portland", "Eugene", "Salem"
print(type(my_tuple))  # <class 'tuple'>

But the parentheses make your code easier to read, so it's good practice to include them.

One gotcha: if you want a tuple with just one item, you need a trailing comma. Without the comma, Python thinks the parentheses are just for grouping, like in a math expression:

not_a_tuple = ("Portland")    # This is just a string!
actual_tuple = ("Portland",)  # THIS is a tuple with one element
print(type(not_a_tuple))      # <class 'str'>
print(type(actual_tuple))     # <class 'tuple'>

Why Use Tuples?

If tuples are just lists you can't change, why would you ever use them? Great question. Tuples shine when your data represents a unit — a group of values that belong together and shouldn't be modified independently.

Think about it: a song has a title, an artist, and an album. Those three things go together as a package. You wouldn't want to accidentally change the artist of a song to something else — that would just be wrong. Here are some natural tuples:

  • A song: ("Bohemian Rhapsody", "Queen", "A Night at the Opera")
  • A coordinate on a map: (45.5152, -122.6784)
  • A student record: ("Priya", "A", "Computer Science")
  • A food cart review: ("Nong's Khao Man Gai", "Thai", 4.8)

Tuples are perfect for data that belongs together as a unit. You'll see this pattern a lot in Assignment 3, so pay close attention here.

Creating and Accessing Tuples

Indexing works exactly the same as with lists. The first element is at index 0, the last is at index -1, &c.:

song = ("Bohemian Rhapsody", "Queen", "A Night at the Opera")

print(song[0])    # Bohemian Rhapsody
print(song[1])    # Queen
print(song[-1])   # A Night at the Opera
print(len(song))  # 3

You can also use len() to get the number of elements, and you can loop through a tuple with a for loop — just like a list. Everything you know about reading from a list works with tuples.

But here's where things get different. Try to change an element:

song = ("Bohemian Rhapsody", "Queen", "A Night at the Opera")
song[0] = "We Will Rock You"  # This will CRASH!

Common Error: If you try to modify a tuple element, Python will give you a TypeError:

TypeError: 'tuple' object does not support item assignment

This isn't a bug — it's the whole point. Tuples are meant to be read-only. If you need to change things, use a list instead.

Tuple Unpacking

This is the killer feature of tuples, and once you learn it, you'll use it everywhere. Unpacking lets you pull all the values out of a tuple and assign them to individual variables in a single line:

song = ("Bohemian Rhapsody", "Queen", "A Night at the Opera")
title, artist, album = song

print(f"{title} by {artist}")          # Bohemian Rhapsody by Queen
print(f"From the album: {album}")      # From the album: A Night at the Opera

The number of variables on the left has to match the number of elements in the tuple. If they don't match, Python will throw a ValueError. But when they do match, it's a beautifully clean way to work with grouped data.

You can even unpack directly in a function call or a print statement — it's incredibly flexible.

Try it!

Create a tuple for your favorite food cart: (name, cuisine, price_range). Unpack it into three separate variables, then print a sentence using all three. Something like: "I love [name] — they serve [cuisine] and it's [price_range]."

Lists of Tuples

Here's where things get really useful — and this is the pattern you'll use in Assignment 3. You can put tuples inside a list. Each tuple is one record, and the list is your whole collection:

music_db = [
    ("Bohemian Rhapsody", "Queen", "Rock"),
    ("So What", "Miles Davis", "Jazz"),
    ("Alright", "Kendrick Lamar", "Hip-Hop"),
    ("Blue in Green", "Miles Davis", "Jazz")
]

for title, artist, genre in music_db:
    print(f"{title} by {artist} ({genre})")

See what's happening in that for loop? Each time through, Python grabs one tuple from the list and unpacks it into title, artist, and genre automatically. That's tuple unpacking at work inside a loop — no extra steps needed.

Try it!

Add two more songs to music_db and run the loop again. Make sure your new tuples have three elements each (title, artist, genre).

Filtering a List of Tuples

Now let's do something more interesting. What if you only want to see songs from a specific genre? You combine the loop with an if statement:

music_db = [
    ("Bohemian Rhapsody", "Queen", "Rock"),
    ("So What", "Miles Davis", "Jazz"),
    ("Alright", "Kendrick Lamar", "Hip-Hop"),
    ("Blue in Green", "Miles Davis", "Jazz")
]

print("Jazz tracks:")
for title, artist, genre in music_db:
    if genre == "Jazz":
        print(f"  {title} by {artist}")

This prints only the Jazz songs. You could also search by artist, filter by any field, count how many match — the possibilities are wide open. This is exactly the kind of thing you'll build in Assignment 3, so make sure this pattern clicks for you.

When to Use Tuples vs. Lists

Here's a quick reference to help you decide:

ListTuple
Syntax[1, 2, 3](1, 2, 3)
Mutable?Yes — add, remove, changeNo — locked after creation
Good forCollections that grow or changeFixed records or grouped data
ExampleA shopping listA single receipt entry (item, qty, price)

The rule of thumb: if your data might change — items being added, removed, or updated — use a list. If the data represents a fixed record or unit of information that should stay together, use a tuple. And if you want a collection of fixed records? That's a list of tuples — the best of both worlds.

Putting It All Together

Let's end with a complete example that ties everything together. This program builds a small student database and lets you look up students by major:

def main():
    students = [
        ("Alice", "Biology", 3.8),
        ("Bob", "Art", 3.2),
        ("Carlos", "Computer Science", 3.5),
        ("Diana", "Biology", 3.9),
        ("Eve", "Art", 3.7)
    ]

    search = input("Enter a major to search for: ")

    print(f"\nStudents majoring in {search}:")
    found = False
    for name, major, gpa in students:
        if major == search:
            print(f"  {name} (GPA: {gpa})")
            found = True

    if not found:
        print("  No students found in that major.")

main()

This is a preview of the kind of program you'll build in Assignment 3. You've got a list of tuples, you're unpacking them in a loop, and you're filtering with a condition. If this makes sense to you, you're in great shape for what's coming next.

Lesson 4 - Nested Data: Lists of Dictionaries

At the end of this lesson, you will be able to:

  • Build a list of dictionaries to represent a table of records.
  • Loop over that list to read, filter, and summarize the data.
  • Recognize this shape as the way real-world data (and JSON) is organized.

In Unit 5 you met two collections that are about to become best friends. A list holds many items in order. A dictionary holds labeled fields - name, rating, and so on. Put them together - a list of dictionaries - and you've got the single most useful data shape in all of programming: a table, where each row is a record and each record knows its own field names.

This isn't an academic exercise. When last lesson's csv.DictReader handed you one dictionary per row, collecting those into a list gives you exactly this. When an app on your phone fetches data from the internet, it almost always arrives in this shape (a format called JSON, which is basically Python lists and dictionaries wearing a slightly different hat). Learn this pattern and an enormous amount of "real" programming suddenly looks familiar.

Building the table

Let's model a few dogs at a shelter. Each dog is a dictionary; the whole roster is a list of them:

dogs = [
    {"name": "Biscuit", "breed": "corgi",    "age": 3, "adopted": False},
    {"name": "Laika",   "breed": "husky",    "age": 5, "adopted": True},
    {"name": "Momo",    "breed": "shiba",    "age": 2, "adopted": False},
    {"name": "Rex",     "breed": "labrador", "age": 7, "adopted": False},
]

Read the shape carefully: the square brackets [ ] make a list, and each thing inside is a dictionary in curly braces { }. Every dog has the same four fields, which is what makes it a tidy table. To visit them all, you loop over the list - and each item you get is a full dictionary you can index into by field name:

def main():
    for dog in dogs:
        print(f"{dog['name']} is a {dog['age']}-year-old {dog['breed']}")

main()

That's the whole core move. for dog in dogs hands you one record at a time; dog["name"] reaches into that record for a field. Everything else in this lesson is a variation on it.

Filtering: finding the records you want

Because each record is right there in the loop, asking a question about your data is just a loop with an if inside. Which dogs still need homes?

def main():
    print("Still looking for a home:")
    for dog in dogs:
        if not dog["adopted"]:
            print(" -", dog["name"])

main()

This is the filtering loop pattern from Unit 5, except now the thing you're testing is a field of a dictionary. Change the condition and you can answer almost anything: dogs older than 4, dogs of a certain breed, dogs whose name starts with "B."

Summarizing: turning records into a number

Filtering picks records; summarizing crunches them down to an answer. Here we combine a counter and an accumulator to report how many dogs are still available and what their average age is:

def main():
    available = 0
    age_total = 0

    for dog in dogs:
        if not dog["adopted"]:
            available += 1
            age_total += dog["age"]

    print(f"{available} dogs are available for adoption.")
    if available > 0:
        print(f"Their average age is {age_total / available:.1f} years.")

main()

Look at how much you're doing with tools you already own: a loop, an if, two accumulators, an f-string. The data got more sophisticated - a table of structured records - but the moves didn't. That's the whole promise of learning the fundamentals well.

Lists of tuples vs. lists of dictionaries. Assignment 3 has you build a "database" as a list of tuples - ("Biscuit", "corgi", 3). A list of dictionaries is the same idea with a readability upgrade: instead of remembering that age is "position 2," you write dog["age"] and it says what it means. Tuples are lighter and great when the fields are obvious; dictionaries win the moment a record has more than a couple of fields or you want the code to read like plain English.

Try it! Build your own list of dictionaries - at least four records - for something you actually care about: albums, video games, houseplants, whatever. Give each record three or four fields. Then write a loop that prints only the records matching some condition you choose (rating above 8, released after 2015, needs watering today...). Print a friendly header first so your output explains itself.

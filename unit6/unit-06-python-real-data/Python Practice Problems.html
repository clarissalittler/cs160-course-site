4. Advance a playlist selection

Complete the function. It should return the next valid index, but stay at the current index when the playlist is empty or already on the last song.

    # YOUR CONDITIONS AND RETURNS HERE
    pass

Check one solution
def next_index(current, songs):
    if len(songs) == 0:
        return current
    if current + 1 >= len(songs):
        return current
    return current + 1

5. Trace two changing lists

available = ["Umbrella", "Chess Set"]
borrowed = []
title = "Umbrella"

if title in available:
    available.remove(title)
    borrowed.append(title)

Draw both lists before and after this block runs. Then: what happens if the block runs a second time without resetting the lists, and why?

Check the reasoning

Before: both items are available and nothing is borrowed. After: only the chess set is available and the umbrella is borrowed. A second run changes nothing, because the umbrella is no longer in available, so the if is false and the body is skipped.

6. Debug a request menu

requests = []
running = True

while running:
    command = input("add, show, or quit? ").strip().lower()
    if command == "add":
        title = input("Song: ").strip()
        requests + [title]
    elif command == "show":
        print(requests)
    elif command == "quit":
        running == False
    else:
        print("Unknown command")

There are two bugs, both to do with updating state. Neither one produces an error message! Find and fix both.

Check one solution
if command == "add":
    title = input("Song: ").strip()
    requests.append(title)
elif command == "quit":
    running = False

requests + [title] builds a new list and then throws it away, since nothing stores it. append changes the list in place. And running == False asks a question instead of assigning, so running stays True forever and there's no way to quit.

7. Count a rule's mistakes

A lender is testing an automatic approval rule on its past loans. In this old data, everyone got a loan, so we know who actually repaid. The rule approves anyone whose score is at or above a cutoff.

applications = [
    {"name": "Avery", "score": 640, "repaid": True},
    {"name": "Bao", "score": 710, "repaid": True},
    {"name": "Cam", "score": 590, "repaid": True},
    {"name": "Dee", "score": 720, "repaid": False},
    {"name": "Eli", "score": 680, "repaid": False},
]

def approve(application, cutoff):
    return application["score"] >= cutoff

Write a function count_mistakes(applications, cutoff) that returns two numbers: how many people who repaid would have been wrongly denied, and how many people who didn't repay would have been wrongly approved. Then print both counts for cutoffs of 600, 650, and 700. Which cutoff would you choose, who gets hurt by each kind of mistake, and is there any cutoff that treats Cam fairly?

Check one solution
def count_mistakes(applications, cutoff):
    wrongly_denied = 0
    wrongly_approved = 0
    for application in applications:
        approved = approve(application, cutoff)
        if not approved and application["repaid"]:
            wrongly_denied += 1
        elif approved and not application["repaid"]:
            wrongly_approved += 1
    return wrongly_denied, wrongly_approved

for cutoff in [600, 650, 700]:
    denied, approved = count_mistakes(applications, cutoff)
    print(f"Cutoff {cutoff}: wrongly denied {denied}, wrongly approved {approved}")
Cutoff 600: wrongly denied 1, wrongly approved 2
Cutoff 650: wrongly denied 2, wrongly approved 2
Cutoff 700: wrongly denied 2, wrongly approved 1

This is the four-outcomes idea from Lesson 6 with only the two mistake counters kept. Notice that 650 is worse than 600 in one way and no better in the other. A wrongly denied person loses a loan they would have repaid; a wrongly approved one may end up in debt they can't manage, and the lender loses money. Cam repaid with a score of 590, so every cutoff here denies Cam. The rule can't see whatever it was about Cam that the score missed.

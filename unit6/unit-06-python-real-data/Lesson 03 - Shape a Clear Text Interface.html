Lesson 3 - Shape a Clear Text Interface

By the end of this lesson, you will be able to:

  • Create multi-line output with triple-quoted strings.
  • Insert changing values into a multi-line f-string.
  • Turn a collection of words into readable text with join.
  • Design a small command vocabulary that is visible, consistent, and keyboard-friendly.

Three quotes make room for multiple lines

A string wrapped in three quotation marks can run across several lines. This is handy whenever the arrangement of the lines is part of the message:

announcement = """
COMMUNITY RADIO 91.7 FM
Tonight at 8: Songs for a Rainy Bus Ride
Requests open after the weather report.
"""

print(announcement)

Triple-quoted strings are ordinary strings; they just get to contain line breaks. They can hold instructions, a recipe card, dialogue, a poem, a status panel, a title screen, whatever you like.

Multi-line f-strings can display changing data

event = {
    "title": "Repair Café",
    "when": "Saturday, 10:00–2:00",
    "where": "Community Center Studio",
    "tags": ["repair", "tools", "all ages"],
    "cost": 0,
}

tag_words = ", ".join(event["tags"])

card = f"""
+--------------------------------------+
EVENT: {event["title"]}
WHEN:  {event["when"]}
WHERE: {event["where"]}
TAGS:  {tag_words}
COST:  ${event["cost"]}
+--------------------------------------+
"""

print(card)

The fixed labels and the border come from the f-string. The details come from the event dictionary. Hand it a different dictionary and the same display works again.

join turns several words into one string

access_features = ["step-free entrance", "captions", "quiet room"]
print("ACCESS: " + "; ".join(access_features))

This puts a semicolon and a space between each pair of neighbors. It reads a little backwards, since the separator is the thing you call the method on and the list is the argument, and it confuses nearly everyone the first time. I still have to think about it. join doesn't change the list; it makes one new string for display.

Put repeated presentation in a function

def show_event(event):
    tag_words = ", ".join(event["tags"])

    if event["cost"] == 0:
        cost_words = "free"
    else:
        cost_words = f'${event["cost"]}'

    print(f"""
EVENT: {event["title"]}
WHEN: {event["when"]}
WHERE: {event["where"]}
TAGS: {tag_words}
COST: {cost_words}
""")

This function's job is presentation. It reads the event record but never edits the title, tags, or cost. A resource directory, a recipe collection, a character roster, or a travel guide could all keep the same wall between data and display.

A command vocabulary is an agreement

An interactive text program understands exactly the comparisons its author wrote and nothing else. So let's make the vocabulary visible:

def show_help():
    print("Commands: next, previous, details, save, help, quit")

command = input("Choose a command: ").strip().lower()

.strip().lower() makes capitalization and stray spaces harmless. It doesn't make the computer understand English. If the program checks for next, then show me another one is still just a different string, unless you decide to support it.

Clarity matters more than decoration

Borders and text art can be fun, but a row of forty dashes is tedious through a screen reader and wraps badly on a phone. Use explicit labels like EVENT, WHEN, and COST. Don't signal status only through color, emoji, spacing, or capitalization. If someone copies the output as plain text, it should still make sense.

Interface studio. Choose an event card, transit display, recipe card, playlist panel, character sheet, room card, or another small display. Then:

  1. Create one triple-quoted heading or instruction block.
  2. Store the changing details in a dictionary.
  3. Use a multi-line f-string to display the dictionary with labels.
  4. Use join to display one list.
  5. Ask another person to identify the important facts and available actions without explanation.

Lesson 2 - CSV, Types, and Provenance

Once you've worked through this lesson, you'll be able to:

  • Identify headers, rows, columns, records, and fields in a CSV file.
  • Read CSV rows as dictionaries and explicitly convert numeric fields.
  • Record missing or malformed values instead of silently treating them as valid.
  • Document a dataset's source, date, units, collection method, and license.

A CSV file is a serialized table

name,area,cost
Tool Library,North,0
Repair Cafe,Central,0
Bike Skills Workshop,East,10

CSV stands for comma-separated values. The first row is a header that names the columns. Every row after that is a record, and each position within a row is a field. What happens when a value contains a comma of its own? It has to be quoted—which is exactly the kind of fiddly detail that makes Python's csv module a better idea than splitting every line yourself.

Read rows as dictionaries

import csv

resources = []

with open("resources.csv", "r", encoding="utf-8", newline="") as data_file:
    reader = csv.DictReader(data_file)
    for row in reader:
        resources.append(row)

print(resources[0])

DictReader uses the header cells as dictionary keys, so the first row comes back as something like {"name": "Tool Library", "area": "North", "cost": "0"}.

File values arrive as text

Look closely at that cost: it's the string "0", not the number 0. Everything in a CSV arrives as text, no matter how numeric it looks. Convert fields according to the data dictionary:

clean_resources = []

with open("resources.csv", "r", encoding="utf-8", newline="") as data_file:
    reader = csv.DictReader(data_file)
    for row in reader:
        clean_record = {
            "name": row["name"].strip(),
            "area": row["area"].strip(),
            "cost": float(row["cost"]),
        }
        clean_resources.append(clean_record)

Now the records in memory have the types we meant them to have. Converting once, while loading, beats trying to remember to convert during every later calculation—future-you will be grateful.

Real tables contain imperfect values

name,area,cost
Tool Library,North,free
,Central,0
Bike Skills Workshop,east side,10 dollars
Repair Cafe,E,

Before writing a single line of cleanup code, make a data-quality log:

RowIssuePossible action
1free is not numericconfirm that it means 0; don't guess silently
2missing namereject or label as unknown, depending on purpose
3inconsistent area and unit text in coststandardize with documented rules
4abbreviated area and missing costverify source; preserve missingness

One modest validation approach: record the problem, skip the row, move on.

problems = []
clean_resources = []

with open("resources.csv", "r", encoding="utf-8", newline="") as data_file:
    reader = csv.DictReader(data_file)
    for row_number, row in enumerate(reader, start=2):
        try:
            cost = float(row["cost"])
        except ValueError:
            problems.append(f"Row {row_number}: cost is not numeric")
            continue

        if row["name"].strip() == "":
            problems.append(f"Row {row_number}: name is missing")
            continue

        clean_resources.append({
            "name": row["name"].strip(),
            "area": row["area"].strip(),
            "cost": cost,
        })

This program doesn't make the data “fully clean”—nothing does. It implements two documented checks, and only those. But reporting the rows it skipped is the honest part: far better than quietly producing a confident summary built on omissions nobody knows about.

Write dictionaries back to CSV

field_names = ["name", "area", "cost"]

with open("clean_resources.csv", "w", encoding="utf-8", newline="") as data_file:
    writer = csv.DictWriter(data_file, fieldnames=field_names)
    writer.writeheader()
    writer.writerows(clean_resources)

DictWriter uses the field list to decide the column names and their order. Write your cleaned data to a new file so the original evidence stays available—you can't re-examine what you've overwritten.

Provenance answers “where did this come from?”

A dataset should never travel alone. It needs a source note answering questions like:

  • Who created or published it?
  • When was it collected and last updated?
  • How were records selected or measured?
  • What units and definitions are used?
  • What license or permission governs reuse?
  • What populations or cases may be missing?

A CSV isn't trustworthy merely because it opens without complaint. Provenance is what lets a reader judge whether the data is current—and whether it's even the right data for the question being asked.

Security connection: One slightly alarming detail: spreadsheet programs may interpret cells beginning with characters such as = as formulas. A CSV built from untrusted input can therefore do things—not just display text—when opened in a spreadsheet. For this course: don't open unknown CSV files casually, preserve original data, and treat exported text as untrusted.

CSV audit. Create or inspect a five-row CSV. Provide:

  1. a four-field data dictionary,
  2. a provenance note,
  3. a log of at least three possible quality checks,
  4. code that loads rows with DictReader and converts one numeric field,
  5. a report stating loaded, skipped, and total row counts, and
  6. a cleaned copy written without overwriting the source.

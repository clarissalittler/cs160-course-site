Lesson 2 - CSV, Types, and Provenance

At the end of this lesson, you will be able to:

  • Identify headers, rows, columns, records, and fields in a CSV file.
  • Read CSV rows as dictionaries and explicitly convert numeric fields.
  • Record missing or malformed values instead of silently treating them as valid.
  • Document a dataset's source, date, units, collection method, and license.

A CSV file is a serialized table

name,area,cost
Tool Library,North,0
Repair Cafe,Central,0
Bike Skills Workshop,East,10

CSV means comma-separated values. The first row is a header naming the columns. Each later row is a record, and each position in a row is a field. Commas inside a value require quoting, which is one reason to use Python's csv module instead of splitting every line yourself.

Read rows as dictionaries

import csv

resources = []

with open("resources.csv", "r", encoding="utf-8", newline="") as data_file:
    reader = csv.DictReader(data_file)
    for row in reader:
        resources.append(row)

print(resources[0])

DictReader uses the header cells as dictionary keys. The first row becomes something like {"name": "Tool Library", "area": "North", "cost": "0"}.

File values arrive as text

The cost is the string "0", not the number 0. Convert fields according to the data dictionary:

clean_resources = []

with open("resources.csv", "r", encoding="utf-8", newline="") as data_file:
    reader = csv.DictReader(data_file)
    for row in reader:
        clean_record = {
            "name": row["name"].strip(),
            "area": row["area"].strip(),
            "cost": float(row["cost"]),
        }
        clean_resources.append(clean_record)

Now the in-memory records match the intended types. Converting once while loading is usually clearer than remembering to convert during every later calculation.

Real tables contain imperfect values

name,area,cost
Tool Library,North,free
,Central,0
Bike Skills Workshop,east side,10 dollars
Repair Cafe,E,

Before coding, make a data-quality log:

RowIssuePossible action
1free is not numericconfirm that it means 0; do not guess silently
2missing namereject or label as unknown, depending on purpose
3inconsistent area and unit text in coststandardize with documented rules
4abbreviated area and missing costverify source; preserve missingness

One small validation approach records the problem and skips the row:

problems = []
clean_resources = []

with open("resources.csv", "r", encoding="utf-8", newline="") as data_file:
    reader = csv.DictReader(data_file)
    for row_number, row in enumerate(reader, start=2):
        try:
            cost = float(row["cost"])
        except ValueError:
            problems.append(f"Row {row_number}: cost is not numeric")
            continue

        if row["name"].strip() == "":
            problems.append(f"Row {row_number}: name is missing")
            continue

        clean_resources.append({
            "name": row["name"].strip(),
            "area": row["area"].strip(),
            "cost": cost,
        })

This program is not “fully clean.” It implements two documented checks. Reporting skipped rows is better than quietly producing a confident summary from unknown omissions.

Write dictionaries back to CSV

field_names = ["name", "area", "cost"]

with open("clean_resources.csv", "w", encoding="utf-8", newline="") as data_file:
    writer = csv.DictWriter(data_file, fieldnames=field_names)
    writer.writeheader()
    writer.writerows(clean_resources)

DictWriter uses the field list to determine column names and order. Write to a new file while cleaning so the original evidence remains available.

Provenance answers “where did this come from?”

A dataset should travel with a source note:

  • Who created or published it?
  • When was it collected and last updated?
  • How were records selected or measured?
  • What units and definitions are used?
  • What license or permission governs reuse?
  • What populations or cases may be missing?

A CSV is not trustworthy merely because it opens. Provenance lets a reader judge whether it is current and fit for a particular question.

Security connection: Spreadsheet programs may interpret cells beginning with characters such as = as formulas. A CSV created from untrusted input can therefore do more than display text when opened in a spreadsheet. For this course, do not open unknown CSV files casually, preserve original data, and treat exported text as untrusted.

CSV audit. Create or inspect a five-row CSV. Provide:

  1. a four-field data dictionary,
  2. a provenance note,
  3. a log of at least three possible quality checks,
  4. code that loads rows with DictReader and converts one numeric field,
  5. a report stating loaded, skipped, and total row counts, and
  6. a cleaned copy written without overwriting the source.

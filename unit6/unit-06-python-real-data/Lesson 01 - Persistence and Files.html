Lesson 1 - Persistence and Files

At the end of this lesson, you will be able to:

  • Explain the difference between in-memory state and persistent data.
  • Read and write a UTF-8 text file with a context manager.
  • Predict how read, write, and append modes affect an existing file.
  • Handle a missing file as an expected first-run condition.

Memory disappears; a file can remain

The list in a Unit 5 catalog lives in the running Python process. When that process ends, its variables disappear. Persistent data is stored somewhere intended to outlive one run: a file, a database, or a remote service.

Persistence changes the program's story. The first run may have no saved data. A later run may load old data created by a different version of the program. Files may be moved, malformed, unreadable, or shared with someone who interprets them differently.

Write a text file

notes = ["check bus schedule", "bring headphones", "pack a snack"]

with open("trip_notes.txt", "w", encoding="utf-8") as output_file:
    for note in notes:
        output_file.write(note + "\n")

print("Saved trip_notes.txt")

open() returns a file object. The with statement creates a context manager: when the indented block ends, Python closes the file even if a problem occurs. The name output_file exists so the code can write to that open file.

Mode "w" means write from the beginning. If the file exists, its old contents are replaced. If it does not exist, Python creates it. "\n" is a newline character; without it, every note would run together on one line.

Read a text file

loaded_notes = []

with open("trip_notes.txt", "r", encoding="utf-8") as input_file:
    for line in input_file:
        loaded_notes.append(line.rstrip("\n"))

print(loaded_notes)

Mode "r" means read. Looping over a file produces one line at a time, usually including its final newline. .rstrip("\n") removes that specific newline. A general .strip() would also remove intentional leading and trailing spaces, which may or may not be wanted.

Append adds without replacing

with open("trip_notes.txt", "a", encoding="utf-8") as output_file:
    output_file.write("charge phone\n")

Mode "a" appends at the end. Predict the contents after these runs:

  1. Run the original "w" program once.
  2. Run the append program twice.
  3. Run the original "w" program again.

The final write-mode run erases both appended copies. Mode is a consequential choice, so use variable names and confirmation messages that make the operation clear.

Paths describe where a file lives

"trip_notes.txt" is a relative path. It refers to a file in the program's current working directory. Browser-based notebooks and online interpreters often provide temporary storage whose location or lifetime differs from a local computer. Print or inspect the file list in your environment, and download any artifact you need to keep.

A path such as "data/trip_notes.txt" refers to a file inside a data folder. A path that works on one computer may fail on another if it contains a private username, drive letter, or folder that does not exist. Relative project paths are usually easier to share.

A missing file can be a normal state

def load_notes(filename):
    notes = []

    try:
        with open(filename, "r", encoding="utf-8") as input_file:
            for line in input_file:
                notes.append(line.rstrip("\n"))
    except FileNotFoundError:
        print(f"No saved file named {filename}; starting with an empty list.")

    return notes

notes = load_notes("trip_notes.txt")
print(f"Loaded {len(notes)} notes.")

try runs code that may fail. except FileNotFoundError handles only the named failure. It does not conceal every possible bug. On a first run, an empty list is a reasonable result and the message explains what happened.

Encoding and line endings are agreements

Text must be translated between characters and bytes. Naming encoding="utf-8" makes that agreement explicit and supports a wide range of writing systems. Operating systems also have different line-ending conventions; Python's text mode normally translates them. Explicit encoding and ordinary newline handling make shared projects more predictable.

Persistence creates responsibility

A value in memory may vanish in seconds. A saved file can be copied, backed up, emailed, or opened years later. Before saving, ask whether the data is necessary, whether a shared machine exposes it, what the filename reveals, and how it can be deleted. “The program remembers” is useful only when people understand what is remembered and control it.

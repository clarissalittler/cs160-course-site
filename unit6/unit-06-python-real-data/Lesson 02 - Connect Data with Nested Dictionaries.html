Lesson 2 - Connect Data with Nested Dictionaries

By the end of this lesson, you will be able to:

  • Read values from a dictionary inside another dictionary.
  • Represent several related things with a consistent structure.
  • Represent connections as keys and values.
  • Use in and .get() when a key may be absent.

Several records can live under one set of keys

A community-center guide needs to describe several spaces. We could make a separate variable for each one, but then nothing connects them, and "which room is east of the lobby?" has no place to live. Instead, let's use an outer dictionary that maps short identifiers to records that all have the same shape:

SPACES = {
    "lobby": {
        "name": "Main Lobby",
        "description": "Information desk, water fountain, and front entrance.",
        "connections": {"east": "studio", "south": "courtyard"},
        "feature": "information desk",
        "open": True,
    },
    "studio": {
        "name": "Art Studio",
        "description": "Tables, sinks, drying racks, and north-facing windows.",
        "connections": {"west": "lobby"},
        "feature": "community mural",
        "open": True,
    },
    "courtyard": {
        "name": "Courtyard",
        "description": "Benches circle a small rain garden.",
        "connections": {"north": "lobby"},
        "feature": "rain garden",
        "open": False,
        "note": "Closed during icy weather",
    },
}

The outer keys name the spaces. Each value is a dictionary with the same core fields. This same shape could describe transit stops, screens in a website, scenes in a story, departments in a store, or stages in a process: anything where you have several things of one kind that refer to each other.

Read from the outside in

print(SPACES["lobby"])
print(SPACES["lobby"]["name"])
print(SPACES["lobby"]["connections"])
print(SPACES["lobby"]["connections"]["east"])

Read the last one left to right: get the lobby record, then its connections dictionary, then whatever is stored under "east". The answer is studio, which is itself a key in SPACES. So we could look that up too, and keep going.

A relationship can be data

The connections dictionary works like a little map, but the idea is bigger than physical space. A lesson could point to the next lesson; a menu choice could point to a screen; a transit stop could point to the next stop down the line.

current_space = "lobby"
direction = "east"
connections = SPACES[current_space]["connections"]

if direction in connections:
    current_space = connections[direction]
    print("Now viewing:", SPACES[current_space]["name"])
else:
    print("That connection is not available.")

Notice what's not in this code: there's no special rule about the lobby's east side. The code asks the current record what "east" means and follows the answer. The data holds the details that vary, and the same few lines follow any connection in any map. That's the trick, and it's why this data shape shows up so often. Once you've seen it you'll find it everywhere!

Required and optional facts

Every space has a name, description, connections, feature, and open status. Only the courtyard has a note. Square brackets are right when the key has to be there, because if it isn't, you want to find out with a loud KeyError rather than a quiet wrong answer. .get() is right when absence is ordinary and means something:

space = SPACES["courtyard"]

print(space["name"])
print(space.get("note", "No special note"))

ordinary_space = SPACES["studio"]
print(ordinary_space.get("note", "No special note"))

The second argument to .get() is what comes back when the key is missing. It doesn't add the key to the dictionary.

Consistent identifiers prevent late failures

"Studio", "studio", and "art_studio" are three different keys. If a connection names an identifier that doesn't exist, nothing complains when you write it. The program only fails when someone actually walks that way, which could be weeks later and in somebody else's hands. So keep internal keys short, lowercase, and consistent, and let the display names be as expressive as you like.

Nested data is not only for maps

PODCASTS = {
    "city_limits": {
        "title": "City Limits",
        "topics": ["housing", "transportation"],
        "episodes": 18,
    },
    "small_signals": {
        "title": "Small Signals",
        "topics": ["music", "technology"],
        "episodes": 7,
    },
}

print(PODCASTS["small_signals"]["topics"][0])

Here the outer dictionary maps show identifiers to records, and inside each record a list holds several topics. Nesting lets the shape of the data match the shape of the subject.

Connection studio. Model three related things: community spaces, transit stops, screens, scenes, menu categories, media collections, or another set. Then:

  1. Give every record the same three or four required fields.
  2. Include one list or inner dictionary.
  3. Retrieve three facts using nested lookups.
  4. Use .get() for one truly optional fact.
  5. Check that every connection or identifier points to something that exists.

Lesson 2 - Connect Data with Nested Dictionaries

By the end of this lesson, you will be able to:

  • Read values from a dictionary inside another dictionary.
  • Represent several related things with a consistent structure.
  • Represent connections as keys and values.
  • Use in and .get() when a key may be absent.

Several records can live under one set of keys

A community-center guide needs to describe several spaces. Instead of creating unrelated variables for each one, an outer dictionary can connect short identifiers to consistently shaped records:

SPACES = {
    "lobby": {
        "name": "Main Lobby",
        "description": "Information desk, water fountain, and front entrance.",
        "connections": {"east": "studio", "south": "courtyard"},
        "feature": "information desk",
        "open": True,
    },
    "studio": {
        "name": "Art Studio",
        "description": "Tables, sinks, drying racks, and north-facing windows.",
        "connections": {"west": "lobby"},
        "feature": "community mural",
        "open": True,
    },
    "courtyard": {
        "name": "Courtyard",
        "description": "Benches circle a small rain garden.",
        "connections": {"north": "lobby"},
        "feature": "rain garden",
        "open": False,
        "note": "Closed during icy weather",
    },
}

The outer keys identify spaces. Their values are dictionaries containing the same core fields. This shape could also represent transit stops, website screens, scenes in a story, departments in a store, or stages in a process.

Read from the outside in

print(SPACES["lobby"])
print(SPACES["lobby"]["name"])
print(SPACES["lobby"]["connections"])
print(SPACES["lobby"]["connections"]["east"])

Read the last expression from left to right: get the lobby record, then its connections dictionary, then the destination stored under east. The result is studio, another key in SPACES.

A relationship can be data

The connections dictionary acts like a small map, but the same pattern is broader than physical movement. A lesson key might point to the next lesson; a menu choice might point to a screen; a transit stop might point to the next stop.

current_space = "lobby"
direction = "east"
connections = SPACES[current_space]["connections"]

if direction in connections:
    current_space = connections[direction]
    print("Now viewing:", SPACES[current_space]["name"])
else:
    print("That connection is not available.")

The code does not contain a special east-lobby rule. It asks the current record what east means. Data supplies the changing details; the same code follows any connection.

Required and optional facts

Every space has a name, description, connections, feature, and open status. Only the courtyard needs a special note. Square brackets are useful when a key must exist. .get() is useful when absence has an ordinary meaning:

space = SPACES["courtyard"]

print(space["name"])
print(space.get("note", "No special note"))

ordinary_space = SPACES["studio"]
print(ordinary_space.get("note", "No special note"))

The second argument to .get() is the fallback returned when the key is absent. It does not add that key to the dictionary.

Consistent identifiers prevent late failures

"Studio", "studio", and "art_studio" are different keys. If a connection names an identifier that does not exist, the program may fail only when someone follows that path. Keep internal keys short and consistent, even when the public display names are expressive.

Nested data is not only for maps

PODCASTS = {
    "city_limits": {
        "title": "City Limits",
        "topics": ["housing", "transportation"],
        "episodes": 18,
    },
    "small_signals": {
        "title": "Small Signals",
        "topics": ["music", "technology"],
        "episodes": 7,
    },
}

print(PODCASTS["small_signals"]["topics"][0])

Here the outer dictionary connects show identifiers to records, and a list inside each record holds several topics. Nesting lets a representation match the relationships in the subject.

Connection studio. Model three related things: community spaces, transit stops, screens, scenes, menu categories, media collections, or another set. Then:

  1. Give every record the same three or four required fields.
  2. Include one list or inner dictionary.
  3. Retrieve three facts using nested lookups.
  4. Use .get() for one genuinely optional fact.
  5. Check that every connection or identifier points to something that exists.

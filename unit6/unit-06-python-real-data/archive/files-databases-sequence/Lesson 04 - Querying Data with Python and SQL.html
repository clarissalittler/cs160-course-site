Lesson 4 - Querying Data with Python and SQL

By the time you finish this lesson, you'll be able to:

  • Describe database tables, rows, columns, and keys.
  • Translate a plain-language data question into a filter, field selection, sort, or aggregate.
  • Match a simple Python collection-processing loop with an equivalent SQL query.
  • Read basic SELECT, FROM, WHERE, ORDER BY, COUNT, and AVG clauses.

A query states what answer you want

Suppose our resource dataset has a name, area, category, and cost for every record. There's plenty we might want to know:

  • Which free resources serve the North area?
  • What are their names and categories?
  • How many resources are in each area?
  • What is the average listed cost?

A query is a structured request for data. It might pick out records, pick out fields, sort the results, or boil many values down into one summary.

Query a list of dictionaries in Python

resources = [
    {"name": "Tool Library", "area": "North", "category": "tools", "cost": 0.0},
    {"name": "Repair Cafe", "area": "Central", "category": "repair", "cost": 0.0},
    {"name": "Bike Workshop", "area": "North", "category": "transport", "cost": 10.0},
]

matches = []
for resource in resources:
    if resource["area"] == "North" and resource["cost"] == 0:
        matches.append(resource)

for resource in matches:
    print(resource["name"], "—", resource["category"])

This little query has three conceptual parts:

  1. Select rows: keep North-area records whose cost is 0.
  2. Select fields: display only name and category.
  3. Present results: label or format them for a person.

The same question in SQL

SELECT name, category
FROM resources
WHERE area = 'North' AND cost = 0;

SQL—pronounced “sequel” or “S-Q-L,” depending on who you ask (I won't pick a side)—is a language for working with relational databases. You can read the query almost like a sentence: select the name and category columns from the resources table, for rows where area is North and cost is 0.

SQL is declarative: it describes the result you want and stays out of the step-by-step details. The database system decides how to find the matching rows. Our Python loop is more procedural—it spells out exactly how to visit, test, append, and display.

Tables, rows, columns, and keys

A relational database stores data in tables:

  • A row is one record.
  • A column is one named field with an expected kind of value.
  • A primary key uniquely identifies a row, such as resource_id.
  • A foreign key can connect a row to another table.

A database is not merely a CSV that grew up. It can enforce constraints, update selected records in place, coordinate many users at once, create indexes for faster lookup, control who can access what, and relate several tables to each other without copying every value into one giant file.

Sort and summarize

SELECT name, cost
FROM resources
ORDER BY cost DESC;

DESC sorts from high to low; ASC sorts low to high and is often the default.

SELECT COUNT(*) AS resource_count,
       AVG(cost) AS average_cost
FROM resources;

COUNT(*) counts the selected rows. AVG(cost) computes a mean over the non-missing values in that column. AS just gives the result a readable label.

Every summary still needs a human to interpret it. Which costs are missing? Does 0 mean free, or unknown? Does one record really equal one opportunity? SQL makes a calculation concise—it doesn't make it meaningful.

Run a tiny database with Python's Standard Library

The sqlite3 module lets Python run a real—if lightweight—relational database. This example keeps the database in memory so it leaves no file behind:

import sqlite3

connection = sqlite3.connect(":memory:")
cursor = connection.cursor()

cursor.execute("""
    CREATE TABLE resources (
        resource_id INTEGER PRIMARY KEY,
        name TEXT,
        area TEXT,
        category TEXT,
        cost REAL
    )
""")

rows = [
    ("Tool Library", "North", "tools", 0.0),
    ("Repair Cafe", "Central", "repair", 0.0),
    ("Bike Workshop", "North", "transport", 10.0),
]

cursor.executemany(
    "INSERT INTO resources (name, area, category, cost) VALUES (?, ?, ?, ?)",
    rows,
)

query = "SELECT name, category FROM resources WHERE area = ? AND cost = ?"
for name, category in cursor.execute(query, ("North", 0.0)):
    print(name, "—", category)

connection.close()

Those question marks are parameter placeholders: the values are supplied separately rather than pasted into the SQL text. That keeps a stray quote in the data from breaking the query, and it's the basic defense against SQL injection. Never build a query by gluing untrusted user input directly into the string.

This is a taste, not a second language exam

Nobody expects you to design a production database this week. The goal is to recognize that selecting, filtering, sorting, and summarizing are general data operations. Python loops express them one way; SQL expresses them in the language many information systems speak natively.

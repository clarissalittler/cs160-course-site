Lesson 1 - Reading and Writing Files

At the end of this lesson, you will be able to:

  • Explain why programs use files to store data that outlives a single run.
  • Open a file and read its contents - all at once, or one line at a time.
  • Write data out to a file, and understand the difference between overwriting and appending.

Here's something you may not have noticed yet: every program you've written so far has amnesia. You type in some numbers, it does its thing, prints an answer - and the moment it ends, everything is gone. Run it again and it remembers nothing. That's fine for a calculator, but it's useless for anything that needs to keep something: a to-do list, a save file, a spreadsheet of grades, a log of what happened.

The fix is files. A file lives on the disk, not in your program's memory, so it sticks around after the program stops. This unit is all about working with real data, and real data almost always lives in a file. So that's where we start.

Reading a file

Say you have a plain text file called friends.txt sitting next to your program, with one name per line:

Dahlia
Amit
Rosa
Kenji

To get at it from Python, you open the file, do something with it, and close it when you're done. The cleanest way to do all of that is a with block, which closes the file for you automatically the moment you're finished:

def main():
    # "r" means we're opening the file to READ it
    with open("friends.txt", "r") as my_file:
        contents = my_file.read()   # read the WHOLE file into one string
    print(contents)

main()

That with open(...) as my_file: line reads as "open friends.txt for reading, and while I work with it, call it my_file." Everything indented underneath runs while the file is open; as soon as the block ends, Python quietly closes the file. You don't have to remember to close it yourself - which is exactly the kind of small chore computers should handle for you.

One line at a time

.read() hands you the entire file as a single string, which is handy but clumsy if you actually want to work with each name. Much more common - and this is where the last two units pay off - is to loop over the file. A file object is a sequence you can for-loop over, and each time around you get one line:

def main():
    with open("friends.txt", "r") as my_file:
        for line in my_file:
            print("Hi there,", line.strip())

main()

Notice the .strip() - one of the string methods from Unit 5. Each line you read in still has its invisible newline character (\n) hanging off the end, the one that moved the cursor to the next line in the original file. .strip() trims that off (along with any stray spaces), so your output doesn't come out double-spaced. Forgetting .strip() is probably the number-one "why does my file output look weird?" bug, so tuck it away now.

Where does the file live? When you write open("friends.txt"), Python looks for that file in the same folder your program is running from. If the file is somewhere else you'd need to give a fuller path. For everything in this unit, keep your .py file and your data file in the same folder and you'll avoid a world of "file not found" headaches.

Writing to a file

Reading is only half the story. To save data, you open a file for writing with "w" and use .write():

def main():
    with open("shopping.txt", "w") as my_file:
        my_file.write("coffee\n")
        my_file.write("dog treats\n")
        my_file.write("hot sauce\n")
    print("Saved your shopping list!")

main()

A couple of things to know. First, .write() does not add a newline for you the way print() does - if you want each item on its own line, you have to include the \n yourself. Second, and this one bites people: opening a file with "w" erases whatever was already in it and starts fresh. If shopping.txt already had your whole week's list, poof, it's gone.

When you'd rather add to the end of a file instead of clobbering it, open it with "a" for append:

with open("shopping.txt", "a") as my_file:
    my_file.write("more coffee\n")   # tacked onto the end; nothing is erased

Putting it together

Reading and writing really shine together. Here's a tiny program that reads a file of test scores (one number per line), and writes out a report - keeping a running total with the accumulator pattern from Unit 5 as it goes:

def main():
    total = 0
    count = 0

    # Read the scores in
    with open("scores.txt", "r") as scores_file:
        for line in scores_file:
            total += float(line)   # each line is one number
            count += 1

    average = total / count

    # Write a little report out
    with open("report.txt", "w") as report_file:
        report_file.write(f"Number of scores: {count}\n")
        report_file.write(f"Average score: {average:.1f}\n")

    print("Report saved to report.txt")

main()

See how naturally the pieces snap together? A loop, the accumulator pattern, an f-string, and files - each one something you already knew, combined into something genuinely useful.

For a bonus, have it also print how many quotes there were in total.

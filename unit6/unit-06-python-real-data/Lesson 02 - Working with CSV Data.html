Lesson 2 - Working with CSV Data

At the end of this lesson, you will be able to:

  • Explain what a CSV file is and why it's everywhere.
  • Read a CSV file into your program with the csv module.
  • Use csv.DictReader to treat each row as a dictionary and pull out the columns you care about.

Last lesson your files had one value per line. That's fine for a shopping list, but the data you actually run into in the world - a class roster, a budget, weather readings, every spreadsheet ever - is a table: rows and columns, each row a record, each column a field. The most common way to store a table as a plain text file is CSV, which stands for comma-separated values. It's exactly what it sounds like.

What a CSV actually is

Here's a little file, foodcarts.csv, holding a few Portland food carts. The first line is the header - it names the columns - and every line after it is one cart:

name,cuisine,rating
Nong's Khao Man Gai,Thai,4.8
Matt's BBQ,Barbecue,4.7
Bing Mi,Chinese,4.6
Kim Jong Smokehouse,Korean,4.5

That's the whole format. No secret sauce - just values with commas between them. If you opened this exact file in Excel or Google Sheets it would show up as a tidy four-row table, because that's what those programs do with a .csv. Which is the point: CSV is the common language that lets a spreadsheet, a database, and your Python program all pass the same data around.

You could parse this yourself... With the tools from Unit 5, you almost could: read each line, call .split(",") to break it at the commas, and there are your columns. That works until a value contains a comma (imagine a cart named "Bao, Bun & Beyond") and your naive split cuts it in the wrong place. Handling all those edge cases is a solved problem, so we don't reinvent it - we borrow Python's csv module instead.

Reading a CSV, the easy way

Python's Standard Library includes a csv module built exactly for this. The friendliest tool in it is csv.DictReader, which reads each row and hands it to you as a dictionary - those key-value pairs from Unit 5 - using the header row for the keys. So instead of remembering that the rating is "the third column," you just ask for row["rating"]. Watch:

import csv

def main():
    with open("foodcarts.csv", "r") as data_file:
        reader = csv.DictReader(data_file)
        for row in reader:
            # each 'row' is a dictionary like
            # {"name": "Matt's BBQ", "cuisine": "Barbecue", "rating": "4.7"}
            print(row["name"], "-", row["cuisine"])

main()

Run that and you get each cart's name and cuisine. Two things worth noticing. First, we import csv at the top - it's a module, and in the very next lesson we'll pull back the curtain on where modules like this come from (and meet another handy one, random). Second, that for row in reader: loop is the same looping-over-a-collection move you've done a dozen times now; the only new thing is that each item happens to be a whole dictionary.

The one gotcha: everything comes in as text

There's a catch that trips up absolutely everyone, so let's meet it head-on. When you read from a file, every value arrives as a string - even the numbers. That 4.7 in the rating column? Python hands it to you as the text "4.7", not the number 4.7. If you try to do math on it directly, you'll either get an error or a very weird answer (remember, "4" + "4" is "44", not 8). So whenever you need to calculate with a column, convert it first with float() or int():

import csv

def main():
    total = 0
    count = 0

    with open("foodcarts.csv", "r") as data_file:
        reader = csv.DictReader(data_file)
        for row in reader:
            rating = float(row["rating"])   # text -> number, every time
            total += rating
            count += 1

    print(f"Average rating across {count} carts: {total / count:.2f}")

main()

And there it is - the accumulator pattern again, now walking through a real dataset and computing an actual statistic. Read a CSV, convert the column you care about, add it up, divide. That handful of moves is the beating heart of an enormous amount of real data work.

Try it! Using the same foodcarts.csv, write a program that finds and prints the name of the highest-rated cart. (Hint: it's the "track the best so far" pattern - keep a best_name and best_rating as you loop, and update them whenever you see a bigger rating. Don't forget to float() the rating before comparing!)

Show Solution 
import csv

def main():
    best_name = ""
    best_rating = -1

    with open("foodcarts.csv", "r") as data_file:
        reader = csv.DictReader(data_file)
        for row in reader:
            rating = float(row["rating"])
            if rating > best_rating:
                best_rating = rating
                best_name = row["name"]

    print(f"Highest rated: {best_name} ({best_rating})")

main()

Who's in the data - and who isn't? A dataset can feel like plain, neutral fact, but every table started as a series of human choices: what to measure, what to leave out, who got counted. A "top food carts" file reflects whoever wrote reviews - which skews toward people with the time, money, and phones to post them. As you start analyzing data, keep asking our three questions: who benefits from this data, who's missing from it, and who decided what a row even looks like? A confident-looking number can still be telling a lopsided story.

Lesson 3 - Libraries, Documentation, and Dependencies

At the end of this lesson, you will be able to:

  • Distinguish a module, package, Standard Library component, and third-party dependency.
  • Import and use a small Standard Library function.
  • Read a function signature, short description, parameters, and return-value documentation.
  • Identify source, version, maintenance, license, privacy, and trust questions raised by a dependency.

Most software is assembled, not written from nothing

You did not write print(), csv.DictReader, or Python's file system. Software development depends on layers of existing code. A module is an importable Python file or component. A package organizes modules. A library is a broader collection of reusable code; people use the term less formally.

The Python Standard Library is distributed with Python. Modules such as csv, random, statistics, pathlib, and sqlite3 normally require no separate installation.

Import a module and qualify its names

import statistics

wait_times = [12, 18, 9, 25, 16]
print(statistics.mean(wait_times))
print(statistics.median(wait_times))

statistics.mean identifies both the module and function. That qualification helps a reader see where the operation came from.

You may also see:

from statistics import mean
print(mean(wait_times))

This is shorter, but the source is less visible at each call. Avoid from statistics import *; importing every public name makes collisions and provenance harder to understand.

Documentation is part of the interface

A simplified function signature might look like:

statistics.mean(data)

Read documentation for four questions:

  1. What job does the function promise? Calculate the arithmetic mean.
  2. What arguments does it expect? An iterable of numerical values.
  3. What does it return? One numerical mean.
  4. What exceptions or limits matter? An empty dataset raises an error; mixed or unsupported types may not make sense.

A copied example is evidence of one possible call, not a complete specification. Change its values, test an empty collection, and connect each argument to the written signature.

Use a library without surrendering the concept

statistics.mean(values) saves code, but you should still know that a mean totals the values and divides by their count. That knowledge lets you interpret empty data, check a surprising result, and decide whether a median tells the story better.

def report_wait_times(wait_times):
    if len(wait_times) == 0:
        print("No wait-time observations are available.")
        return

    print(f"Observations: {len(wait_times)}")
    print(f"Mean: {statistics.mean(wait_times):.1f} minutes")
    print(f"Median: {statistics.median(wait_times):.1f} minutes")

The library provides calculations. Your program still supplies empty-data behavior, units, labels, and interpretation.

Third-party packages add installation and trust

A third-party package is distributed separately from Python. Package installers such as pip can obtain packages, but installation may be unavailable on a school or workplace computer. Browser notebooks sometimes include popular packages already or allow temporary installation.

Required work in this unit uses the Standard Library so it can run in Colab, OnlineGDB, or a basic local Python installation without administrator access. Later data notebooks may provide third-party tools in a prepared environment.

A dependency is part of your program's risk

Before adopting a dependency, ask:

  • Source: Is this the intended project, or an imitation with a similar name?
  • Maintenance: Is it actively maintained, and are security reports addressed?
  • Version: Which version does the program expect? Could an update change behavior?
  • Compatibility: Does it support the Python and operating-system versions students can access?
  • License: What reuse and attribution conditions apply?
  • Privacy and network access: Does it send data elsewhere or download additional components?
  • Necessity: Does the benefit justify adding another thing that can fail?

“Open source” means source code is available under some license; it does not automatically mean secure, maintained, ethical, or suitable for every purpose.

Versions make claims time-dependent

Documentation may describe a newer version than the environment you are using. When a call behaves differently from an example, record the Python version, package version if relevant, complete error, and smallest reproducible code. “It doesn't work” becomes a useful report when another person can recreate it.

AI-generated and copied code are dependencies, too

Code suggested by a person, website, or AI system still needs source review, tests, and attribution where required. Do not paste code that handles files, credentials, or network requests without understanding what it reads, writes, or transmits. If you cannot explain a line, isolate it and investigate before building on it.

  1. run the documentation example,

  3. test an edge case,
  4. place the call inside a function with labeled output, and

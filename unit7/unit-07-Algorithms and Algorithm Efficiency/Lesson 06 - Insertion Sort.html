Lesson 6 - Insertion Sort

At the end of this lesson, you will be able to:

  • Explain how insertion sort works step by step
  • Compare insertion sort to selection sort

A Different Strategy

Selection sort isn't the only way to sort a list—it's just one approach. Insertion sort takes a different tack, and honestly, it's probably even closer to what most people do instinctively when they're organizing things by hand.

Like selection sort, insertion sort divides the list into a sorted portion and an unsorted portion. But here's where they diverge: instead of scanning the entire unsorted section for the minimum, insertion sort just grabs the next unsorted item and slides it to the left—swapping it with its neighbor over and over—until it lands in the right spot within the sorted section. You're "inserting" each card into its correct position, one at a time.

Think of it this way. You're playing cards, and someone deals them to you one at a time. Each time you get a new card, you slide it into the right place in your hand. You don't wait until you have all the cards and then hunt for the smallest one—you just put each new card where it belongs as you get it. That's insertion sort.

The Card Sort Version

Here's the human-readable algorithm for sorting a hand of cards with insertion sort:

Insertion Card Sort Algorithm

  1. Get a hand of unsorted cards
  2. Set a marker for the sorted section after the first card of the hand
  3. Repeat steps 4 through 6 until the unsorted section is empty
  4. Select the first unsorted card
  5. Swap this card to the left until it arrives at the correct sorted position
  6. Advance the marker to the right one card
  7. Stop

Watch the animation below to see insertion sort in action. Pay attention to a couple of things. First, notice how the sorted portion builds up from the left—but unlike selection sort, the sorted section doesn't necessarily contain the smallest values in the list. It just contains values that are sorted relative to each other. Second, notice that cards keep swapping left until they find their resting spot—they don't jump directly to their final position.

How It Differs from Selection Sort

This is worth pausing on, because it's a subtle but important distinction. With selection sort, you scan the entire unsorted section each time, find the absolute smallest value, and drop it into place. The sorted section always contains the globally smallest values. With insertion sort, you just take whatever card comes next and shuffle it into the right spot among the cards you've already sorted. The sorted section contains only items that have been placed in order relative to each other—but they might not be the smallest items overall.

The practical upshot? Selection sort always does the same number of comparisons regardless of the input. Insertion sort, on the other hand, can get lucky—if the list is already mostly sorted, each card barely has to move, and it finishes quickly. If the list is in reverse order, though, every card has to slide all the way to the front, and it takes a while. The performance depends on the input, which is an interesting property.

From Cards to Code

Let's formalize the algorithm. Here's the step-by-step version:

  1. If it's the first element, it's already sorted—nothing to do
  2. Pick the next element from the unsorted section
  3. Compare it with each element in the sorted section
  4. Shift everything in the sorted section that's larger than the new value one position to the right
  5. Insert the value into the gap
  6. Repeat until the list is sorted

And here's the pseudocode. Notice the while loop inside the for loop—that's the part that slides each element left until it finds its home:

procedure insertionSort( A : array of items )
   int holePosition
   int valueToInsert

   for i = 1 to length(A) inclusive do:
      valueToInsert = A[i]
      holePosition = i

      while holePosition > 0 and A[holePosition-1] > valueToInsert do:
         A[holePosition] = A[holePosition-1]
         holePosition = holePosition - 1
      end while

      A[holePosition] = valueToInsert

   end for
end procedure

The key idea in the pseudocode: we save the value we want to insert, then shift elements to the right one at a time to "make room," and finally drop the saved value into the hole. It's like sliding books on a shelf to make space for a new one.

Something to think about:

Imagine you have a list that's already sorted. How many swaps would selection sort do? How many would insertion sort do? Now imagine a list in reverse order. Which algorithm handles that worst case better—or do they both struggle equally? Think about what each algorithm's inner loop is doing in each scenario.

Insertion sort and selection sort are both straightforward, easy-to-understand algorithms—and that's exactly why we learn them. They won't win any speed contests on huge datasets (we'll talk about faster algorithms & efficiency later), but they're clear, correct, and they give you a solid foundation for understanding how sorting works in general. The fact that two algorithms can solve the same problem in such different ways—one by always finding the minimum, the other by inserting each element into place—is one of the really cool things about computer science.

Unit 7 Overview

In this unit we step back from writing programs to ask what computation actually is. It turns out an algorithm is an idea that doesn't belong to any one programming language, and the same algorithm can be written many different ways. Searching and sorting give us concrete algorithms to trace and compare, and Big-O gives us a way to talk about how their operation counts grow under the same assumptions, without choosing a programming language. Then the last two lessons go somewhere unexpected: some problems can't be computed at all, and yet three rules on a grid of squares can compute anything.

Learning objectives

By the end of this unit, you should be able to:

  1. Define an algorithm and explain why it is separate from any one programming language.
  2. Recognize the same algorithm expressed in several different languages.
  3. Describe linear and binary search and explain why binary search requires sorted data.
  4. Trace selection sort and insertion sort and distinguish comparisons from data movement.
  5. Measure an algorithm's efficiency using operation counts and Big-O classification.
  6. Describe, in plain terms, the limits of computation and the idea of universal computation.

Lesson map

The six lessons in Unit 7
LessonCentral ideaQuestions to carry forward
1. What Is an Algorithm, Really?An algorithm is a set of steps for solving a problem. It doesn't have to be written in a programming language, but it does need to be clear enough to follow.Would these steps work for every intended input? Is there a point where the person or computer following them would have to guess?
2. One Algorithm, Many LanguagesOne algorithm can be written in several programming languages. The punctuation changes, but we can still look for the same sequence of ideas.Where does each version make a decision or repeat a step? Which differences belong to the language?
3. SearchingLinear search checks items one by one; binary search cuts down the possibilities, but needs the data to be sorted first.What assumptions does the search need? How does the amount of work change as the collection grows?
4. Sorting and Measuring Cost: Big-OSorting gives us something concrete to count. Big-O helps us talk about how that work grows as the input gets bigger.What operation am I counting? What does the classification tell me, and what does it leave out?
5. What Computers Can’t DoSome problems have no algorithm that can give the right answer for every possible input. The halting problem gives us a way to see why.What would a supposed all-purpose halting checker have to handle? Why isn't a faster computer enough to solve the problem?
6. Computation From Almost Nothing: Conway’s Game of LifeThe Game of Life starts with a few simple rules for cells on a grid. Repeated over time, those rules can produce surprisingly complex behavior and even support computation.How does the next state follow from the current one? What can repeated local rules build?

Unit 7 Summary

Wrap up

In this unit we stepped back from writing programs to think about what computation is. An algorithm is an idea that doesn't belong to any programming language. That means we can compare how the work grows for two algorithms, even though the actual running time depends on the language and the machine. And it turns out computation has some hard limits, along with a reach that's honestly a little surprising.

What to carry forward

  • An algorithm is a step-by-step method for solving a problem, and it's an idea rather than a piece of code. You can write the same algorithm in Python, JavaScript, Lisp, or plain pseudocode and it's still the same computation, the way a recipe is still the same recipe whether it's written in English or Spanish.
  • Efficiency is about how an algorithm's work grows as the input gets bigger, and Big-O notation lets us talk about that growth without picking a language or a computer. The classes you saw most were constant O(1), logarithmic O(log n), linear O(n), and quadratic O(n²), and the gaps between them get enormous once the input does.
  • Linear search checks items one at a time, so it's O(n), while binary search keeps cutting a sorted list in half, so it's O(log n) and needs far fewer checks on a big list. The catch is that the list has to be sorted first, and getting it sorted has a cost of its own.
  • Selection sort keeps finding the smallest value that's left and moving it into place, while insertion sort takes each new value and slides it into a sorted section that keeps growing, a bit like sorting a hand of cards. Both are O(n²) in the worst case, but they compare and move data in different ways.
  • If you ever wonder where a Big-O class comes from, count the comparisons, copies, shifts, and swaps, because that's what the classification is built on. And two algorithms in the same Big-O class can still do quite different work, so sharing a class doesn't make them the same algorithm.
  • Some problems can't be solved by any algorithm, no matter how clever the programmer or how fast the computer. The halting problem is the famous example, and it's a limit on computation itself rather than on today's technology.
  • On the other side, computation is so basic that it shows up in surprising places. Conway's Game of Life is just three simple rules on a grid, and yet a universal computer can be built inside it.

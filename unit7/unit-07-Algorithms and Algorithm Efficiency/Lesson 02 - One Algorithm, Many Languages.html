Lesson 2 - One Algorithm, Many Languages

At the end of this lesson, you will be able to:

  • Explain why an algorithm is an idea that is separate from any one programming language.
  • Recognize the same algorithm written in several very different languages.

The plan is the real thing

Way back in Unit 3, before we wrote any Python, we wrote pseudocode - the plan for a program in plain English. Then we translated the plan into Python. It's easy to come away thinking Python was the point and the pseudocode was just a warm-up. It's actually the other way around. The plan - the algorithm - is the real thing. Python is just one way to write it down.

That's a big claim, so let's prove it. We're going to take one simple algorithm and write it four different ways: as pseudocode, and then in three real programming languages. Watch what stays the same.

The algorithm

Here's our algorithm, in pseudocode. It walks through a list of numbers and finds the biggest one (you wrote almost exactly this in Unit 5!):

set biggest to the first number in the list
for each number in the list:
    if number is bigger than biggest:
        set biggest to number
print biggest

Read it once and convince yourself it works. We start by assuming the first number is the biggest. Then we look at every number; any time we find one bigger than our current champion, it becomes the new champion. At the end, biggest holds the answer.

The same algorithm, in three languages

Now here is that exact same algorithm in three actual programming languages. You only know one of these (Python), and that's fine - you're not here to learn the other two. You're here to notice that they're all saying the same thing.

Python - the language you already know:

numbers = [4, 9, 2, 11, 7]
biggest = numbers[0]
for number in numbers:
    if number > biggest:
        biggest = number
print(biggest)

JavaScript - the language that runs inside every web browser on Earth. Different punctuation (curly braces, semicolons), same idea:

let numbers = [4, 9, 2, 11, 7];
let biggest = numbers[0];
for (let number of numbers) {
    if (number > biggest) {
        biggest = number;
    }
}
console.log(biggest);

Common Lisp - and now for something that looks like it fell out of a spaceship. Lisp is one of the oldest programming languages still in use, and it wears its parentheses proudly. Take a breath, and then keep reading - because it is doing the identical thing:

(let ((numbers (list 4 9 2 11 7)))
  (let ((biggest (first numbers)))
    (dolist (number numbers)
      (when (> number biggest)
        (setf biggest number)))
    (print biggest)))

All three of these, when you run them, print the same thing: 11, the biggest number in the list.

Spot the skeleton

The three versions look wildly different on the surface - one has colons, one has curly braces, one is drowning in parentheses. But underneath, every single one does the same four things, in the same order:

  1. Remember the biggest so far, starting with the first number.  (biggest = numbers[0]  /  let biggest = numbers[0]  /  (biggest (first numbers)))
  2. Walk through the numbers, one at a time.  (for number in numbers  /  for (let number of numbers)  /  (dolist (number numbers) ...))
  3. If this one is bigger, update the champion.  (if number > biggest  /  if (number > biggest)  /  (when (> number biggest) ...))
  4. Print the answer.

That shared skeleton - the loop, the comparison, the remembered value - is the algorithm. The colons and braces and parentheses are just costumes. A Python programmer in Portland and a Lisp programmer in Tokyo who have never met would each recognize the other's "find the biggest number" in seconds, even though the two of them couldn't read a word of each other's language.

Try it! Look at the Common Lisp version - the scary one. Without knowing any Lisp, find the line that does the comparing ("is this number bigger than the biggest so far?"). It's written (> number biggest) - the > comes first, which is part of what makes Lisp look so alien. Now find the loop. You just read a language you've never studied, because you already knew the algorithm.

Why this matters

This is the central idea of the whole unit, and arguably of computer science itself: a computation is a thing in its own right, floating above any particular language. The language is how we write it down; the computation is what we wrote.

Once you really believe that, some powerful questions open up - questions about the computation itself, not about Python or Lisp:

  • How fast is this algorithm? (We'll find that "find the biggest" has a speed we can talk about no matter which language it's in - that's coming up next.)
  • Is there a faster algorithm for the same job?
  • And the wildest one of all: are there things that no algorithm, in any language, on any computer, could ever do? (Spoiler for later in the unit: yes.)

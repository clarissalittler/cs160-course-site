Lesson 02 - Linear Search

The Simplest Search There Is

Computers spend an enormous amount of their time searching through data. Looking up your student record, finding a particular song in a playlist, checking whether a username already exists—it's all searching. So one of the first questions in computer science is: how do you find a specific item in a list?

The simplest possible answer is: start at the beginning and check every single item, one at a time, until you either find what you're looking for or run out of list. That's it. That's linear search. It's called "linear" because you move through the list in a straight line—first item, second item, third item—no skipping, no shortcuts.

Think of it like looking for your car keys. You don't have a system—you just start checking places. Kitchen counter? No. Coat pocket? No. Coffee table? No. Under the couch cushion? There they are. You checked each spot one by one until you found them. That's linear search in action.

How It Works (Step by Step)

Let's make this a bit more precise. Say we have a list of numbers, and we're looking for a particular value—we'll call it the key. Each item in the list sits at a numbered position called its index. Here's the algorithm written out in pseudocode:

Note: assume that list and key are already set
1   set location = 1
2   repeat until location > (length of the list)
3       if list[location] == key
4           print "Found at " + location
5           end program
6       set location = location + 1     advance to next location
7
8   print "Value not found"

Let's walk through what's happening here. We start at position 1. We look at the value at that position and ask: "is this the thing I'm looking for?" If yes—great, we're done. If not, we move to position 2 and ask the same question. We keep going, one position at a time, until either we find our key or we've checked every single item in the list without finding it.

The notation list[location] just means "the value in the list at position location." So list[3] would be whatever value is sitting in the third slot. You saw this kind of notation back in the unit on arrays—it's the same idea.

Seeing It in Python

Here's a working Python program that creates a list of random numbers and then tries to find a specific value using linear search. It's doing exactly what our pseudocode described—just in real, runnable code.

# Demo for Linear Search
import random

# main function
def main():
    value = 6
    numbers = []
    for num in range(1, 10):
        numbers.append(random.randrange(1, 10, 1))
    print(numbers)
    for num in range(1, len(numbers)):
        if(numbers[num] == value):
            print("Your number is in index: ", num)
    if(num == len(numbers)-1):
        print("Number not found!")

# call main
main()

The program builds a list of 9 random numbers (each between 1 and 9), prints the list, and then walks through it one position at a time checking for the value 6. If it finds a match, it tells you the index. If it gets all the way to the end without a match, it reports that the number wasn't found. Straightforward, right?

The Big Weakness

Linear search is beautifully simple—and for small lists, it works just fine. But it has one major drawback: you might have to look at every single item in the list.

If you're searching a list of 10 items, that's no big deal. But what if the list has a million items? Or a billion? In the worst case—where the thing you want is the very last item, or isn't in the list at all—you have to check every. single. one. That gets slow fast.

Think about it this way: imagine trying to find someone's phone number in a phone book (remember those?) by starting at page one and reading every single entry until you find the right name. You'd be there all day. Nobody actually uses a phone book that way—you jump to roughly the right section because the names are in alphabetical order. That "jumping to the right section" idea is the basis of a much faster search algorithm, which we'll meet in the next lesson.

Something to think about:

When would linear search actually be the right choice? Think about situations where the list is small, or where the items aren't in any particular order. If you've got a messy junk drawer and you're looking for a pair of scissors, you don't have a choice—you just rummage through it one item at a time. That's linear search, and sometimes it's all you've got. The question is: when can we do better?

Linear search is our baseline—the simplest approach, the one you'd think of first. It always works (on any list, sorted or not), and it's easy to understand and code. But "always works" doesn't mean "always works well." In the next lesson, we'll see how a smarter approach—binary search—can find things dramatically faster, as long as we have one key advantage: a sorted list.

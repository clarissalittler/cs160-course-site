Wrap up

So let's step back and look at how it all fits together. Every time you visit a website, you're relying on a whole stack of open, standard protocols working quietly behind the scenes: DNS turns a name like pcc.edu into an IP address, and with that address in hand your computer knows exactly where to send its requests - and how to get the page back so your browser can show it to you. No central authority runs any of this; it works because everyone agreed on the same rules.

These shared standards and autonomous systems - along with the Internet's hierarchical structure - are what allowed it to become global in scale; nowadays, nearly every country in the world has at least some access to the Internet. The Internet is continuing to grow as well. As a result of the existing protocols, it is easy to create more and more, knowing that everyone will be able to access it immediately as long it adheres to the standards.

Summary

  • When you type in a website name, your browser will contact the DNS to find the IP address.
  • When you receive the address you'll send an HTTP GET request to the website to send you its homepage.
  • The website server will respond with the HTML code that makes up its web page.
  • All of the communications above happen on the Internet which means TCP or UDP will break the message into packets and then send them. If TCP is used, error checking will occur.
  • IP will route the packets back and forth between your computer and the server.
  • All of this information is sent over the physical wires, cable, wifi networks, and routers that make up the physical network of the internet.

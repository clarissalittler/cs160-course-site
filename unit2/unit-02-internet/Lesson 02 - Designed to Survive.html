Lesson 2 - Designed to Survive: Packets and Redundancy

At the end of this lesson, you will be able to:

  • Explain how splitting messages into packets lets data take many paths to its destination.
  • Explain why redundancy - many possible paths - makes a network hard to break.
  • Connect this design to why the internet survives outages and resists censorship.

The problem: build a network that can take a hit

Imagine you're one of the internet's original designers, back in the 1960s, and you're handed a hard requirement: build a communication network that keeps working even when pieces of it are destroyed. Cables get cut, machines catch fire, power goes out - and the network still has to get the message through. How would you do it?

The answer they landed on is the reason the internet works the way it does today, and it comes down to two ideas: packets and redundancy.

Idea one: break the message into packets

Instead of sending your message - an email, a photo, a video - as one big unbroken stream, the internet chops it into small pieces called packets. Each packet is labeled with where it's going, where it came from, and which piece of the message it is (piece 3 of 47), so the pieces can be put back in order at the other end.

Think of mailing a long book to a friend by tearing out the pages and sending each one in its own envelope. It sounds absurd, but it has real advantages: if one envelope gets lost, you only resend that page, not the whole book. And - this is the key part - the envelopes don't all have to travel the same way. Some can go via Chicago, some via Denver, whatever route is open at the moment. They meet up and get reassembled at the destination. Splitting your message into packets means no single road has to carry the whole thing, which sets up the second idea.

Idea two: build in redundancy

A network is just dots (computers, routers) connected by lines (links). If there's only one path between two dots, that path is a single point of failure - cut it and they can't talk. So the internet is built with redundancy: many possible paths between places, so that if one is unavailable, the packets simply flow around the gap.

Now the resilience questions (assume every path is built):

  • What's the cheapest path from node C to node I?
  • Now node E fails completely. What's the new cheapest path from C to I? Did the network still get the message through?
Show answers

Normally the cheapest route is C → D → E → I (cost 3 + 5 + 3 = 11). When E dies, the packets reroute: C → D → F → H → I (cost 3 + 6 + 2 + 5 = 16). More expensive, a little slower - but the message still arrives. That's redundancy doing its job.

Why this matters beyond the puzzle

This isn't just a neat design - it has two big real-world consequences that come straight back to our unit's theme:

  • The internet survives outages. When a construction crew cuts a fiber line or a data center loses power, packets reroute and most of us never notice. The network is antifragile in exactly the spots where it stays distributed.
  • The internet resists censorship. Because there's no single chokepoint, it's genuinely hard for anyone - even a government - to fully block information. Shut down one path and traffic finds another; it's a big part of why tools like VPNs can get around blocks. (We'll see the flip side later: when traffic does get funneled through a few big companies, that resistance quietly weakens.)

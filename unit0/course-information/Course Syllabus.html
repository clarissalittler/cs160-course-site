Course Description

This class introduces students to the breadth of computer science and concepts of programming. Explores concepts including the importance and impact of computing and technology, computability, computational complexity, algorithm analysis and design, abstraction, data and information, the Internet, programming concepts, application development, computational thinking, and the global impact of computing.

We will explore programming concepts using the Python Programming Language. Python is designed to be easy to understand and fun to use. Python reads like English, which takes a lot of syntax-learning stress off coding beginners. 

Intended Outcomes for the Course

On completion of this course the student should be able to:

  • IO 1:  Create computer programs to implement algorithms that solve problems.
  • IO 2:  Assess the computational complexity and computability of algorithms and their implementations.
  • IO 3:  Demonstrate a computing culture that is collaborative and ethical.
  • IO 4:  Evaluate computing innovations, computing systems, and career opportunities in computer science and other related disciplines.
  • IO 5:  Analyze questions or problems that impact the community and/or environment using quantitative information.

For more information, please go to the Course Content and Outcome Guide for this course.

Course Topics

Course Topics
Unit Description Learning Outcomes
1 Digital Information Explore computers as layered systems and examine how bits represent numbers, text, images, and sound. Evaluate how standards, compression, access, ownership, and permission shape digital information.
  1. Trace information through the hardware and software layers of a computer system. (IO 4)
  2. Represent small whole numbers using bits, bytes, and the binary number system. (IO 4)
  3. Explain how standards, metadata, and sampling represent text, images, and sound. (IO 2)
  4. Justify a lossless or lossy compression choice for a particular purpose and audience. (IO 2)
  5. Distinguish ownership from permission and identify responsible paths for reusing digital work. (IO 3)
  6. Analyze who benefits, who might be harmed or excluded, and who has decision-making power in an everyday computing system. (IO 3)
2 The Internet Trace everyday communication across the physical internet and its layered protocols. Evaluate how access, cloud and platform dependencies, privacy, standards, governance, and infrastructure choices affect people and communities.
  1. Distinguish the internet from Wi-Fi, the web, cloud services, and individual apps, and trace an exchange across independently operated networks. (IO 4)
  2. Explain packet switching, routing, loss and retransmission, congestion, latency, throughput, and the limits of redundancy. (IO 2, 4)
  3. Explain how IP addresses, ports, DNS, layering, encapsulation, HTTPS, and request-response protocols cooperate in a web request. (IO 2)
  4. Compare independent hosting, cloud, CDN, and platform dependencies, including convenience, correlated failure, environmental costs, and control. (IO 3, 4)
  5. Analyze an access, outage, privacy, or governance problem by identifying evidence, stakeholders, who benefits, who may be harmed or excluded, and who decides. (IO 3, 5)
  6. Propose both a technical mitigation and an institutional response appropriate to an internet incident or inequity. (IO 3, 4)
3 Introduction to Programming Write and run your first Python programs. Explore algorithms and pseudocode, variables and types, input and output, calculations and debugging, and counted repetition with for loops.
  1. Develop an algorithm in plain language and pseudocode before coding it. (IO 1)
  2. Create a Python program that uses variables, input, output, and calculation. (IO 1, 2)
  3. Convert between text and numeric types and format output with f-strings. (IO 1)
  4. Read a traceback, diagnose common errors, and test a program against answers you already know. (IO 1, 2)
  5. Use for loops and range to produce an intentional repeated pattern. (IO 1)
  6. Explain how the assumptions inside an algorithm affect the people who use it. (IO 3)
4 Functions, Decisions, and Repetition Name and reuse processes with student-defined functions, then teach programs to choose and repeat: Boolean expressions, if/elif/else, logical operators, and while loops with input validation.
  1. Define and call original functions with parameters and return values. (IO 1)
  2. Create conditional expressions resulting in boolean results (true or false) and test them at boundary values. (IO 1, 2)
  3. Alter the flow of a program with if, elif, and else. (IO 1)
  4. Use logical operators to build complex boolean expressions. (IO 1)
  5. Use while loops for input validation and explain why a loop terminates. (IO 1, 2)
  6. Explain how thresholds and rules in code act as policy for the people they affect. (IO 3)
5 Collections, Data Models, and Interfaces Move from single values to collections: strings as sequences, lists, tuples, and dictionaries. Model small parts of the world as records, and treat usability and accessibility as design concerns.
  1. Create, index, slice, and modify strings and lists in Python. (IO 1)
  2. Apply collection-processing patterns: counting, accumulating, filtering, and finding extremes. (IO 1, 2)
  3. Choose among tuples, lists, and dictionaries to represent records, and justify the choice. (IO 1, 4)
  4. Design a small schema and text interface that handle unknown, optional, and nonconforming values respectfully. (IO 3)
  5. Evaluate who is included or excluded by a data model's categories and required fields. (IO 3)
6 Files, Databases, and Software in the Real World See what changes when programs must keep data around: files and persistence, CSV data and provenance, libraries and dependencies, a taste of SQL, and the habits that keep software maintainable.
  1. Read and write text and CSV files, converting values to appropriate types. (IO 1)
  2. Document a dataset's source, meaning, and quality issues before analyzing it. (IO 5)
  3. Use documentation to apply a library module you did not write. (IO 1, 4)
  4. Express the same simple query as a Python loop and as SQL. (IO 1, 2)
  5. Improve a working program with tests, documentation, and refactoring. (IO 1, 3)
7 Algorithms & the Nature of Computation Study algorithms as things independent of any programming language: searching, measuring cost with Big-O, problems no program can ever solve, and the surprising behavior of simple rules in Conway's Game of Life.
  1. Write simple algorithms and express the same algorithm in prose, pseudocode, and code. (IO 1)
  2. Trace linear and binary search and explain when each is appropriate. (IO 1, 2)
  3. Quantify the efficiency of different algorithms using Big-O classification. (IO 2)
  4. Explain the halting problem and distinguish "slow to compute" from "impossible to compute." (IO 2)
  5. Describe how simple local rules can produce complex, even unpredictable, behavior. (IO 2, 4)
8 Data Explore and visualize datasets from a wide variety of topics as you hunt for patterns, make predictions, and try to learn more about the world around you.
  1. Create bar charts, histograms, scatter plots, and crosstab charts using Python libraries. (IO 1, 5)
  2. Draw conclusions from data by using quantitative reasoning and reading charts. (IO 5)
  3. Explain the reasons that someone would create a bar chart, histogram, scatter plot, or crosstab chart in order to explore one or two columns of data. (IO 5)
  4. Explain why data needs to be cleaned. (IO 5)
9 Artificial Intelligence Open up the machine-learning black box: fitting a line, gradient descent, neural networks, and backpropagation — then the deep learning era, generative AI, and questions of bias, society, and careers.
  1. Explain key terminology associated with the field of AI. (IO 4)
  2. Describe how a model learns from examples by reducing measured error. (IO 2, 4)
  3. Explain gradient descent and, at a conceptual level, how neural networks are trained. (IO 2)
  4. Describe what generative AI systems do and their characteristic failure modes. (IO 4)
  5. Identify the societal impacts of AI, including bias and accountability. (IO 3, 4)
  6. Describe career opportunities in the AI field. (IO 4)
10 Cybersecurity Learn to protect yourself online: scams and social engineering, misinformation and verification habits, passwords and multi-factor authentication, privacy, harassment, and recovering when things go wrong.
  1. Recognize common scams, phishing, and social-engineering techniques. (IO 3, 4)
  2. Evaluate online claims using verification habits such as lateral reading. (IO 4, 5)
  3. Explain risks to privacy from using modern technology. (IO 3, 4)
  4. Explain how encryption, passwords, passkeys, and multi-factor authentication protect accounts and communication. (IO 2, 4)
  5. Build a plan for responding to harassment, breaches, or a compromised account. (IO 3, 4)

Instructional Approach

This course is arranged chronologically and employs a modular design. Each week, students should complete the lessons, shareable Activity Discussion, assignment, and quiz listed in that week's unit module. These modules are available by clicking "Content" on the course navigation bar.

Due dates for each week's discussion, assignment, and quiz will be listed within the module itself. Activities within the modules may direct students to use many of the tools contained in Brightspace, including Assignments, Discussions, or Quizzes. These tools will be accessible from within the weekly content modules, as well as from the course navigation bar in the Coursework drop-down menu.

Weekly Structure

Each week you will complete a Unit module. The unit and learning activities are listed on the Weekly Announcement, Course Schedule, and Unit Overview pages.

At the beginning of each week, read the Unit Overview page and start on the lesson pages. Lesson pages contain readings, videos, worked examples, and interactive practice. Each week also includes one Activity Discussion: you will make or investigate something interesting, share what you made or found, and respond to classmates' work. After completing the lessons, you will also have a Quiz, a Week Assignment, and a Unit Summary page to review. Do not skip the summary pages - they contain additional resources for the unit!

  • Weekly Assignments, Quizzes, Activity Discussions, and the Midterm Exam will all be due on Sunday of each week.
  • Assignment resubmissions and late work will be due Friday before the Final Exam week.
  • Final Exam will be due on Wednesday of Final Exam week.

Release Conditions

There are several important release conditions you need to be aware of:

  • The Final Exam will not be available until you have completed the Post-Survey in Unit 11, AND scored at least a 1 on every Weekly Assignment. You can resubmit Weekly Assignments until Friday before Final Exam week.

Pair Programming, Collaboration, and Group Work

You will be required to complete some work with your study group and share your work on the weekly Activity Discussions for feedback. In the programming units, you are encouraged to practice with a partner using an industry technique called pair programming. Pair programming consists of two programmers working on the same program at the same time. Both partners will be able to see the same screen at the same time and one programmer will be the driver and the other will be the navigator. The programmer using the keyboard is the driver, while the navigator tells the driver what to do. It is expected the programmers swap roles every three to five minutes.

I also expect and encourage you to talk through each week's material with your study group. Please follow these group guidelines:

  • You may discuss the ideas in a Weekly Assignment with your study group, but the work you submit must be your own: your own document, your own code, your own words. 
  • If your group works through something and you are unable to join, you may NOT ask to be sent the answers. You will need to complete it on your own.
  • For problems that ask “What will the program display?” it is critical for you to step through the code and “predict” the answer, before typing up the code and asking the computer to show you the answer - don’t let the computer do the thinking for you!
  • Sharing a complete solution with a classmate — in either direction — is not collaboration and is not permitted.

Students will be required to form a study group and meet at an agreed-upon time, to complete course activities outside of our scheduled meeting times.

Graded Activities & Feedback

Weekly Assignments: 80%

There will be 10 Weekly Assignments this term, one per unit — some are programs, some are analyses, and some are creative artifacts that show what you can do with the week's ideas. All Weekly Assignments can be accessed from the Coursework drop-down menu on the navigation bar and in the Content Unit module to which they relate. You should plan to submit your work (an upload or a shareable link, as the handout describes) to the Assignment folder on or before the due date. Each assignment is graded on a 0-4 scale using the criteria listed in its handout. Submitted work will be given feedback, and you can revise and resubmit for full credit with no late penalty until the Friday before Final Exam week. You must score at least a 1 on every Weekly Assignment to unlock the Final Exam. The purpose of these assignments is to practice, and then demonstrate, the problem-solving, computational thinking, and programming skills introduced in each unit. Mastery of the programming weeks also builds a solid foundation for success in the next course, CS161A/B. 

Activity Discussions: 0%

Each unit includes a creative, exploratory Activity Discussion. You will make or investigate something connected to the week's ideas, share your result in D2L—often as a Google or Colab link—and respond to classmates' work. You must first post to the discussion before you can view other posts.  The purpose of these discussions is to make computer science social and shareable: everyone contributes something concrete, sees the variety of things classmates made or discovered, and responds with curiosity and constructive feedback.

Quizzes: 0%

There will be a quiz for each unit. They will consist of multiple-choice, short answers, and true or false questions from the unit lessons. Please complete the quiz before attempting the Weekly Assignment within the same unit - you will be more prepared! Quizzes are not graded and you have unlimited opportunities to retake them. The Midterm and Final draw their questions from the same pools as the weekly quizzes, so the quizzes are also your best exam preparation. You must score 100% on the Course Information quiz to gain access to the first content unit. The purpose of these quizzes is to assess your command of the material we have covered in a particular unit. 

Midterm and Final Exam: 10% each (20% total)

There will be a Midterm and Final exam. The Midterm covers Units 1 - 4 and will consist of 20 multiple-choice, short answer, and true or false questions from the weekly quizzes and you have 60 minutes and one attempt to complete the exam. The Final will consist of 30 multiple-choice, short answer, and true or false questions from the weekly quizzes and you have 90 minutes and one attempt to complete the exam. The purpose of these exams is to assess your command of the material we have covered in the course.

Grading Scale

This course uses a 4.0 grading scale because it:

  • Is mathematically accurate - Your score will tell you exactly how you are doing and how you can improve. With a 0-100 scale, 60% of the grade is weighted towards failure. With a 4.0 scale, each gradation is weighted more evenly.
  • Values knowledge - Your grade will reflect what you know and can do.
  • Uses a feedback loop - Your score will be based on a rubric, encouraging mistakes as necessary for learning. Using a feedback loop with the rubric, you will be expected to make the required changes to improve your understanding of the material. It is important to remember that I have high expectations, and I believe you can learn how to code. Feedback is meant to help improve your learning, not to criticize, so please assume positive intention when reading!

  • 0 (No evidence). This isn't a grade as much as a mark to indicate there is no basis for assigning a grade.
  • 1 (Not yet). The evidence shows insufficient learning to pass the course in most areas.
  • 2 (Approaching). The evidence shows learning is sufficient in many areas to pass the course, but some gaps remain.
  • 3 (Meets). The evidence shows learning is sufficient to pass the course in all areas.
  • 4 (Exceeds). The evidence shows learning in all areas is beyond what is required to pass the course.

Academic Integrity (rules about cheating, plagiarism, or sharing work)

Students are required to complete this course in accordance with the Student Rights and Responsibilities Handbook. Cheating includes any attempt to defraud, deceive, or mislead the instructor in arriving at an honest grade assessment, and may include copying answers from other students or using unauthorized notes during tests. Plagiarism is a particular form of cheating that involves presenting as one's own the ideas or work of another, and may include using other people's ideas without proper attribution and submitting another person's work as one's own. Dishonest activities such as cheating on exams and submitting or copying work done by others will result in disciplinary actions including but not limited to receiving a failing grade. For further information, review the institution's Academic Integrity Policy.

As a reminder, learning to code can be difficult and frustrating and takes LOTS of practice. Our academic integrity policy for this course states that when completing programming assignments you may:

  • review course materials
  • look things up in the Python documentation
  • google specific questions online, such as "syntax for Python while loops"
  • use the tutorial examples in a lesson or assignment notebook as starting ideas only - the artifact you submit must be a new creation of your own, not a light edit of a sample

You may NOT, under any circumstances, begin a programming assignment by:

  • looking for completed code which you can then modify
  • starting with a copy of the actual sample program and modify
  • asking a more experienced friend or family member to outline a solution for you

For individual-designated problems or exercises copying, sharing, or using improper resources is a violation of course principles. 

For multi-person-designated problems or exercises, copying, sharing, or using improper resources outside of one's group is a violation of course principles.

I do encourage the discussion of ideas with other students in the course and with your study group. Collaboration in the form of pair programming is an effective learning practice. One person sharing an assignment or test solution with another would not be collaboration and is not permitted.

The only way to learn to code is to do it yourself. The assignments build directly on examples from the lessons, so ask for clarification in the Ask Questions! discussion if something seems confusing. If you start with code from another source and change the variable names or other content to make it look original, you will receive a zero on the assignment.

I may ask you to explain your assignment verbally. If you cannot satisfactorily explain what your code does, and answer questions about why you wrote it in a particular way, then you should also expect a zero.

Generative AI Tools

AI tools like ChatGPT, Claude, and Gemini follow the same rules as human helpers. You may use them the way you would use a knowledgeable friend: to explain a concept a different way, to look up syntax, or to help you make sense of an error message. You may NOT have them produce your assignment for you - pasting an assignment prompt into an AI tool and submitting what comes back is the same violation as submitting a friend's work, and the "explain your code verbally" expectation above applies with special force. If AI assistance meaningfully shaped something you submit, say so in your reflection. Never paste personal information (yours or anyone else's) or another course's graded work into a consumer AI service. Some assignments - especially in Unit 9 - make working with an AI tool the whole point; those handouts state their own rules, which take precedence for that assignment.

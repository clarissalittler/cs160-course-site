Lesson 7 – Functions: Your Own Verbs

At the end of this lesson, you will be able to:

  • Define and call a simple function.
  • Explain why functions are useful—reuse, organization, and abstraction.
  • Identify the parts of a function definition: def, the name, the colon, and the indented body.

You've Been Using Functions Since Day One

Here's something that might surprise you: you already know how to use functions. Every time you write print(), input(), or int(), you're calling a function. Those are functions that somebody else wrote and built into Python for you. print() is a verb that means "show this on the screen." input() is a verb that means "ask the user for something and give me what they typed."

Functions are verbs. They do things. And in this lesson, you're going to learn how to make your own.

Remember how in the drawing assignments you made functions like triangle() or draw_house() in Colab? Same idea. You gave a name to a block of drawing instructions so you could reuse them. Now we're going to do that more formally—and understand what's actually happening when you write one.

Why Bother?

Imagine you're writing a program that needs to print a little greeting banner in three different places:

print("=" * 30)
print("  Welcome to the Program!")
print("=" * 30)

# ... some code later ...

print("=" * 30)
print("  Welcome to the Program!")
print("=" * 30)

# ... even more code later ...

print("=" * 30)
print("  Welcome to the Program!")
print("=" * 30)

That's the same three lines, copied and pasted three times. It works, sure—but what happens when you want to change the greeting? You have to find and update every single copy. Miss one and your program is inconsistent. This is the kind of thing that causes bugs in real software.

Functions solve this problem. You write the code once, give it a name, and then just use that name whenever you need it. One place to update, zero chance of forgetting a copy.

Your First Function

Here's what a function definition looks like in Python:

def print_banner():
    print("=" * 30)
    print("  Welcome to the Program!")
    print("=" * 30)

Let's break that down piece by piece:

  • def – This keyword tells Python "I'm about to define a function." Think of it as short for "define."
  • print_banner – That's the name we chose for our function. This is the verb we're creating.
  • () – The parentheses. For now they're empty—we'll put stuff in them in the next lesson.
  • : – The colon at the end. Just like if statements, the colon says "the indented block that follows belongs to this."
  • The indented lines – These are the body of the function. This is the code that runs when the function is called.

But here's the critical thing: defining a function doesn't run it. It just teaches Python a new word. To actually make it go, you have to call it:

def print_banner():
    print("=" * 30)
    print("  Welcome to the Program!")
    print("=" * 30)

print_banner()
print_banner()
print_banner()

Now we get our banner printed three times—but the actual code for it only exists in one place. If we want to change the message, we change it once inside the function and every call picks up the change automatically.

Common Mistake: A function that's defined but never called doesn't do anything! If you write def print_banner(): and its body but never write print_banner() somewhere below, Python will happily learn the word and then never use it. Your program will run with no errors—and no output. Don't forget to actually call your functions.

Try it! Open a new Colab notebook (or Python file) and write a function called print_greeting that prints two lines—a greeting and a fun fact about yourself. Then call it three times. Run it and make sure you see the output three times.

The Indentation Rule

Just like with if statements, indentation is how Python knows what's inside the function and what isn't. Look carefully at this example:

def say_hello():
    print("Hello!")
    print("Welcome to CS 160!")

print("This line is NOT inside the function.")

The two print lines that are indented under def are inside the function. They only run when say_hello() is called. The last line—not indented—is outside the function and runs immediately when Python reaches it.

Here's what happens when we run this whole program:

def say_hello():
    print("Hello!")
    print("Welcome to CS 160!")

print("This runs right away.")
say_hello()
print("This runs after the function call.")

Output:

This runs right away.
Hello!
Welcome to CS 160!
This runs after the function call.

See that? Python skips the function body when it first encounters the def. It just registers the name. Then when it hits say_hello(), it jumps up into the function, runs the body, and comes back to continue where it left off.

Try it! Predict the output of this program before you run it. Then check yourself:

def cheer():
    print("Go Ducks!")
    print("Quack quack!")

print("Ready?")
cheer()
print("Game over.")
cheer()

Functions That Do More Than Print

Functions can contain any code you've already learned—variables, math, if-statements, &c. Here's a function that draws a little box with a message inside it:

def print_reminder():
    message = "Don't forget to save your work!"
    border = "*" * (len(message) + 4)
    print(border)
    print(f"* {message} *")
    print(border)

print_reminder()

And here's one that uses an if statement. Let's say we have a program that asks the user's name and then prints a special message if it's a specific name:

def print_welcome():
    name = input("What's your name? ")
    print(f"Welcome, {name}!")
    if name == "Guido":
        print("Oh wow, the creator of Python! Big fan.")

print_welcome()

The function handles everything—getting the input, printing the greeting, and doing the check. All wrapped up in one tidy package.

Try it! Write a function called print_weather_report that asks the user "Is it raining? (yes/no)" and prints either "Bring an umbrella!" or "Enjoy the sunshine!" depending on their answer. Call the function to test it.

Naming Your Functions

Good function names are little descriptions of what the function does. Since functions are verbs, their names should usually start with a verb:

  • print_greeting – prints a greeting
  • calculate_tax – calculates a tax
  • check_age – checks an age
  • draw_triangle – draws a triangle

In Python, function names follow the same snake_case convention as variable names: all lowercase, words separated by underscores. Avoid names like f1, myFunc, or do_stuff—they don't tell you anything about what the function actually does.

A good rule of thumb: if someone reads your function name, they should be able to guess roughly what it does without reading the code inside it.

Wrapping Up

Functions are one of the most important ideas in programming. They let you take a block of code, give it a name, and reuse it as many times as you want. In the next lesson, we'll make functions much more powerful by giving them inputs—so that the same function can do different things depending on what you pass to it.

Try it! Write a function called print_favorite_things that prints your three favorite things (movies, foods, songs—whatever you like), each on its own line. Call it twice. Then change one of the items inside the function and notice how both calls automatically pick up the change. That's the power of writing code in one place.

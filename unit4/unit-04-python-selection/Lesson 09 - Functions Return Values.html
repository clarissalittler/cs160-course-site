Lesson 9 – Functions: Return Values

At the end of this lesson, you will be able to:

  • Write functions that return values using the return statement.
  • Explain the difference between printing and returning.
  • Use the return value of a function in expressions and variable assignments.

Printing vs. Returning

So far, all of our functions have used print() to show their results on screen. That's fine when all you want to do is display something—but what if you want a function to calculate something and give the answer back to you so you can use it later?

Think about the len() function. When you write len("hello"), it doesn't print 5 on the screen. It gives you back the number 5, and you can do whatever you want with it—store it in a variable, use it in a calculation, pass it to another function, &c. That "giving back" is called returning a value.

This is one of the most important ideas in all of programming, and it's the thing that trips up beginners the most. So let's take it slow.

The return Statement

Here's a simple function that adds two numbers and returns the result:

def add(a, b):
    return a + b

result = add(3, 5)
print(result)        # 8
print(add(10, 20))   # 30

The return keyword says "here's the answer—send it back to whoever called me." When Python hits return a + b, it evaluates a + b, and that value gets sent back to the line that called the function. So add(3, 5) becomes 8, and that 8 gets stored in result.

You can think of a function with a return value like a little machine. You feed it some inputs, it does some work, and it hands you back a result. The return statement is the machine handing you the result.

Try it! Write a function called multiply that takes two parameters and returns their product. Then call it a few times and print the results. Try storing the result in a variable and then using that variable in another calculation.

Why Not Just Print?

This is the question everyone asks, and it's a great question. Let's look at two functions side by side and see why it matters:

# This function PRINTS the result — shows it on screen, but doesn't give it back
def add_print(a, b):
    print(a + b)

# This function RETURNS the result — gives it back so you can use it
def add_return(a, b):
    return a + b

Now watch what happens when we try to use the results:

# This works perfectly:
total = add_return(3, 5)
double = total * 2
print(double)  # 16

# This does NOT work the way you'd expect:
total = add_print(3, 5)  # prints "8" on screen, but total is... None!
print(total)              # None

When add_print runs, it shows 8 on the screen—but it doesn't give anything back. So when you write total = add_print(3, 5), Python sets total to None, which is Python's way of saying "nothing here." The number 8 appeared on your screen and then vanished into the void. You can't use it for anything.

With add_return, the 8 comes back to you. You can store it, do math with it, pass it to another function—whatever you need.

Common Mistake: If you see None where you expected a number (or a string, or anything else), you almost certainly printed inside the function instead of returning. This is one of the most common beginner bugs, and now you know exactly what causes it.

Try it! Write two versions of a function that calculates the area of a rectangle (length times width). In the first version, print the result inside the function. In the second version, return it. Then try to store each function's result in a variable and print that variable. See the difference? The print version gives you None.

Functions That Calculate Things

Return values really shine when your function does some kind of computation. Here's one that calculates a tip:

def calculate_tip(bill, tip_percent):
    tip = bill * (tip_percent / 100)
    return tip

my_tip = calculate_tip(45.00, 20)
print(f"Your tip is ${my_tip:.2f}")  # Your tip is $9.00

The function does the math and hands the result back. The calling code decides what to do with it—in this case, formatting it nicely with a dollar sign. The function doesn't need to know about the formatting. It just does the calculation. This separation is a big deal—it means you can reuse the same calculate_tip function in different contexts without changing it.

Here's another practical one—a function that returns a Boolean:

def is_even(number):
    return number % 2 == 0

print(is_even(4))   # True
print(is_even(7))   # False

# And because it returns a Boolean, you can use it in an if statement:
if is_even(42):
    print("42 is even!")  # this prints

This is really powerful. You've made your own function that you can use in conditions, just like the built-in ones.

Try it! Write a function called is_passing that takes a grade parameter and returns True if the grade is 60 or above, False otherwise. Then use it in an if-statement to print a message like "You passed!" or "Keep studying."

Using Return Values in Expressions

Since a function call with a return value evaluates to that value, you can use it anywhere you'd use a regular value—in math, in f-strings, as an argument to another function, &c.:

def calculate_tip(bill, tip_percent):
    return bill * (tip_percent / 100)

# Use return values directly in math:
total_tips = calculate_tip(50, 18) + calculate_tip(30, 20)
print(f"Total tips from two tables: ${total_tips:.2f}")  # $15.00

# Use a return value in an f-string:
print(f"Tip on $80 at 15%: ${calculate_tip(80, 15):.2f}")  # $12.00

# Pass a return value to another function:
print(round(calculate_tip(33.33, 18), 2))  # 6.0

You don't always have to store the result in a variable first. Sometimes it's cleaner to use the function call directly. Use whichever makes your code easier to read.

return Stops the Function

Here's an important detail: as soon as Python hits a return statement, it immediately exits the function. Any code after the return never runs. This is actually really useful—it lets you bail out of a function early:

def check_age(age):
    if age < 0:
        return "That's not a valid age!"
    if age >= 18:
        return "You're an adult."
    return "You're a minor."

print(check_age(25))   # You're an adult.
print(check_age(-3))   # That's not a valid age!
print(check_age(12))   # You're a minor.

Notice we don't even need elif here. If age is negative, Python hits the first return and leaves the function immediately—it never checks the other conditions. If age is 18 or over, it hits the second return and leaves. If neither of those triggered, it falls through to the last return.

This "early return" pattern is very common in real-world code, especially for input validation—check for bad input first, bail out if you find it, then handle the normal cases.

Try it! Write a function called letter_grade that takes a numeric score (0–100) and returns the letter grade as a string: "A" for 90+, "B" for 80+, "C" for 70+, "D" for 60+, "F" otherwise. Use the early-return pattern—no elif needed. Test it with several scores.

Putting It All Together

Let's build a slightly more complete example that uses parameters, return values, and if-statements together. Say we're writing a program for a food cart that calculates the total cost of an order with tax:

def calculate_total(price, quantity, tax_rate):
    subtotal = price * quantity
    tax = subtotal * (tax_rate / 100)
    return subtotal + tax

def format_price(amount):
    return f"${amount:.2f}"

def describe_order(item, quantity, total):
    return f"{quantity}x {item} — Total: {format_price(total)}"

# Place some orders
burger_total = calculate_total(8.50, 2, 8.0)
fries_total = calculate_total(3.75, 3, 8.0)

print(describe_order("Burger", 2, burger_total))
print(describe_order("Fries", 3, fries_total))
print(f"Grand total: {format_price(burger_total + fries_total)}")

Output:

2x Burger — Total: $18.36
3x Fries — Total: $12.15
Grand total: $30.51

Look at what's happening here. Each function does one small, clear thing. calculate_total handles the math. format_price handles the dollar-sign formatting. describe_order handles putting together the description string. And the main code at the bottom stitches them together. Each function returns its result so the next piece can use it.

This is what real programs look like—lots of small functions, each doing one job, each handing their results to the next. It's easier to read, easier to test, and easier to change. If the tax rate changes, you update one function. If you want a different display format, you update a different function. Nothing else breaks.

Try it! Extend the food cart example. Add a function called apply_discount that takes a total and a discount_percent and returns the discounted price. Then use it: if the grand total is over $25, apply a 10% discount. Print the final total either way.

Wrapping Up

The return statement is what turns your functions from "things that do stuff" into "things that produce values." Printing is for showing things to the user. Returning is for giving values back to your code. Once you get comfortable with return values, you can start building programs out of small, composable pieces—each function doing one thing well and passing its result along.

To summarize the three lessons on functions:

  • Lesson 7: Functions are named blocks of code you can reuse. def, name, colon, indented body.
  • Lesson 8: Parameters make functions flexible. Arguments are the values you pass in.
  • Lesson 9: return gives a value back. Print shows it on screen; return sends it back to the calling code.

With variables, types, if-statements, and functions in your toolkit, you can start writing programs that are genuinely useful. Nice work.

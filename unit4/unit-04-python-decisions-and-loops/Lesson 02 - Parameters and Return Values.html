Lesson 2 - Parameters and Return Values

At the end of this lesson, you will be able to:

  • Define and call a function that accepts parameters.
  • Distinguish a parameter in a definition from an argument in a call.
  • Use return when a result should be stored or used in another expression.
  • Write a plain-language contract describing a function's expected inputs and promised result.

Make the useful parts changeable

Our scene-transition function always used the same location. We could create transition_to_library(), transition_to_moon(), and many more nearly identical functions. A better abstraction separates the stable pattern from the information that changes:

def scene_transition(place):
    print("[music rises]")
    print(f"NARRATOR: Meanwhile, at {place}...")
    print("[music fades]")

scene_transition("the library")
scene_transition("the bus stop")
scene_transition("a very small moon")

place is a parameter: a local name in the definition that stands for information a caller will provide. "the library" is an argument: the particular value supplied by one call. On that call, place temporarily refers to "the library". On the next call, it refers to "the bus stop".

More than one parameter

def announce_event(event_name, location, start_time):
    print(f"{event_name}")
    print(f"Location: {location}")
    print(f"Starts: {start_time}")

announce_event("Repair café", "Library room 2", "Saturday at 1 PM")

Arguments are matched to parameters by position: first to first, second to second, and so on. The call should provide the right number of values in the expected order. Descriptive parameter names reduce mix-ups.

A function can be called inside a loop:

for copy_number in range(1, 4):
    announce_event("Repair café", "Library room 2", f"Session {copy_number}")

Local names stay inside the function

Parameters and variables created in a function are normally local to that call:

def show_double(number):
    doubled = number * 2
    print(doubled)

show_double(6)
print(doubled)  # NameError: doubled is not defined here

This boundary is helpful. A function can do its work without accidentally replacing unrelated variables elsewhere in the program. Each call gets its own local values.

Printing a result is not returning it

A function that prints communicates with a person. A function that returns a value communicates with the rest of the program:

def calculate_tip(meal_cost, tip_rate):
    tip = meal_cost * tip_rate
    return tip

suggested_tip = calculate_tip(30.00, 0.18)
total = 30.00 + suggested_tip
print(f"Tip: ${suggested_tip:.2f}")
print(f"Total: ${total:.2f}")

When Python reaches return tip, the function call itself becomes that value. You can picture calculate_tip(30.00, 0.18) being replaced by 5.4. That is why its result can be stored or used in a calculation.

Compare:

def print_double(number):
    print(number * 2)

def calculate_double(number):
    return number * 2

print_double(5)                # displays 10
result = calculate_double(5)  # stores 10
print(result + 1)              # displays 11

The printing function is not “worse.” It performs a different job. Choose based on who needs the result next: a person looking at output, or code that will continue processing it.

A function contract

A contract is a short statement of what callers may supply and what the function promises to do or return. For example:

calculate_tip(meal_cost, tip_rate)

  • expects two numbers: a dollar amount and a rate written as a decimal,
  • returns the dollar amount of the tip,
  • does not print or ask the user for input.

The contract helps separate concerns. Input can happen once in the outer program; the calculation function can be tested with values chosen by the programmer:

print(calculate_tip(100, 0.20))  # expected: 20.0
print(calculate_tip(0, 0.20))    # expected: 0.0
print(calculate_tip(25, 0))      # expected: 0.0

These are informal tests. Because the function returns a result and does not pause for input, it is easy to call repeatedly with normal and boundary cases.

Parameters define permitted variation

Choosing parameters is a design decision. If a drawing function accepts color and size, callers may vary color and size. If a profile function requires only “first name” and “last name,” it assumes every name fits that structure. If a transit estimator accepts only driving speed, it treats other modes as outside the model.

A parameter list is therefore a small statement about which differences the program expects. Ask whether the fixed parts truly must be fixed, whether the caller has enough control, and whether a default quietly favors one kind of user.

Build and test a reusable function. Choose one:

  • a text function that prints a scene, label, stanza, or quiz question with changeable details;
  • a drawing function that changes a shape's size, turn angle, or narrated label; or
  • a calculation function that returns a converted measurement, price, or time.

Give it at least one parameter, call it with three different arguments, and write its contract. If it computes a value, return that value and use it after the call.

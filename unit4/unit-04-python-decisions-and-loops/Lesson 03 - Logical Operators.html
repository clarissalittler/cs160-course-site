One condition is often not enough. You might want to act only if it's raining and cold, or if someone is a student or a senior. Logical operators let you combine true/false values into bigger questions.

Logical Operators

Where this comes from: logic gates

This idea reaches all the way down to the hardware. Deep inside the CPU, tiny switches called logic gates combine electrical signals - "high" voltage stands for true, "low" for false. The three basic gates are AND, OR, and NOT, and they behave exactly like the everyday words. Play with each one below (flip the switches and watch the output bulb):

Logical operators in Python

Python gives you those same three operations as words you can put right into a condition: and, or, and not.

So our input-validation check from the last lesson, if grade < 0 or grade > 100:, reads exactly how it sounds: "if the grade is below 0 or above 100, it's invalid."

Bug Alert:

In the program below, x = 1, y = 4, and z = 3, and we want to check whether any one of them is equal to 2. None of them is, so we would predict the program would say "2 is not found." Run the program to see what actually happens.

Surprised? It prints "There is a 2!" even though none of our variables is 2. Remember - the operands on either side of a logical operator must each be true or false on their own. Here, Python reads x or y or z == 2 as x or y or (z == 2) - only the z == 2 part is an actual comparison. The x and y operands are just the bare integers 1 and 4! This causes unexpected results because in computer science, 0 is false and anything else is true - so x (which is 1) counts as true all by itself, which makes the whole or expression true.

def main():
    x = 1
    y = 4
    z = 3

    if x or y or z == 2:
        print("There is a 2!")
    else:
        print("2 is not found.")

main()

The fix is to write each comparison out in full, so every operand is its own true/false test: if x == 2 or y == 2 or z == 2:

Decisions inside decisions

Sometimes answering one question leads to another question. Figuring out how many days February has is a good example: first you ask whether it's a leap year, and the leap-year rule itself has a question inside it. When you put one if inside another, that's called nesting - and the inner decision is simply indented one more level:

def main():
    year = int(input("Enter a year: "))

    if year % 100 == 0:
        # century years are leap years only if divisible by 400
        if year % 400 == 0:
            print(f"In {year}, February has 29 days (leap year)")
        else:
            print(f"In {year}, February has 28 days")
    else:
        # most years: leap year if divisible by 4
        if year % 4 == 0:
            print(f"In {year}, February has 29 days (leap year)")
        else:
            print(f"In {year}, February has 28 days")

main()

Read the indentation carefully - the inner if/else only runs after the outer condition has already been decided. Nesting is how programs handle "it depends... and then it depends again."

Nesting vs. combining. Not every nested decision needs to be nested. Often you can flatten two conditions into one using the and/or operators you just learned. For example, instead of nesting an if inside an if to check that someone is both a student and over 18, you could write if is_student and age > 18:. Use nesting when the second question only makes sense after the first is answered; reach for and/or when you're really just checking several things at once.

Decisions with functions

Here's where the two halves of this course start clicking together. Back in Unit 3 you learned that a function can return a value. Well - a function can return a Boolean, and a Boolean is exactly what an if statement wants. So you can wrap a messy or repetitive condition inside a well-named function and then read your decisions like plain English.

Compare. Without a function, checking "is this number even?" means remembering the modulus trick every time. With a function, you write the trick once and give it a name that says what it means:

def is_even(n):
    return n % 2 == 0     # this comparison is already True or False

number = 7
if is_even(number):
    print(f"{number} is even")
else:
    print(f"{number} is odd")

Notice there's no == True needed - is_even(number) already is a Boolean, so it drops straight into the if. Step through it and watch the True/False answer travel back out of the function and into the decision:

This is a genuinely powerful habit: when a condition gets complicated (validating input, checking a password, deciding if a move is legal in a game), tuck it into a function with a clear name. Your if statements stay readable, and you can reuse the check anywhere.

Try it! Write a function is_passing(grade) that returns True when the grade is 70 or higher and False otherwise. Then use it in an if statement - if is_passing(score): - to print an encouraging message. (Notice how much friendlier that reads than if score >= 70:.)

How high is "high voltage"?

Show Solution

When transistors became common in computer circuitry, "high" voltage was about 5 volts - enough to make the transistors work, light a small LED, or (nowadays) power a USB flash drive. "Low" voltage has always been close to 0 volts. As circuits got smaller, manufacturers lowered the voltage to save power and heat; today's CPUs and RAM run at roughly 1.3 to 1.5 volts.

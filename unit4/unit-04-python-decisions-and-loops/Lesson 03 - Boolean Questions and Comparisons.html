Lesson 3 - Boolean Questions and Comparisons

This lesson is all about asking questions. When you're done, you'll be able to:

  • Write comparisons that produce True or False.
  • Distinguish assignment with = from equality comparison with ==.
  • Test comparisons at, below, and above a boundary.
  • Define a small Boolean function whose name asks a clear question.

Yes-or-no questions

A Boolean value is either True or False. Those are the only two possibilities! Booleans are named after George Boole, who in the 1800s worked out that you could do algebra with "true" and "false" the way you do algebra with numbers. We lightly used these last unit, but now we'll make them ourselves by comparing other values:

print(7 > 3)          # True
print(7 == 3)         # False
print("cat" == "cat") # True

A comparison is an expression like any other: it produces a value. That value can be printed, stored, returned from a function, or, starting next lesson, used to decide whether a block of code runs at all.

OperatorQuestionExample
==Are the values equal?answer == "yes"
!=Are the values different?status != "closed"
<Is the left value smaller?temperature < 32
<=Is the left value smaller or equal?age <= 12
>Is the left value larger?balance > 0
>=Is the left value larger or equal?score >= 70

= changes state; == asks a question.

score = 70        # assign the value 70
score == 70       # evaluate to True

Why two different symbols? Because a language needs both "make this so" and "is this so?", and since = was already taken for assignment back in the earliest languages, equality got the doubled version. Try reading = as "gets" or "becomes" and == as "is equal to": "score becomes 70" and "is score equal to 70?" are very different sentences.

Subtle distinctions

Suppose a reduced-price ticket applies to ages 12 and under:

age = 12
qualifies_for_child_price = age <= 12
print(qualifies_for_child_price)

Test just below the boundary (11), right on it (12), and just above it (13). And read the rule closely, because "under 12" and "12 and under" are different rules: the first wants <, the second wants <=. One character changes who qualifies.

This is obviously not an idle distinction and, indeed, is the kind of mistake that we accidentally make and find ourselves going mad to try and find.

Comparing text

reply = input("Continue? yes or no: ")
print(reply == "yes")

Type Yes, or YES, or yes with a stray space, and you get False. This isn't Python being nitpicky! Those really are different sequences of characters, and it has no way to know that you'd consider them the same. You don't want your programming language making fuzzy decisions for what is and isn't "the same thing". So before comparing a simple response, normalize it, that is to say put the variety of inputs into a standardized form:

reply = input("Continue? yes or no: ")
normalized_reply = reply.strip().lower()
print(normalized_reply == "yes")

.strip() shaves whitespace off the beginning and end; .lower() makes every letter lowercase. (Keep the original text around when capitalization matters. A person's chosen display name isn't ours to flatten.)

You can compare text with < or >, but the ordering goes by character codes rather than by anything a dictionary would recognize, so capital letters, punctuation, and accented characters all come out in surprising places. For now, equality is the text comparison that behaves the way you expect.

Boolean variables and functions

Storing a Boolean in a well-named variable makes a later decision read almost like English:

hour = 14
is_matinee = hour < 17
print(is_matinee)

If the same question keeps coming up in several places, turn it into a function:

def is_matinee(hour):
    return hour < 17

print(is_matinee(14))  # True
print(is_matinee(19))  # False

The function's name reads as a question, which is exactly what we want. And since the comparison already produces a Boolean, you can return it directly. This longer version works too, it just says the same thing twice:

def is_matinee(hour):
    result = hour < 17
    return result

Build a boundary table. For each expression, predict and then run three useful cases:

  • temperature <= 32
  • word_count >= 500
  • number % 2 == 0
  • reply.strip().lower() == "yes"

For one numeric rule, write a Boolean function with a question-style name and a one-sentence contract.

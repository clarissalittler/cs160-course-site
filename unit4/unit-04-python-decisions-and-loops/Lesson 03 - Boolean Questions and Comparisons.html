Lesson 3 - Boolean Questions and Comparisons

At the end of this lesson, you will be able to:

  • Write comparisons that produce True or False.
  • Distinguish assignment with = from equality comparison with ==.
  • Test comparisons at, below, and above a boundary.
  • Define a small Boolean function whose name asks a clear question.

Programs can ask yes-or-no questions

A Boolean value is either True or False. You saw these two values in Unit 3; now we will produce them by comparing other values:

print(7 > 3)          # True
print(7 == 3)         # False
print("cat" == "cat") # True

A comparison is an expression. It produces a value that can be printed, stored, returned, or—next lesson—used to decide whether a block of code runs.

OperatorQuestionExample
==Are the values equal?answer == "yes"
!=Are the values different?status != "closed"
<Is the left value smaller?temperature < 32
<=Is the left value smaller or equal?age <= 12
>Is the left value larger?balance > 0
>=Is the left value larger or equal?score >= 70

= changes state; == asks a question.

score = 70        # assign the value 70
score == 70       # evaluate to True

Read = as “gets” and == as “is equal to.”

Boundaries deserve three tests

Suppose a reduced-price ticket applies to ages 12 and under:

age = 12
qualifies_for_child_price = age <= 12
print(qualifies_for_child_price)

Test just below the boundary (11), exactly on it (12), and just above it (13). If the rule says “under 12” rather than “12 and under,” the operator should be <, not <=. One character changes who qualifies.

This is why boundary testing is both technical and social. Thresholds turn a continuous world into categories: eligible or not, passing or failing, flagged or unflagged. Code should match the stated rule, but we should also be willing to ask who chose the rule, what evidence supports it, and how borderline or unusual cases are handled.

Text comparisons are exact

reply = input("Continue? yes or no: ")
print(reply == "yes")

The result is False for Yes, YES, or yes . Python is not being stubborn; those are different sequences of characters. Normalize a simple response before comparing:

reply = input("Continue? yes or no: ")
normalized_reply = reply.strip().lower()
print(normalized_reply == "yes")

.strip() removes whitespace at the beginning and end. .lower() makes letters lowercase. Keep the original text when capitalization matters, such as a person's chosen display name.

Ordering text with < or > follows character order, not a full human-language dictionary. Capitalization, punctuation, and accented characters can produce surprises. Equality is usually the clearest comparison for beginner text programs.

Store a Boolean or name the question with a function

A Boolean variable can make a later decision read clearly:

hour = 14
is_matinee = hour < 17
print(is_matinee)

If the same question is useful in several places, define a Boolean function:

def is_matinee(hour):
    return hour < 17

print(is_matinee(14))  # True
print(is_matinee(19))  # False

The function's name forms a readable question. Because the comparison already produces a Boolean, return it directly. The longer version below works, but repeats the idea unnecessarily:

def is_matinee(hour):
    result = hour < 17
    return result

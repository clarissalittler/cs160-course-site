Lesson 3 - Boolean Questions and Comparisons

This lesson is all about asking questions. When you're done, you'll be able to:

  • Write comparisons that produce True or False.
  • Distinguish assignment with = from equality comparison with ==.
  • Test comparisons at, below, and above a boundary.
  • Define a small Boolean function whose name asks a clear question.

Programs can ask yes-or-no questions

A Boolean value is either True or False — that's it, that's the whole menu. You met these two values in Unit 3; now we'll manufacture them ourselves by comparing other values:

print(7 > 3)          # True
print(7 == 3)         # False
print("cat" == "cat") # True

A comparison is an expression like any other: it produces a value. That value can be printed, stored, returned from a function, or — next lesson — used to decide whether a block of code runs at all.

OperatorQuestionExample
==Are the values equal?answer == "yes"
!=Are the values different?status != "closed"
<Is the left value smaller?temperature < 32
<=Is the left value smaller or equal?age <= 12
>Is the left value larger?balance > 0
>=Is the left value larger or equal?score >= 70

= changes state; == asks a question.

score = 70        # assign the value 70
score == 70       # evaluate to True

Try reading = as “gets” and == as “is equal to” — “score gets 70” and “is score equal to 70?” are very different sentences.

Boundaries deserve three tests

Suppose a reduced-price ticket applies to ages 12 and under:

age = 12
qualifies_for_child_price = age <= 12
print(qualifies_for_child_price)

Test just below the boundary (11), exactly on it (12), and just above it (13). And read the rule closely: “under 12” and “12 and under” are different rules — the first wants <, the second <=. One character changes who qualifies.

Boundary testing, then, is both a technical habit and a social one. A threshold takes a smooth, continuous world and chops it into categories: eligible or not, passing or failing, flagged or unflagged. Our code should match the stated rule — and we should also be willing to ask who chose the rule, what evidence supports it, and what happens to the people who land right on the line or don't fit the categories at all.

Text comparisons are exact

reply = input("Continue? yes or no: ")
print(reply == "yes")

Type Yes, or YES, or yes with a stray space, and the result is False. Python isn't being stubborn — those really are different sequences of characters. So normalize a simple response before comparing:

reply = input("Continue? yes or no: ")
normalized_reply = reply.strip().lower()
print(normalized_reply == "yes")

.strip() shaves whitespace off the beginning and end; .lower() makes the letters lowercase. (Do keep the original text around when capitalization matters — a person's chosen display name isn't ours to flatten.)

You can order text with < or >, but the ordering follows character order, not a real human-language dictionary — capitalization, punctuation, and accented characters all produce surprises. For beginner text programs, equality is usually the comparison that behaves the way you expect.

Store a Boolean or name the question with a function

Storing a Boolean in a well-named variable makes a later decision read almost like English:

hour = 14
is_matinee = hour < 17
print(is_matinee)

If the same question keeps coming up in several places, promote it to a function:

def is_matinee(hour):
    return hour < 17

print(is_matinee(14))  # True
print(is_matinee(19))  # False

The function's name reads as a question, which is exactly what we want. Since the comparison already produces a Boolean, you can return it directly. The longer version below works — it just says the same thing twice:

def is_matinee(hour):
    result = hour < 17
    return result

Build a boundary table. For each expression, predict and then run three useful cases:

  • temperature <= 32
  • word_count >= 500
  • number % 2 == 0
  • reply.strip().lower() == "yes"

For one numeric rule, write a Boolean function with a question-style name and a one-sentence contract.

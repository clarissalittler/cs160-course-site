Lesson 5 - while Loops and Validation

Here's what this lesson will teach you to do:

  • Choose a for loop for counted repetition and a while loop for condition-controlled repetition.
  • Identify the initialization, condition, and update in a while loop.
  • Use a loop to re-prompt after an unacceptable response or stop at a sentinel.
  • Trace a loop and explain why it will eventually terminate.

Repeat while a question remains true

A for loop is the right choice when a sequence or a known count controls the work: repeat four sides, print five lines, visit each item. But sometimes nobody knows the count in advance — a program may need to keep going until the user gives an acceptable answer, reaches a goal, or decides to stop, and that could take one try or forty. A while loop handles this by checking a Boolean condition before each iteration:

count = 3

while count > 0:
    print(count)
    count = count - 1

print("Go!")

The loop has three essential parts:

  1. Initialization: count = 3 establishes the starting state.
  2. Condition: count > 0 asks whether another iteration should happen.
  3. Update: count = count - 1 changes the state so the condition will eventually become false.

A while loop is a pretest loop — it asks its question before doing anything. If the condition starts out false, the body runs zero times. Not once. Zero.

To convince yourself (or a skeptical classmate) that a loop terminates, point to what moves on every iteration and explain why it must eventually make the condition false. Here, count drops by 1 each time, so it has no choice but to reach 0.

An infinite loop has no reliable path to a false condition.

count = 3
while count > 0:
    print(count)
    # count never changes

This program prints 3 forever — or until you stop the environment yourself, whichever comes first. When a loop won't end, look at the variables in its condition and check that the body actually moves them in the right direction.

Validate a simple text response

Input validation is checking whether what the user typed fits what the program needs right now. Rather than silently treating every non-yes response as “no,” this loop explains what it will accept and asks again:

reply = input("Continue? yes or no: ").strip().lower()

while reply != "yes" and reply != "no":
    print("Please type yes or no.")
    reply = input("Continue? yes or no: ").strip().lower()

print(f"You chose {reply}.")

Look closely at that condition. An answer is unacceptable while it is not yes and not no. If we'd used or, the condition would always be true — even "yes" is not equal to "no" — and nobody would ever escape the loop.

This loop copes with capitalization and surrounding spaces, but it still won't recognize y, or sure, or a response in another language — all reasonable things for a person to type. It's worth pausing on that: validation is not the art of scolding users until they obey the machine. Good validation explains the constraint, preserves already-entered work when it can, and accepts the reasonable variations the program knows how to interpret.

Validate a numeric range

rating = int(input("Rate the activity from 1 to 5: "))

while rating < 1 or rating > 5:
    print("Please enter a whole number from 1 through 5.")
    rating = int(input("Rate the activity from 1 to 5: "))

print(f"Recorded rating: {rating}")

The loop handles whole numbers outside the allowed range. Type a word or decimal text, though, and the program still crashes with a ValueError — fixing that takes exception handling, which is beyond this lesson. And that's okay! Just be precise about what your program can and cannot handle yet, and don't claim input is fully validated when it isn't.

Use a sentinel when the user controls the length

A sentinel is a special value whose whole job is to mean “stop.” This program accepts any number of nonnegative donations and stops at a negative value:

total = 0.0
amount = float(input("Donation amount, or a negative number to finish: $"))

while amount >= 0:
    total += amount
    amount = float(input("Donation amount, or a negative number to finish: $"))

print(f"Total recorded: ${total:.2f}")

The first input, the one before the loop starts, is sometimes called a priming read — it gives the condition something to check on the first pass. The update at the bottom reads the next value. And the negative sentinel gets checked but never added to the total.

One requirement: a sentinel has to live outside the valid data. If negative temperatures were legitimate input, -1 would be a terrible stop signal. A text command such as done might be clearer, but mixing text and numeric conversion requires techniques we haven't covered yet.

Respectful control includes a way out

Interactive software shouldn't trap people in a process. A loop needs a visible exit; it should say what's about to happen; and it shouldn't erase everything someone already entered because of one mistake. Context matters enormously here — a challenge that repeats until you beat it can be fun in a game, while the same design in an application form becomes coercive or flat-out inaccessible. Termination, it turns out, is both a correctness property and a user-respect property.

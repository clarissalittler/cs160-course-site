Repeat while a question remains true

A for loop is a good choice when a sequence or known count controls the work: repeat four sides, print five lines, visit each item. Sometimes the number of repetitions is unknown. A program may need to continue until the user gives an acceptable answer, reaches a goal, or chooses to stop. A while loop checks a Boolean condition before each iteration:

count = 3

while count > 0:
    print(count)
    count = count - 1

print("Go!")

The loop has three essential parts:

  1. Initialization: count = 3 establishes the starting state.
  2. Condition: count > 0 asks whether another iteration should happen.
  3. Update: count = count - 1 changes the state so the condition will eventually become false.

A while loop is a pretest loop: if the condition begins false, the body runs zero times.

To argue that the loop terminates, identify what moves on every iteration and why it must eventually make the condition false. Here, count decreases by 1 and must reach 0.

An infinite loop has no reliable path to a false condition.

count = 3
while count > 0:
    print(count)
    # count never changes

This program prints 3 forever—or until the environment is stopped. If a loop will not end, inspect the variables in its condition and verify that the body updates them in the correct direction.

Validate a simple text response

Input validation checks whether input fits the program's current requirements. Instead of silently treating every non-yes response as “no,” this loop explains the accepted choices and asks again:

reply = input("Continue? yes or no: ").strip().lower()

while reply != "yes" and reply != "no":
    print("Please type yes or no.")
    reply = input("Continue? yes or no: ").strip().lower()

print(f"You chose {reply}.")

Notice the logic. The answer is unacceptable while it is not yes and not no. If we used or, the condition would always be true: even "yes" is not equal to "no".

This loop handles capitalization and surrounding spaces, but it does not recognize every reasonable expression such as y, sure, or a response in another language. Validation is not the same as blaming users until they obey the machine. Good validation explains the constraint, preserves already-entered work when possible, and accepts reasonable variations the program can interpret.

Validate a numeric range

rating = int(input("Rate the activity from 1 to 5: "))

while rating < 1 or rating > 5:
    print("Please enter a whole number from 1 through 5.")
    rating = int(input("Rate the activity from 1 to 5: "))

print(f"Recorded rating: {rating}")

The loop handles whole numbers outside the allowed range. It will still raise a ValueError for words or decimal text because exception handling is beyond this lesson. Be precise about what your program can and cannot yet handle; do not claim input is fully validated when it is not.

Use a sentinel when the user controls the length

A sentinel is a special value that means “stop.” This program accepts any number of nonnegative donations and stops at a negative value:

total = 0.0
amount = float(input("Donation amount, or a negative number to finish: $"))

while amount >= 0:
    total += amount
    amount = float(input("Donation amount, or a negative number to finish: $"))

print(f"Total recorded: ${total:.2f}")

The first input before the loop is sometimes called a priming read. The update at the bottom reads the next value. The negative sentinel is checked but never added.

A sentinel must be outside the valid data. If negative temperatures are legitimate, -1 would be a poor stop signal. A text command such as done may be clearer, but mixing text and numeric conversion then requires techniques we have not yet covered.

Respectful control includes a way out

Interactive software should not trap people in a process. A loop should have a visible exit, explain what will happen, and avoid erasing earlier input after one mistake. In a game, a repeating challenge may be fun. In an application form, the same design can become coercive or inaccessible. Termination is therefore both a correctness property and a user-respect property.

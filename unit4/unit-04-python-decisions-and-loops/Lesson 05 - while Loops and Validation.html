Lesson 5 - while Loops and Validation

Here's what this lesson will teach you to do:

  • Choose a for loop for counted repetition and a while loop for condition-controlled repetition.
  • Identify the initialization, condition, and update in a while loop.
  • Use a loop to re-prompt after an unacceptable response or stop at a sentinel.
  • Trace a loop and explain why it will eventually terminate.

Repeat while a question stays true

A for loop is the right tool when you know how many times to repeat: four sides, five lines, one for each item. But often nobody knows the count in advance. A program might need to keep asking until the user gives an acceptable answer, or keep collecting entries until they say they're done, and that could take one try or forty. If for means "do this N times," then while means "keep going as long as this is true":

count = 3

while count > 0:
    print(count)
    count = count - 1

print("Go!")

Every while loop has three parts, and when a loop misbehaves it's almost always because one of them is missing or wrong:

  1. Initialization: count = 3 sets up the starting state.
  2. Condition: count > 0 asks whether another iteration should happen.
  3. Update: count = count - 1 changes the state so that the condition will eventually become false.

Notice that the question gets asked before each pass, including the first one. If the condition is false from the start, the body runs zero times. Not once. Zero.

How do you convince yourself (or a skeptical classmate) that a loop will actually stop? Point to the thing that changes on every pass and explain why it has to eventually make the condition false. Here, count drops by 1 each time, so it has no choice but to hit 0.

An infinite loop is one with no way to reach a false condition.

count = 3
while count > 0:
    print(count)
    # count never changes

This prints 3 forever, or until you stop the program yourself, whichever comes first. They're a very common mistake. When it happens, look at the variables in the condition and check whether the body actually moves them in the right direction.

Validate a simple text response

Input validation means checking whether what the user typed is something the program can work with. The lazy approach is to treat anything that isn't "yes" as "no" and move on. A better approach says what it will accept and asks again:

reply = input("Continue? yes or no: ").strip().lower()

while reply != "yes" and reply != "no":
    print("Please type yes or no.")
    reply = input("Continue? yes or no: ").strip().lower()

print(f"You chose {reply}.")

Look closely at that condition!. We keep looping while the answer is not yes and not no. It's tempting to write or there instead, since "not yes or no" sounds right in English, but our informal language betrays us: even "yes" is not equal to "no", so the condition would be true for every possible input and nobody would ever get out.

This loop handles capitalization and stray spaces, but it still rejects y, and sure, and any answer in another language, all of which are perfectly reasonable things for a person to type. That's a limitation of our program! Good validation isn't about scolding people until they obey the machine. Instead, it explains what's needed, keeps the work someone has already entered, and accepts reasonable variations where possible.

Validate a numeric range

rating = int(input("Rate the activity from 1 to 5: "))

while rating < 1 or rating > 5:
    print("Please enter a whole number from 1 through 5.")
    rating = int(input("Rate the activity from 1 to 5: "))

print(f"Recorded rating: {rating}")

This catches whole numbers outside the range. Type a word or 3.5, though, and the program still crashes with a ValueError, because int() fails before the loop ever gets to look. Fixing that takes a tool called exception handling that we haven't covered. And that's fine! Just be honest with yourself about what the program does and doesn't handle yet, and don't call input "validated" when it's only half validated.

Use a special value when the user controls the length

A sentinel is a special value whose whole job is to mean "stop." This program accepts any number of donations and stops when it sees a negative one:

total = 0.0
amount = float(input("Donation amount, or a negative number to finish: $"))

while amount >= 0:
    total += amount
    amount = float(input("Donation amount, or a negative number to finish: $"))

print(f"Total recorded: ${total:.2f}")

Why is there an input() both before the loop and at the bottom of it? The first one is sometimes called a priming read. The condition needs a value to check before the first pass, so we have to read one in ahead of time. The one at the bottom is the update: it reads the next value so that the condition has something new to look at. And notice that the negative sentinel gets checked but never added to the total, since the loop exits before total += amount can run.

One requirement for a sentinel: it has to be a value that could never be real data. If negative temperatures were legitimate input, -1 would be a terrible stop signal! A word like done would be clearer, but mixing text and numeric conversion takes techniques we'll get to later.

You can usually force one kind of loop to imitate the other, and I don't recommend it. Pick the one that makes the stopping rule obvious to the next person who reads the program.

A loop needs a way out

Interactive software shouldn't trap people. A loop needs a visible exit, it should say what's about to happen, and it shouldn't throw away everything someone already entered because of one typo. Context changes a lot here: a challenge that repeats until you beat it is fun in a game, and the exact same design in a benefits application is somewhere between hostile and unusable. So "how does this loop terminate?" is actually two distinct questions, one about correctness and one about how the program treats the user.

Unit 4 Overview - Functions, Decisions, and Repetition

In Unit 3 we got from an idea to a small running program. Those programs all had one thing in common: they ran straight through from top to bottom, and the only way to get different behavior was to give different input. This unit is where programs start to have some structure of their own. We'll give a group of steps a name (a function), let each use of it bring its own details (parameters), get results back out (return), ask yes-or-no questions, choose between paths, and repeat something for as long as a condition holds.

We start running into our first taste of real design decisions. A function's name can make clear what it does or hide it. A parameter list decides which variations a tool will even allow. Comparisons draw lines; if statements turn human rules into automatic outcomes; validation can help people or trap them. So we'll test whether our programs follow their rules, and we'll keep asking what those rules mean for the person on the other end.

Learning objectives

By the end of the unit, you'll be able to:

  1. Define and call functions, including functions with parameters and return values.
  2. Write and test Boolean expressions using comparisons and logical operators.
  3. Use if, elif, and else to create reachable, understandable branches.
  4. Use while for input validation or condition-controlled repetition and explain termination.
  5. Choose between for and while based on the reason repetition stops.
  6. Test functions, boundaries, branches, and loops with normal, boundary, and invalid cases.

Lesson map

The five lessons in Unit 4
LessonCentral ideaQuestions to carry forward
1. Functions as Named ActionsA function puts a group of steps under one name. Once it's defined, we can call it wherever that job needs doing.Has the function merely been defined, or has it been called? What job would a good name describe?
2. Parameters and Return ValuesParameters let us give a function information to work with; a return value lets it hand an answer back.Which details might change from one call to the next? What can the rest of the program do with the returned result?
3. Boolean Questions and ComparisonsA comparison asks a yes-or-no question about values. The answer is a Boolean: True or False.What exactly is being compared? What happens at the boundary?
4. Decisions and Logical OperatorsAn if statement lets a program choose what to do, and logical operators let us put questions together into more complicated rules.Which path will this input take? Who chose the rule, and whom might it affect?
5. while Loops and ValidationA while loop keeps going as long as a condition is true. It can give someone another chance to enter a response the program understands.What makes the condition change? What happens if the user never enters an accepted response?

Learning activities and assessment

  1. Complete Lessons 1–5 and the Python Practice Problems.
  2. Complete Unit 4 Quiz.
  3. Complete one Week 4 creative-programming route: the ColabTurtle project or a text-first quiz/oracle or branching-radio-play notebook.
  4. Complete and share the Week 4 Activity Discussion: Throw Something (a tiny physics simulator).

Whichever Week 4 route you pick, you'll define a function of your own, call it more than once, and make at least one real decision with an if. Parameters and loops are there to make your creation richer. Whether it's a drawing or a text-based interaction is entirely up to you.

Unit 4 Summary

Your programs came into this unit as straight lines and are leaving with a vocabulary and the ability to make choices. A function puts a whole process under one name. Parameters let each call bring its own input, and return sends the result back out to the program. Boolean expressions answer yes-or-no questions, if statements act on the answers, and while loops keep acting until an answer changes.

What to carry forward

  • def name(): defines a function and name() calls it. Defining a function only teaches Python a new word, and nothing in its body runs until you call it, which is why a file full of definitions and no calls doesn't print anything.
  • A parameter is the name in the definition, and an argument is the value a particular call supplies for it. That's how one function can work on one input this time and a different one the next.
  • print shows something to a person, while return hands a value back to the program so it can be stored or used in another calculation. If you print when you meant to return, the answer shows up on screen and the rest of your program has nothing to work with.
  • Before you write a function, it helps to write down its contract: what it expects, what it gives back or does, and what it doesn't handle. Then anyone who calls it, including you a week later, knows what they can count on.
  • Comparisons such as ==, !=, <, <=, >, and >= ask yes-or-no questions and give back a Boolean, True or False. Keep = and == straight: one equals sign stores a value, and two ask whether two values are the same.
  • An if/elif/else chain checks its conditions from top to bottom and runs only the first branch whose condition is true, so the order you put them in matters. You can build bigger questions with and (both sides true), or (at least one, and both is fine), and not (which flips a Boolean).
  • When you test a decision, try values just below, at, and just above every boundary, and make sure at least one test reaches every branch. Boundaries are where mistakes like < instead of <= hide, and a branch no test reaches is a branch you've never seen run.
  • A while loop needs three things: an initialization before the loop, a condition, and an update inside the body that eventually makes the condition false. Leave out the update and the loop never stops.
  • So when should you use which loop? Use for when a count or a sequence tells you how many times to repeat, and while when you're waiting for something to change, like a person finally typing an answer the program can use.
  • Categories, thresholds, validation rules, and exits are design decisions that land on real people. A < where you meant <= changes who gets the cheaper ticket, and a validation loop with no way out can leave someone stuck with no way to move on.

Synthesis check

def describe_number(number):
    if number % 2 == 0:
        return "even"
    else:
        return "odd"

reply = ""
while reply != "quit":
    number = int(input("Enter a whole number: "))
    print(f"That number is {describe_number(number)}.")
    reply = input("Press Enter to continue or type quit: ").strip().lower()

See if you can point to everything at once: the function definition, the parameter, the argument, the return values, the comparison, the branches, and the loop's initialization, condition, and update. Then name one input this program handles and one entirely reasonable input it can't handle yet.

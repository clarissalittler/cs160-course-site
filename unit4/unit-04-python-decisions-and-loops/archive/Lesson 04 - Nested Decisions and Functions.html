Lesson 4 - Nested Decisions and Functions

At the end of this lesson, you will be able to:

  • Write nested decisions - a decision inside another decision.
  • Use a function that returns True or False to make your conditions clearer.

Decisions inside decisions

Sometimes answering one question leads to another question. Figuring out how many days February has is a good example: first you ask whether it's a leap year, and the leap-year rule itself has a question inside it. When you put one if inside another, that's called nesting - and the inner decision is simply indented one more level:

def main():
    year = int(input("Enter a year: "))

    if year % 100 == 0:
        # century years are leap years only if divisible by 400
        if year % 400 == 0:
            print(f"In {year}, February has 29 days (leap year)")
        else:
            print(f"In {year}, February has 28 days")
    else:
        # most years: leap year if divisible by 4
        if year % 4 == 0:
            print(f"In {year}, February has 29 days (leap year)")
        else:
            print(f"In {year}, February has 28 days")

main()

Read the indentation carefully - the inner if/else only runs after the outer condition has already been decided. Nesting is how programs handle "it depends... and then it depends again."

Nesting vs. combining. Not every nested decision needs to be nested. Often you can flatten two conditions into one using the and/or operators from the last lesson. For example, instead of nesting an if inside an if to check that someone is both a student and over 18, you could write if is_student and age > 18:. Use nesting when the second question only makes sense after the first is answered; reach for and/or when you're really just checking several things at once.

Decisions with functions

Here's where the two halves of this course start clicking together. Back in Unit 3 you learned that a function can return a value. Well - a function can return a Boolean, and a Boolean is exactly what an if statement wants. So you can wrap a messy or repetitive condition inside a well-named function and then read your decisions like plain English.

Compare. Without a function, checking "is this number even?" means remembering the modulus trick every time. With a function, you write the trick once and give it a name that says what it means:

def is_even(n):
    return n % 2 == 0     # this comparison is already True or False

number = 7
if is_even(number):
    print(f"{number} is even")
else:
    print(f"{number} is odd")

Notice there's no == True needed - is_even(number) already is a Boolean, so it drops straight into the if. Step through it and watch the True/False answer travel back out of the function and into the decision:

This is a genuinely powerful habit: when a condition gets complicated (validating input, checking a password, deciding if a move is legal in a game), tuck it into a function with a clear name. Your if statements stay readable, and you can reuse the check anywhere.

Try it! Write a function is_passing(grade) that returns True when the grade is 70 or higher and False otherwise. Then use it in an if statement - if is_passing(score): - to print an encouraging message. (Notice how much friendlier that reads than if score >= 70:.)

That's the end of Unit 4! Your programs can now make decisions, simple and complex. In the next unit we add the other great superpower: repetition - getting the computer to do something over and over with loops.

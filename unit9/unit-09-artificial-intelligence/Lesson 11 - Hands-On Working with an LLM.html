Time to Get Your Hands Dirty

We've spent several lessons talking about AI—how LLMs work, what generative AI can do, where bias creeps in. That's all important. But at some point, you have to stop reading about swimming and actually get in the pool.

This is that lesson.

Remember back in Lesson 6, we talked about how LLMs are essentially very sophisticated autocomplete—prediction machines that generate text one token at a time based on patterns learned from training data? Today you're going to see that process in action. You'll type things in, get responses back, and start developing an intuition for what these tools are good at, where they stumble, and how the way you ask a question changes the answer you get.

That last part—the way you ask—turns out to matter a lot.

Getting Started: Pick Your Tool

You'll need access to an LLM for this lesson. The good news: there are several solid options, and they're all free to use at a basic level. Pick whichever one you like—or try more than one:

  • ChatGPT (by OpenAI) — Create a free account and start chatting. Probably the most well-known option.
  • Claude (by Anthropic) — Also free to sign up. Good at longer, more nuanced responses.
  • Google Gemini — Free with a Google account, which you probably already have.
  • Microsoft Copilot — Free, runs in your browser, no account required to get started.

Any of these will work for everything we're doing today. They each have slightly different personalities and strengths, but the core mechanics are the same: you type a prompt, the model generates a response, token by token, using the process we discussed in Lesson 6.

Go ahead and open one up. We'll wait.

Prompt Engineering Basics

Here's something that might surprise you: getting a good answer from an LLM is a skill. The same model that gives you a vague, unhelpful response to one prompt can give you something genuinely useful if you ask differently. The art of crafting good prompts even has a name—prompt engineering—and while that sounds fancy, the core ideas are pretty straightforward.

Here are four tips that will immediately make you better at this:

1. Be Specific

Vague prompts get vague answers. Compare these two:

  • Vague: "Write a poem."
  • Specific: "Write a four-line poem about rain in Portland, in the style of a haiku, with a slightly melancholy tone."

The first prompt gives the model almost nothing to work with—it could write about literally anything, in any style, at any length. The second tells the model exactly what you want: a specific topic, a specific form, a specific mood. More detail in your prompt means less guessing from the model, and less guessing means a better result.

2. Give Context

LLMs respond differently depending on the framing you provide. Telling the model who it's talking to or what role it should play can dramatically change the output. For example:

  • "Explain how a CPU works." — You'll get a general explanation, probably pitched at a random level.
  • "You are a helpful tutor for a community college intro CS class. Explain how a CPU works to a student who has never taken a computer science course before. Use simple analogies." — Now you'll get something much more appropriate for your actual situation.

Context steers the prediction. The model generates different "next tokens" when it thinks it's writing for a beginner than when it thinks it's writing for an expert.

3. Ask for a Format

If you want a specific kind of output, say so. LLMs are surprisingly good at following formatting instructions:

  • "Give me a bulleted list of five uses for AI in healthcare."
  • "Explain the difference between supervised and unsupervised learning in exactly two sentences."
  • "Create a table comparing three LLMs, with columns for name, company, and one strength."

Without format instructions, the model will pick whatever structure it thinks fits—which might not be what you actually wanted.

4. Iterate

This is maybe the most important tip of all: the first response is rarely the best one. Think of your first prompt as a rough draft. Read the response, figure out what's missing or off, and refine your prompt. Ask the model to try again with different constraints. Tell it what you liked and what you didn't.

This back-and-forth isn't a sign that the tool is broken—it's how the tool is meant to be used. Professional prompt engineers iterate constantly. You should too.

Try it: Prompt Comparison

Pick a question—anything you're curious about. Now try asking that same question in two different LLMs (say, ChatGPT and Claude, or Gemini and Copilot). How do the responses differ? Is one more detailed? More conversational? Does one give you caveats while the other sounds more confident? What does this tell you about the idea that LLMs are generating responses rather than looking up a single correct answer?

Structured Activities

Alright—time to actually do things. Work through these three activities at your own pace. These connect directly to what you'll be doing in Lab 05, so think of this as a warm-up.

Activity 1: Generate Some Code

Ask the LLM to write a short Python program that does something fun. Be creative with your prompt! Some ideas to get you started:

  • "Write a Python program that generates a random compliment."
  • "Write a Python program that converts a temperature from Fahrenheit to Celsius and tells me whether I need a jacket."
  • "Write a Python program that plays a simple number-guessing game."

Once you get the code, try running it. (You can use Replit if you don't have Python installed—it's free and runs right in your browser.) Does the program actually work? If not, try pasting the error message back into the LLM and asking it to fix the problem. How does it do?

Pay attention to this: the model generated that code token by token, just like it generates English text. It wasn't copying from a database of programs. It predicted what a reasonable Python program should look like based on your description. Sometimes that prediction is spot-on. Sometimes it's close but has a bug. Sometimes it's completely off. That's the nature of generation vs. retrieval—exactly what we talked about in Lesson 7.

Activity 2: Get an Explanation

Ask the LLM to explain a concept from this course—maybe something from an earlier unit that you found tricky. Some possibilities:

  • "Explain the difference between machine learning and deep learning."
  • "What is binary, and why do computers use it?"
  • "What's the difference between an algorithm and a program?"

Now here's the important part: evaluate the explanation. Is it accurate? Is it clear? Does it match what you learned in this course, or does it say something different? If something seems off, check it against your course materials. Remember, the model isn't recalling facts from a textbook—it's generating text that sounds like a good explanation. Usually it is one. But not always.

Activity 3: Fact-Check the Model

This is where it gets interesting. Ask the LLM about something very specific—ideally something you can verify independently. Try something like:

  • "When was Portland Community College founded, and how many campuses does it have?"
  • "Who won the 2023 FIFA Women's World Cup, and what was the final score?"
  • "Name three restaurants on Alberta Street in Portland."

Now fact-check the response. Look things up. Are the claims accurate? Did it get the details right, or did it confidently state something that turns out to be wrong? If it got something wrong, that's hallucination in action—exactly what we talked about in Lesson 6. The model generated plausible-sounding text that happens to not be true. It's not lying. It's predicting, and sometimes the prediction lands on something false.

Remember: LLMs are prediction machines, not truth machines. They generate whatever text sounds most plausible based on patterns in their training data. That means they can be confidently, fluently, convincingly wrong. Always verify claims that matter—especially facts, statistics, dates, and citations.

Lesson 2 - Learning from Examples

At the end of this lesson, you will be able to:

  • Explain how AI, machine learning, neural networks, and deep learning fit inside one another.
  • Explain how machine learning flips programming around, from writing rules to learning them from examples.
  • Describe training data and test data, and why doing well on new examples is what counts.
  • Explain, in everyday terms, what "learning" means inside a machine: adjusting numbers to make fewer mistakes.

Boxes inside boxes

Last lesson we saw that "AI" covers plenty of ground. Most of what people mean by AI today lives in a few nested boxes, and it helps to get them straight before we go any further:

  • Artificial intelligence is the biggest box: any technique for getting computers to do things that seem intelligent. That includes search, hand-written rules, and everything below.
    • Machine learning is one part of AI: techniques where the computer learns how to do a task from examples, instead of being told every rule.
      • Neural networks are one family of machine-learning models, loosely inspired by neurons in the brain.
        • Deep learning means neural networks with many layers. Chatbots, image generators, and modern speech recognition are all deep learning.

So every neural network is machine learning, and all machine learning is AI, but not the other way around. Deep Blue was AI without any machine learning at all. And the text classifier in this week's activity is machine learning, but it isn't a neural network. (It learns a weight for each word, which, as you'll see in Lesson 4, makes it a close cousin of a single neuron!)

The big flip

In the Python units, we wrote programs by spelling out the rules. If the balance is below zero, print a warning. If the score reaches the threshold, flag the message. The programmer decides every step, and the computer follows them.

That works great for some things. Tax rules are fussy, but they're written down, and you can turn them into code. Now try a task that sounds easier: write rules that tell a cat photo from a dog photo.

"Dogs have floppy ears"? Lots of dogs don't. "Cats are small"? Not compared to a chihuahua. Fur color, whiskers, tail shape, the angle of the photo, the lighting... every rule you write has piles of exceptions. You can tell a cat from a dog in a fraction of a second, and you'd still have a really hard time writing down how you do it.

So machine learning flips the whole thing around. Instead of writing the rule, you give the computer lots of photos labeled "cat" and lots labeled "dog," and you have it find a rule that sorts them. Those labeled photos are the training data. The programmer still makes plenty of choices: which data to use, what kind of model, what counts as a mistake. But nobody writes the cat-detecting rule by hand.

You've already done a tiny version of this! In Unit 5, Lesson 6, you tried several thresholds for the scam filter, counted the mistakes for each, and kept the best one. That was you, adjusting one number by hand to make fewer mistakes on labeled examples. Machine learning is that same idea, done automatically, with way more numbers.

Three flavors of learning

Machine-learning methods differ in what kind of feedback the computer gets:

  • Supervised learning comes with an answer key. Every example has a label ("cat," "spam," "fraud"), and the model learns to predict the label. Most of this unit is about supervised learning.
  • Unsupervised learning has no answer key. The model looks for structure on its own, like grouping customers with similar shopping habits without being told what the groups should be.
  • Reinforcement learning learns from rewards. The system tries actions, sees what happens, and adjusts to get more reward next time. This is how game-playing systems got so good, and it comes back when we talk about chatbots and agents.

Does it work on new examples?

So if a model gets all its training examples right, does that mean it's good? Not necessarily! A model can do great on its training examples and still be terrible on new ones. Imagine all your cat photos were taken indoors and all your dog photos were taken in a park. A model might "learn" that green grass means dog! It would ace the training data and then call every cat in a backyard a dog. Fitting the training data so closely that you learn the wrong lesson is called overfitting.

So before training, we set some examples aside as a test set, and we never let the model train on them. Afterward, we check how it does on those. Doing well on examples you've never seen is called generalization, and it's the whole goal.

Even a good test score only tells you about examples like the ones in the test set, though. If every test photo is a crisp, well-lit pet portrait, the score tells you very little about blurry photos taken at night. (This is the Unit 8 sampling question again: who and what is in your data?)

What does "learning" actually mean in there?

"The computer finds the pattern" can sound mysterious, so let's make it concrete. A machine-learning model contains a bunch of adjustable numbers, called parameters. I like to picture them as knobs. The knob settings determine what the model predicts.

Training means turning those knobs, over and over, so that the model's predictions match the examples better. That's it! For a big chatbot, there are billions of knobs and the process is enormous and expensive. But underneath, the basic operation is "measure how wrong you are, and adjust the numbers to be a little less wrong."

In the next lesson we'll watch this happen with a model that has only one knob, which is small enough to follow every single step.

Try it: Think of something you can do easily but couldn't write step-by-step rules for, like recognizing a friend's voice on the phone. What examples would a learning system need to learn it? And what might go wrong if all of those examples came from one place, like phone calls in a quiet room?

Lesson 7 - Generative AI: Making New Things

At the end of this lesson, you will be able to:

  • Explain what "generative" means in the context of AI.
  • Distinguish between generative AI and search or retrieval.
  • Give examples of generative AI for text, images, code, and music.

What Does "Generate" Mean?

When you Google something, the search engine finds web pages that already exist. It's a librarian, not an author—it points you to a shelf, but it doesn't write the book.

Generative AI is fundamentally different. When you ask an LLM to write a poem about a cat who's terrible at skateboarding, it doesn't go looking for a page that contains that poem. That page doesn't exist. Instead, it creates something new—word by word, token by token—that didn't exist before you asked.

That's what "generative" means: these systems generate new content—text, images, music, code—that is, in some meaningful sense, original. Now, "original" is a complicated word here, and we'll get into why. But the key idea is that generative AI usually does not retrieve a whole stored answer the way a search engine does. It produces new output based on patterns it learned from existing material. That distinction matters for understanding how these tools work, for thinking about copyright, and for knowing when to trust the output.

Text Generation (LLMs)

We covered this in Lesson 6, but it's worth a quick recap. An LLM generates text by predicting the next token, over and over. You give it a prompt—"Write a haiku about Portland rain"—and it produces tokens one at a time: "Gray," "skies," "weep," "softly"... Each token is chosen based on everything that came before it, using patterns the model learned during training.

The result is generated on the spot rather than fetched like a stored document. In most cases it isn't simply copied from a database or stitched together from saved fragments. That said, models can sometimes reproduce memorized snippets from training data, so "generated" does not mean "guaranteed never seen before." That's what powers ChatGPT, Claude, Gemini, &c.—each response is produced in the moment.

Image Generation

Text generation is impressive, but image generation is where a lot of people had their "wait, what?" moment.

The most common approach is called diffusion, and here's the intuition: imagine starting with a screen full of pure static—random colored noise, like an old TV that's lost its signal. Now imagine slowly removing the noise, guided by a text description like "a golden retriever wearing sunglasses at the beach." Step by step, shapes form, colors coalesce, and eventually you've got an image of a very cool dog at the beach.

It's like sculpting. You start with a block of marble (the noise) and chip away (removing noise, guided by the text prompt) until something recognizable emerges. The model learned this process by studying millions of real images during training.

The major image generation tools include DALL-E (made by OpenAI), Midjourney, and Stable Diffusion. They each work a little differently under the hood, but they all share this idea of turning noise into images guided by text.

Here's a fun way to see why this is genuinely generative: think about the prompt "draw a cat riding a bicycle on Mars." No photograph of that exists. No artist has painted it (probably). Yet these tools produce a coherent picture of it—because they've learned what cats look like, what bicycles look like, and what Mars looks like, and they can combine those concepts into a single scene. That's generation, not retrieval.

Code Generation

The internet contains a lot of code, so when you train a large language model on all that data, it picks up programming languages right alongside English. This led to tools like GitHub Copilot, &c., which can look at the code you're writing and suggest what comes next—or even generate entire functions from a plain-English description. Type a comment like "sort this list from highest to lowest" and the tool writes the Python for you.

Professional developers use these tools daily. You'll get hands-on experience with code generation in Lesson 11—but it's a great example of how the same underlying technology (predict the next token) produces very different output depending on what the model was trained on.

Music and Audio

If you can generate text, images, and code, why not sound? AI models can now generate music, speech, and sound effects. Tools like Google's MusicLM or Meta's MusicGen take a text description—"upbeat jazz with a walking bass line"—and produce a listenable audio clip.

Other tools focus on voice: given a short sample of someone speaking, they can generate new speech in that person's voice saying things they never said. (If that sentence made the hairs on the back of your neck stand up—good. We'll talk about the implications in the ethics lessons later in this unit.)

Audio generation is newer and rougher around the edges than text or image generation, but it's advancing fast. The same principle applies: learn patterns from training data, then generate new content that follows those patterns.

The "Generate vs. Search" Distinction

This is important enough to state head-on:

A common misconception: Many people assume generative AI is searching a database and pasting together existing pieces—remixing sentences from different sources, or combining chunks of images like a collage. That's not usually how it works. Generative AI predicts new output from statistical patterns learned during training rather than doing a normal web search or copying a whole stored answer. Models can sometimes reproduce memorized training examples, though, so "generated" does not mean "copied from nowhere" in an absolute sense.

Why does this distinction matter?

  • Copyright: If the AI were copying existing work, infringement would be straightforward. But since it's generating new content from learned patterns, the legal picture is murkier—and courts are actively wrestling with this right now.
  • Hallucination: A search engine either finds a correct answer or finds nothing. A generative model can produce confident-sounding text that's completely wrong—because it just generated whatever sounded right, with no source to copy from.
  • Output quality: Generated output will usually be plausible, because the model learned from real examples. But "plausible" isn't "correct." A generated image might show a person with six fingers. A generated paragraph might include a made-up statistic. These aren't search failures—they're generation artifacts.

So when someone says "the AI just Googled the answer," they're wrong—in a way that matters.
